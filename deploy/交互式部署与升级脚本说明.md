# Consumer 与 Modeling 交互式部署、升级说明

本文说明以下两个交互式脚本的使用方法，非交互式入口见第 6 节：

```text
install-consumer-modeling-interactive.sh
upgrade-consumer-modeling-legacy-interactive.sh
```

两个脚本用途不同：

| 脚本 | 用途 |
| --- | --- |
| `install-consumer-modeling-interactive.sh` | 新架构分离部署的首次安装，以及已有分离部署的升级 |
| `upgrade-consumer-modeling-legacy-interactive.sh` | 旧架构 Consumer、Modeling 合并部署迁移到新架构分离部署 |

## 1. 现场依赖

现场主机需要：

```text
Linux
Bash 3.2 及以上
Docker Engine 20.10 及以上
curl
tar
gzip
sha256sum
flock
awk
sed
mktemp
```

Docker daemon 必须处于运行状态。发布包路径应使用绝对路径，或者使用当前目录下的相对路径。

Consumer 发布包应包含：

```text
onto-agent/
onto-agent/deploy/install.sh
onto-agent/deploy/opsctl
onto-agent/deploy/manifest.json
onto-agent/backend/.env.example
```

Modeling 发布包应包含：

```text
modeling/
modeling/deploy/install.sh
modeling/.env.example
```

Onto Modeling 发布包应包含：

```text
onto-modeling/
onto-modeling/deploy.sh
onto-modeling/docker-compose.release.yml
onto-modeling/.env.example
onto-modeling/images/
```

知识包 Hub 发布包（`bash knowledge-hub/build.sh <version> [amd|arm]` 生成）应包含：

```text
knowledge-hub/
knowledge-hub/deploy.sh
knowledge-hub/docker-compose.knowledge-hub.yml
knowledge-hub/images.env
knowledge-hub/images/
```

独立评测服务发布包由 `bash eval-service/build.sh <version> [amd|arm]` 生成，位于
`eval-service/dist/evaluation-<version>-linux-<arch>.tar.gz`，顶层目录为 `eval-service/`，与其他组件
发布包一样支持通配符；也可使用完整发布包解压后的 `eval-service/` 子目录。发布包或目录中必须包含：

```text
deploy/deploy.sh
deploy/docker-compose.eval-service.yml
evaluation-image.tar
IMAGE
```

## 2. 新架构首次分离部署

执行：

```bash
bash install-consumer-modeling-interactive.sh
```

交互流程：

```text
1. 选择“首次部署”
2. 选择默认安装目录 /opt/onto-agent-stack 或自定义目录
3. 选择默认端口或自定义端口
4. 输入 Consumer 发布包路径
5. 输入 Modeling 发布包路径
6. 输入 Onto Modeling 发布包路径（留空跳过）
7. 输入知识包 Hub 发布包路径（留空跳过）
8. 输入独立评测服务发布包路径（留空跳过）
```

Onto Modeling、知识包 Hub 或评测服务发布包留空时跳过对应组件。选择 Onto Modeling 时，必须提供配套 Hub 发布包，
或已有 Hub 容器通过健康检查；否则预检在变更服务前停止，明确提示知识包发布不可用。
安装及升级后还会从建模容器检查 Hub 网络与服务凭据；不能把建模进程启动当作知识包发布就绪。
评测服务需要 Hub 的评测凭据：提供 Hub 发布包，或使用已经部署且配置完整的 Hub。
评测部署除进程活性外还检查 `/evaluation/api/ready`，依赖缺失时停止，不报告部署完成。
安装入口须与发布包版本一致，补部署时使用本版本脚本的 `--knowledge-hub-package`、`--evaluation-package` 参数。

首次安装默认端口如下：

| 服务 | 默认宿主端口 | 容器端口 |
| --- | ---: | ---: |
| Consumer Backend | 5055 | 5055 |
| Consumer MCP | 7488 | 7488 |
| Consumer Frontend | 8888 | 80 |
| Modeling Workbench | 8100 | 5100 |
| Modeling MCP | 5188 | 5188 |
| Onto Modeling | 5100 | 8100 |
| 独立评测服务 | 8090 | 8090 |

Modeling Workbench 的默认宿主端口是 8100，5100 归 Onto Modeling——两者会同时运行，
沿用旧的 5100 会让 Onto Modeling 起不来。已部署实例的端口写在各自 `.env` 里，升级不受影响。

选择自定义端口时，脚本会逐项询问六个端口。端口输入会自动去除首尾空格，并校验为 `1` 到 `65535` 的整数。
提供了 Onto Modeling 发布包时，其端口不能与另外五个端口相同，相同时会要求重新输入。

首次安装会依次执行：

```text
执行 Onto Modeling 预检（提供了发布包时）
校验已有 knowledge-hub 容器归属（提供了 Hub 发布包时）
解压 Consumer 和 Modeling 发布包
生成 Consumer 与 Modeling 共用的 MODELING_SERVICE_TOKEN
生成 AUTH_BOOTSTRAP_ADMIN_PASSWORD
生成独立的 EVALUATION_SERVICE_TOKEN（提供评测发布包时）
执行 Consumer 预检
打印预检逐项结果
部署 Consumer
部署 Modeling
部署知识包 Hub（提供了发布包时），等待容器内健康检查通过
部署 Onto Modeling（提供了发布包时），等待 /api/health 就绪
部署独立评测服务（提供了发布包时），等待容器内 /evaluation/api/health 就绪
```

Onto Modeling 排在 Consumer、Modeling 之后部署，因此它的预检放在任何变更之前：已有 `onto-modeling` 容器
必须属于 `<安装根目录>/onto-modeling`，否则拒绝接管；随后运行发布包自带的
`preflight.sh`（AVX、内存、磁盘）。任一项不通过都直接退出，不会留下 Consumer、
Modeling 已变更而 Onto Modeling 起不来的半完成状态。已有 `knowledge-hub` 容器同样必须属于
`<安装根目录>/knowledge-hub`。

Onto Modeling 共享 Consumer 的账号中心：脚本读取 `onto-agent-backend` 容器的实际网络，
写入 `onto-modeling/.env` 的 `ONTO_MODELING_EXTERNAL_AUTH_NETWORK`，其自带的 auth-server 停用。
Consumer 未在运行时该步骤直接报错，不会写入猜测的网络名。

知识包 Hub 是独立 compose 项目（容器 `knowledge-hub`，数据卷 `knowledge-hub_knowledge-hub-data`），
部署在 `<安装根目录>/knowledge-hub`，同样加入 Consumer 的实际网络，Onto Modeling 经服务名访问它。
Hub 的服务凭据保存在 `knowledge-hub/.env`：首次部署时沿用 Onto Modeling 已有的
`ONTO_HUB_SERVICE_TOKEN`，没有时生成；随后脚本把 Onto Modeling 的该值对齐为 Hub 实际使用的值。
凭据只写入权限 600 的 `.env`，不会打印。

独立评测服务部署在 `<安装根目录>/eval-service`，使用独立的 `knowledge-evaluation` Compose
项目和 `knowledge-evaluation_evaluation-data` 数据卷。脚本读取 Consumer 的实际网络，将
Consumer、Hub 的评测凭据和 Onto Modeling 接收评测完成通知的凭据（`ONTO_EVALUATION_SERVICE_TOKEN`，
由 Onto Modeling 部署生成）传给评测部署脚本；凭据不出现在交互输出中。未部署 Onto Modeling 时评测只告警、
不发完成通知。已有评测容器的 Compose
工作目录必须是 `<安装根目录>/eval-service/deploy`，否则在变更服务之前拒绝接管。

评测配置由 `<安装根目录>/eval-service/deploy/.env` 保存（权限 600）。升级只复制镜像、清单和
部署文件，保留原加密密钥、端口及其他运行配置，不复制发布包或目录中可能存在的 `.env`。
默认界面地址为 `http://localhost:8090/evaluation/`，绑定所有网卡；远程机器使用部署主机的
地址访问。通过 `EVAL_PORT`、`EVAL_BIND_ADDRESS` 或评测运行配置调整端口和监听地址。
评测端口与六个交互端口分开配置；更改后需相应设置建模入口 `ONTO_WEB_EVAL_PUBLIC_URL`。
Judge 模型可由管理员登录评测页面后配置。

设置 `EVAL_ENV_FILE` 可使用已有受保护的外部配置，脚本提前校验并原样沿用；外部配置中的
加密密钥、依赖地址和评测凭据须自行配齐。部署失败或健康检查超时会停止流程，不报告交互部署完成。

Consumer 预检失败时会停止部署，并打印类似以下报告路径：

```text
<安装根目录>/onto-agent/.onto-runtime/opsctl/reports/<operation_id>/01-preflight
```

报告中的 `PASS`、`WARN`、`BLOCK` 含义如下：

| 状态 | 含义 |
| --- | --- |
| `PASS` | 检查通过 |
| `WARN` | 存在警告，脚本可继续部署 |
| `BLOCK` | 阻断部署，必须先处理 |

## 3. 旧合并部署迁移到新分离部署

此流程用于旧版本目录同时包含 Consumer 和 Modeling 的情况。

执行：

```bash
bash upgrade-consumer-modeling-legacy-interactive.sh
```

交互输入：

```text
旧的合并部署根目录
新的 Consumer 发布包路径
新的 Modeling 发布包路径
新的 Onto Modeling 发布包路径（留空跳过）
新的知识包 Hub 发布包路径（留空跳过）
新的独立评测服务发布包路径（留空跳过）
```

脚本会依次执行：

```text
校验旧安装目录和发布包
确认 Onto Modeling 端口并执行其预检（提供了发布包时）
校验已有 knowledge-hub 容器归属（提供了 Hub 发布包时）
执行 Consumer 预检并打印逐项结果
读取旧 Consumer 的端口和配置
备份 Consumer 配置
备份旧 Modeling 数据卷
停止属于旧安装目录的 Consumer 和 Modeling 容器
升级 Consumer
创建独立 Modeling 目录
迁移旧 Modeling 配置和端口
复用旧 Modeling 数据卷
部署独立 Modeling
校验新容器和数据卷
部署知识包 Hub（提供了发布包时）
部署 Onto Modeling（提供了发布包时），等待 /api/health 就绪
部署独立评测服务（提供了发布包时），等待容器内 /evaluation/api/health 就绪
```

旧合并部署的 Modeling 通常发布在 5100，迁移后原样保留，与 Onto Modeling 默认端口相同。
此时脚本会在动手前要求输入 Onto Modeling 的宿主端口，不能与 Consumer、Modeling 已用端口相同。
Onto Modeling 部署在 `<旧安装根目录的上级目录>/onto-modeling`，知识包 Hub 部署在
`<旧安装根目录的上级目录>/knowledge-hub`，均共享 Consumer 网络，接线方式与首次部署相同。
独立评测服务部署在 `<旧安装根目录的上级目录>/eval-service`；Consumer 评测凭据在其升级
重启前补齐，已有评测密钥和运行配置保留。

Modeling 端口在停止旧容器前从容器的端口绑定配置读取，自定义端口原样保留；读不到时脚本在动手前报错，
可用 `MODELING_PORT=<端口>` 显式指定后重试。

0.26.9.0 之前的合并部署只有 `mw-modeling`，没有 `mw-modeling-agent`：此时只备份并复用 Workbench 数据卷，
Agent 由新发布包首次创建。旧部署清单声明了 Agent 但容器不存在时，脚本拒绝升级。
`install-consumer-modeling.sh --upgrade-from` 的非交互迁移遵循相同规则。

迁移备份默认保存在：

```text
<旧安装根目录的上级目录>/backups/interactive-legacy-upgrade-<时间>/
```

该脚本只处理“旧合并部署迁移”。如果安装目录已经存在独立的 `modeling` 目录，应改用新架构交互脚本执行分离升级。

## 4. 新架构分离部署升级

执行：

```bash
bash install-consumer-modeling-interactive.sh
```

交互流程：

```text
1. 选择“升级部署”
2. 输入已分离部署的安装根目录
3. 选择升级 Consumer、Modeling，或两者一起升级
4. 输入对应的发布包路径
5. 输入 Onto Modeling 发布包路径（留空跳过；与上一步的升级范围无关）
6. 输入知识包 Hub 发布包路径（留空跳过；与升级范围无关，先于 Onto Modeling 部署）
7. 输入独立评测服务发布包路径（留空跳过；在 Hub、Onto Modeling 之后部署）
```

升级时不会询问端口，也不会重新指定端口。脚本会读取并保留：

```text
<安装根目录>/onto-agent/backend/.env
<安装根目录>/modeling/.env
<安装根目录>/onto-modeling/.env
```

其中的 Consumer、Modeling 和 Onto Modeling 端口配置。

唯一的例外是首次加入 Onto Modeling：它还没有 `.env`，默认端口 5100；0.26.9.0 之前的分离部署
Modeling 仍在 5100，两者相同时脚本会在动手前要求输入 Onto Modeling 的宿主端口。
Onto Modeling 的预检同样在任何变更之前执行，见第 2 节。
提供评测目录时同样提前检查包文件、容器归属和外部配置。评测目录留空则不触碰已有评测服务；
提供目录则更新交付物，保留 `eval-service/deploy/.env` 中的加密密钥和配置。
仅升级 Modeling 时，Consumer 必须已有有效的 `EVALUATION_SERVICE_TOKEN`；缺失时需选择
升级 Consumer 或两者一起升级，以便新生成的凭据随 Consumer 重启生效。

升级范围说明：

| 选项 | 行为 |
| --- | --- |
| `1` | 只升级 Consumer，只询问 Consumer 发布包 |
| `2` | 只升级 Modeling，只询问 Modeling 发布包 |
| `3` | 两者一起升级，依次询问两个发布包 |

Modeling 单独升级前会检查：

```text
Consumer 和 Modeling 目录存在
MODELING_SERVICE_TOKEN 两边一致
mw-modeling、mw-modeling-agent 属于当前 Modeling 目录
原 Modeling 数据卷存在且名称正确
```

Modeling 升级前会创建备份：

```text
<安装根目录>/backups/separated-interactive-upgrade-<时间>/
├── modeling.env
├── modeling-data.tar.gz
└── modeling-agent-data.tar.gz
```

升级成功后会再次校验：

```text
mw-modeling 使用 mw-modeling_modeling-data
mw-modeling-agent 使用 mw-modeling_modeling-agent-data
```

## 4A. 沿用已运行的 Consumer，只部署或升级 Hub、Onto Modeling、评测

Consumer 已在运行时，执行 `bash install-consumer-modeling-interactive.sh`，按提示操作：

```text
1. 选择模式 3（只部署或升级 Hub、Onto Modeling、评测）
2. 选择组件安装根目录（默认是运行中 Consumer 安装目录的上一级）
3. 输入 Onto Modeling 发布包路径（留空跳过）
4. 输入知识包 Hub 发布包路径（留空跳过）
5. 输入独立评测服务发布包路径（留空跳过）
```

三个发布包至少提供一个。该模式不安装、不升级、不重启 Consumer，也不修改 Consumer 的配置：

- 网络、jiuwenbox 沙箱卷和 Consumer 安装目录都从运行中的 `onto-agent-backend` 容器读取，
  评测凭据从该目录的 `backend/.env` 读取；
- Onto Modeling 沿用已部署时的端口，首次部署默认 5100；该端口已被其他容器发布时提示换一个；
- 以下情况会在任何变更之前退出，提示先升级 Consumer：Consumer 未运行；部署评测时 Consumer
  缺少 `EVALUATION_SERVICE_TOKEN`；Consumer 版本不支持独立评测。

部署顺序、凭据对齐和健康检查与其他模式相同。非交互式脚本中的对应用法见第 6 节。

## 5. 常见问题

### 5.1 `BUNDLE-CHECKSUMS: 发布包校验和失败`

说明发布包中的文件内容与 `checksums.txt` 不一致。常见原因包括：

```text
手工修改了发布包目录中的文件
发布包传输不完整
解压后覆盖了文件
```

应重新获取或重新构建完整发布包，不要直接修改发布包中的受校验文件。

### 5.2 `PORT-* 端口值无效`

首次安装自定义端口必须是 `1` 到 `65535` 的整数。输入前后带空格时脚本会自动清理；如果仍然失败，应检查是否混入了其他字符。

### 5.3 `awk: ... regexp escape sequence \" ...`

这是 awk 对正则表达式中 `\"` 写法的兼容性警告，通常不影响预检结果。应以预检报告中的 `PASS`、`WARN`、`BLOCK` 状态为准。

### 5.4 `Consumer 预检存在 BLOCK/ERROR`

查看报告目录中的：

```text
summary.txt
result.json
checks.tsv
logs/
```

先处理所有 `BLOCK` 项，再重新执行脚本。

### 5.5 `MODELING_SERVICE_TOKEN` 不一致

Consumer 和 Modeling 必须使用同一个至少 32 字符的服务令牌。分离升级时脚本会校验一致性；不一致时会停止升级。

### 5.6 端口被占用

首次安装时更换自定义端口。升级时脚本会沿用已有端口；如果端口被其他服务占用，应先处理占用服务或修正已有 `.env`，再重新升级。

Onto Modeling 与本套部署内其他服务的端口冲突由脚本在动手前检测并要求重新输入；被本套部署之外的
进程占用时，`deploy.sh` 拉起容器会失败，此时 Consumer、Modeling 已完成，处理占用后可单独执行
`bash <安装根目录>/onto-modeling/deploy.sh`。

## 6. 非交互式分离部署与升级

`install-consumer-modeling.sh` 同样支持首次安装、分离升级和旧版迁移。通过
`--evaluation-package <发布包>` 指定独立评测服务，不指定则跳过；发布包结构、Hub
依赖、共享网络、加密密钥保留与健康检查规则与前述交互式流程相同。

首次安装示例（以下路径为通用占位路径）：

```bash
INSTALL_ROOT=/opt/onto-agent-stack \
bash deploy/install-consumer-modeling.sh \
  --consumer-package /path/to/consumer-release.tar.gz \
  --modeling-package /path/to/modeling-release.tar.gz \
  --knowledge-hub-package /path/to/knowledge-hub-release.tar.gz \
  --onto-modeling-package /path/to/onto-modeling-release.tar.gz \
  --evaluation-package /path/to/evaluation-release.tar.gz
```

升级已分离的部署时，在脚本名后添加 `upgrade`，其余参数相同：

```bash
INSTALL_ROOT=/opt/onto-agent-stack \
bash deploy/install-consumer-modeling.sh upgrade \
  --consumer-package /path/to/consumer-release.tar.gz \
  --modeling-package /path/to/modeling-release.tar.gz \
  --knowledge-hub-package /path/to/knowledge-hub-release.tar.gz \
  --evaluation-package /path/to/evaluation-release.tar.gz
```

Consumer 已在运行、只需部署或升级知识包 Hub、Onto Modeling 和独立评测服务时，不传
`--consumer-package` 和 `--modeling-package`：

```bash
bash deploy/install-consumer-modeling.sh \
  --knowledge-hub-package /path/to/knowledge-hub-release.tar.gz \
  --onto-modeling-package /path/to/onto-modeling-release.tar.gz \
  --evaluation-package /path/to/evaluation-release.tar.gz
```

此时脚本不安装、不升级、不重启 Consumer，也不修改其配置：从运行中的 `onto-agent-backend` 容器
读取网络、jiuwenbox 沙箱卷和安装目录，再从该目录的 `backend/.env` 读取评测凭据。未设置
`INSTALL_ROOT` 且 Consumer 安装目录名为 `onto-agent` 时，组件安装在它旁边。Consumer 未运行、
