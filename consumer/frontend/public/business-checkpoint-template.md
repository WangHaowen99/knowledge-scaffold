# Business Checkpoint Template

本模板只定义 `report_business_checkpoint` 的通用调用规则、字段语义和摘要约束。具体业务步骤、`stage`、`phase`、中文标题和执行顺序由当前主流程或子流程 Markdown 定义，不在本模板中重复维护。

## 1. 使用原则

- `report_business_checkpoint` 用于向上层业务 Agent 上报业务阶段边界、状态变化和必要的交互元数据，不用于承载业务事实，也不替代业务推理。
- 业务流程进入一个明确阶段时，应上报 `*.started`。
- 阶段完成、跳过、失败、等待用户确认或准备结束前，应上报对应 `*.completed`、`*.skipped`、`*.failed` 或 `*.waiting_user`。
- `*.started` 只说明阶段目标、已知输入和下一步动作，不输出尚未验证的结论。
- `*.completed` 必须基于已经完成的工具结果、查询记录、人工确认或明确业务证据，但业务事实本身应保留在阶段内普通 events、工具结果、阶段正文或最终答案中。
- checkpoint 的 `summary` 只总结当前阶段，不写最终报告，不把多个后续阶段的结论提前合并。
- 同一主流程内，checkpoint 顺序必须与主流程步骤顺序一致；当前阶段的结束事件必须先于下一阶段的开始事件。
- 若任一工具或脚本结果明确返回等待用户确认状态，例如 `requires*Confirmation=true`、`workflowStatus=awaiting_*`、`nextAction=confirm_*`，当前阶段必须上报 `*.waiting_user` 并停止自动推进；不得自行代替用户选择后续分支，也不得上报 `*.completed` 或进入下一业务阶段。
- 如果一个阶段内部需要连续查询多个实体或执行多个工具，除非主流程另有要求，不必为每个查询细节都上报 checkpoint。checkpoint 负责标记阶段开始、结束、跳过、失败或等待人工确认；阶段内的实时过程和证据优先通过普通推理 events、工具结果和阶段正文输出，由业务 Agent 在当前阶段缓存中解析。

## 2. 业务数据查询通用约束

- 查询业务数据前，应先加载目标实体的 object 定义，并使用 object 中的准确中文字段名。
- 查询语句应明确目标实体、过滤条件和需要返回的字段；不要用"完整记录、所有字段、相关信息"等泛化表达替代字段名。
- 字符串型关键值（如单号、编号、标识等）作为等值过滤条件时，必须按原值加引号进行精确匹配。不得省略前导零、括号、连字符、斜杠、中文或其他标点，避免被查询工具误解析为表达式或非完整字段值。
- 如果查询返回了数据行，但除过滤关键值外的业务字段全部为空、明显缺少 object 定义中的关键字段，或结果只回显了查询条件，应视为"不可确认的伪命中"，不得作为有效业务记录继续推理。应先使用加引号的精确关键值重试一次，并优先返回 object 定义中的稳定字段；仍为空时按当前阶段失败或缺失证据处理。
- 如果返回字段中某个非过滤字段被工具提示不存在，应仅移除该可选返回字段后重试，不得改变过滤关键值、改查相似样例或用空字段补齐记录。
- 若工具返回字段不存在、空表头、无真实数据行或运行错误，应按当前阶段失败或缺失证据处理，不要改写查询条件、改查相似样例或编造记录。

## 3. 工具字段

`report_business_checkpoint` 仅使用以下顶层字段：

| 字段 | 必填 | 说明 |
| --- | --- | --- |
| stage | 是 | 稳定业务阶段 key。取值由当前流程 Markdown 明确给出。 |
| stage_title | 是 | 阶段中文标题。取值由当前流程 Markdown 明确给出。 |
| phase | 是 | 阶段生命周期 key，建议格式为 `{stage}.{lifecycle}`。 |
| phase_title | 是 | 当前 checkpoint 的中文标题。 |
| summary | 是 | 基于当前阶段事实的简短摘要。 |
| render_intent | 否 | 给业务 Agent 的呈现意图提示。 |
| entity_refs | 否 | 当前阶段涉及的业务实体、对象或关键记录引用。 |
| data | 否 | 可选交互或展示元数据；普通业务事实不要放入 checkpoint data。 |

不要使用工具 schema 未定义的顶层字段。需要输出结构化业务数据时，优先通过阶段内普通 events、工具结果、阶段正文或最终答案承载；不要在 `*.completed` checkpoint 中重复汇总同一批业务事实。

## 4. 生命周期

| lifecycle | phase 后缀 | 含义 |
| --- | --- | --- |
| started | `.started` | 阶段开始，目标和输入已明确。 |
| completed | `.completed` | 阶段完成，已有明确输出或结论。 |
| skipped | `.skipped` | 阶段按业务规则跳过。 |
| failed | `.failed` | 阶段因关键数据缺失、工具失败或规则阻断失败。 |
| waiting_user | `.waiting_user` | 阶段需要用户人工确认后才能继续。 |

## 5. render_intent

`render_intent` 是提示，不是强制渲染命令。业务 Agent 会结合 checkpoint、阶段内 events 和 LLM 总结选择最终呈现方式。

| render_intent | 适用场景 |
| --- | --- |
| text_summary | 阶段开始、简短结论、跳过、失败、等待人工确认。 |
| table | 单组结构化字段、查询结果、清单明细。 |
| section_tables | 多组表格，如多类清单、分类汇总。 |
| impact_tree | 具有层级或流转关系的结构，如组织层级、流程链路。 |
| metric_cards | 少量关键指标，如数量、条数、状态。 |

## 6. summary 约束

`summary` 应满足：

- 1 到 3 句话，优先短句。
- 只写当前阶段事实，不写推测。
- 可以包含关键数量、关键记录条数、阶段结论和下一步。
- 不要粘贴大表格；表格应通过阶段正文、工具结果或最终答案承载，不要通过 checkpoint data 重复承载。
- 失败或跳过时必须说明原因。
- 等待人工确认时必须写清需要用户确认的问题和可选路径。

推荐格式：

```text
当前阶段已完成/开始/跳过/失败：{关键事实}。阶段结论：{结论或状态}。下一步：{下一步动作}。
```

## 7. 人工确认

只有当前阶段确实需要用户输入后才能继续时，才上报 `.waiting_user`。

等待用户确认时：

```json
{
  "stage": "<由流程定义>",
  "stage_title": "<由流程定义>",
  "phase": "<stage>.waiting_user",
  "phase_title": "等待人工确认",
  "summary": "当前阶段需要用户确认：<确认问题>。确认后将继续：<后续路径>。",
  "render_intent": "text_summary",
  "data": {
    "question": "<需要用户确认的问题>",
    "options": ["<选项1>", "<选项2>"]
  }
}
```

用户确认完成后，应上报 `.completed`，并在 `summary` 中说明人工确认结果。后续阶段不得再次把已完成的人工确认描述为等待确认，除非当前阶段再次提出新的确认问题。

## 8. 阶段内事实输出约定

业务 Agent 会在当前阶段的 `*.started` 与 `*.completed` 之间持续消费普通 events，并从工具结果、阶段正文和最终答案中抽取结构化事实和证据。不要为了补充事实在 checkpoint data 中重复输出同一批业务数据。

阶段内输出结构化事实时，应尽量让普通 events、工具结果或阶段正文包含以下信息，便于业务 Agent 解析和呈现：

- 当前实体：涉及的实体、对象或记录的标识或名称。
- 关联实体：与当前实体存在关系的上游/下游实体。
- 关系类型：实体之间的业务关系（如交付、归属、流转等）。
- 关键数量：与当前阶段相关的计数、状态量等。
- 证据来源：使用的清单、查询结果、工具输出或业务规则。

## 9. 调用示例

阶段开始：

```json
{
  "stage": "example_stage",
  "stage_title": "示例阶段",
  "phase": "example_stage.started",
  "phase_title": "开始示例阶段",
  "summary": "开始执行示例阶段，已获得必要输入，下一步将查询业务数据。",
  "render_intent": "text_summary"
}
```

阶段完成：

```json
{
  "stage": "example_stage",
  "stage_title": "示例阶段",
  "phase": "example_stage.completed",
  "phase_title": "示例阶段完成",
  "summary": "示例阶段已完成：查询到 3 条记录，形成 2 条结果。下一步进入后续阶段。",
  "render_intent": "table",
  "entity_refs": ["示例业务实体"]
}
```
