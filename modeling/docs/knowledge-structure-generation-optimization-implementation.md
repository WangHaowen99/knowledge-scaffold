# 知识结构生成专项优化实施说明

> 基线：cs:5100 线上镜像 `mw-modeling:v2026.08.19-ae255448`
> 范围：仅修改资料分析完成后的知识结构生成。
> 不包含：领域分析、材料知识分析、全文读取、文档分段、资料分析缓存。

## 本轮实施内容

### 1. 批次级断点恢复

对象、规则/指标、业务操作三个阶段的批次结果写入 `generation_batch_checkpoints`：

- 成功批次保存结构化产物；
- 失败批次保存校验问题与累计尝试次数；
- 专家跳过保存明确决定；
- 生成门禁、额度或服务重启后的显式恢复会复用已完成批次；
- 输入、流程图、知识包基线或协议变化时，`planHash` 不同，旧检查点不会被复用。

生成计划指纹只引用文档修订指纹，不读取或重新处理文档正文。

### 2. 规则/指标即时校验

`submit_rules_metrics` 后立即检查：

- 当前批次内部 key 重复；
- 与已完成批次 key 重复；
- 规则引用不存在的对象；
- 指标引用不存在的对象。

校验问题会反馈给当前批次的下一次生成，只重试当前批次，不等最终整包保存时才失败。

### 3. 完整进度上报

进度总数现在包含：

```text
对象批次 + 规则/指标批次 + 操作批次 + 最终校验保存
```

业务操作阶段与最终校验保存阶段会持续更新统一 Job 的阶段、进度和心跳，不再在规则/指标完成后停留在旧百分比。

### 4. 资料分析边界

知识结构生成仍然只消费上游资料分析已经产出的：

- `candidateObjects`；
- `candidateArtifacts`；
- `materialEvidence`；
- `documentReadCoverage`；
- 已确认流程图。

本轮没有给知识生成 Agent 增加 `read_document`、`search_documents` 或全文读取门禁，也没有修改 `runAnalyze()`、`DocumentReadSession`、材料批次缓存。资料分析优化可在其他分支独立演进。

## 暂不启用的优化

规则/指标和操作批次有限并发暂不在本轮默认开启。原因是线上模型近期多次出现 `429`，在没有完善并发退避、额度暂停和同项目任务取消传播之前直接并发，可能缩短单次理想耗时，却会提高实际失败率。

下一阶段应在独立开关下实现：

```text
MODELING_KNOWLEDGE_GENERATION_CONCURRENCY=1|2|3
```

并满足：

- 429 自动降并发；
- `insufficient_quota` 不立即重试；
- 并发批次独立 capture 和校验；
- 合并、最终校验和候选版本保存保持串行原子执行。

## 验收标准

- 已完成批次再次生成时模型调用次数为 0；
- 规则/指标无效引用在当前批次暴露；
- `planHash` 变化时拒绝复用旧产物；
- 操作和最终校验阶段有准确进度；
- 原有整包映射、引用、安全校验全部保留；
- 资料分析相关代码和数据库协议无变化。
