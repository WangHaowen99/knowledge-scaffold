# 知识结构生成专项优化实施说明

> 基线：`fix/modeling-long-task-observability@ad6615d3`
> 范围：仅修改资料分析完成后的知识结构生成。
> 不包含：领域分析、材料知识分析、全文读取、文档分段、资料分析缓存。

## 本轮实施内容

### 1. 生成单元级断点恢复

对象、规则/指标、业务操作三个阶段的批次结果写入 `generation_batch_checkpoints`：

- 成功批次保存结构化产物；
- 失败批次保存校验问题与累计尝试次数；
- 专家跳过保存明确决定；
- 生成门禁、额度或服务重启后的显式恢复会复用已完成批次；
- 每个单元保存独立 `dependencyHash`；输入局部变化时只让受影响单元失效。

生成计划指纹只引用文档修订指纹，不读取或重新处理文档正文。

### 2. Excel 对象优先

- 只要输入中存在来自已上传 Excel/CSV 资料的 Sheet，对象目录就由业务 Sheet 确定性生成；
- Schema Manifest 只解释 Sheet，不生成对象；
- 文档对象候选只用于补充说明和证据，不新增对象；
- 只有没有结构化 Sheet 的纯文档项目才调用模型生成逻辑对象。

### 3. 动态批次与受控并发

- 对象和规则指标单批根据上下文动态取 8–12 个候选；
- operation 保持每批最多 3 个已确认流程；
- 三阶段默认并发分别为 4、4、3，可用环境变量降低；
- 429 和临时模型错误在当前单元退避重试，额度耗尽不重试；
- 所有批次完成后按计划顺序归并并执行全局 key、来源与引用校验。

### 4. 规则/指标即时校验

`submit_rules_metrics` 后立即检查：

- 当前批次内部 key 重复；
- 与已完成批次 key 重复；
- 规则引用不存在的对象；
- 指标引用不存在的对象。

校验问题会反馈给当前批次的下一次生成，只重试当前批次，不等最终整包保存时才失败。

### 5. 完整进度上报

进度总数现在包含：

```text
对象批次 + 规则/指标批次 + 操作批次 + 最终校验保存
```

业务操作阶段与最终校验保存阶段会持续更新统一 Job 的阶段、进度和心跳，不再在规则/指标完成后停留在旧百分比。

### 6. 资料分析边界

知识结构生成仍然只消费上游资料分析已经产出的：

- `candidateObjects`；
- `candidateArtifacts`；
- `materialEvidence`；
- `documentReadCoverage`；
- 已确认流程图。

本轮没有给知识生成 Agent 增加 `read_document`、`search_documents` 或全文读取门禁，也没有修改 `runAnalyze()`、`DocumentReadSession`、材料批次缓存。资料分析优化可在其他分支独立演进。

## 验收标准

- 已完成批次再次生成时模型调用次数为 0；
- 规则/指标无效引用在当前批次暴露；
- `planHash` 变化时只复用依赖指纹未变化的单元；
- 操作和最终校验阶段有准确进度；
- 原有整包映射、引用、安全校验全部保留；
- 资料分析相关代码和数据库协议无变化。
