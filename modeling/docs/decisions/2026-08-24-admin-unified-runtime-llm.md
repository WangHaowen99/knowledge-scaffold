# Modeling 管理员统一运行时 LLM 配置

> 状态：已实施 · 2026-08-24

## 决策

部署 Modeling Workbench 不再要求预先提供 LLM 地址、模型名或 API Key。admin 登录后在配置中心
维护的平台主模型与后台任务模型作为统一运行时默认，保存后对所有没有个人覆盖的账号立即生效。
个人覆盖仍保持最高优先级；平台后台任务模型未配置时使用平台主模型。

独立 modeling-agent 不保存第二份配置。每个新任务开始时，它通过 Modeling core 的内部接口读取
当前账号的有效模型配置。该接口同时校验用户或运行身份以及至少 32 字符的
`MODELING_SERVICE_TOKEN`，因此浏览器只有登录 Token 时无法读取 API Key。部署脚本在令牌缺失时
生成随机值并分别注入 core 与 agent，令牌和 API Key 均不得写入日志。

## 配置优先级

1. 当前账号的个人模型覆盖；
2. admin 当前保存的平台默认；
3. 历史用户默认快照；
4. 可选部署环境变量兜底。

平台 API Key 使用 AES-256-GCM 加密后存入 `modeling.db`，公开配置接口只返回是否已配置。内部
Agent 接口仅在容器网络内向通过双重认证的服务返回解密值，新任务每次重新解析，因此修改配置
不要求重启容器，已经运行中的任务继续使用启动时取得的模型实例。
