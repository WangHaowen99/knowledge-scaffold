# Mermaid 流程图导入

## Context

流程图编辑器以 `diagrams/processes.json` 中的结构化流程文档为事实源，`.mmd` 文件是确认流程后生成的派生产物。若上传的 Mermaid 仅作为附件保存，它不会进入流程确认和知识结构生成链路。浏览器端解析结果也不能作为可信写入，因为调用方可以绕过页面校验。

导入失败必须给出可操作原因，同时不能在校验失败或草稿修订冲突时产生半成品流程。

## Decision

- 服务端只解析 `flowchart` 和 `graph`，支持节点、连线、连线文字、方向和 `subgraph`；导入后转换为现有 `FlowchartDiagram`。
- 拒绝初始化指令、点击跳转、样式、HTML 和外部链接等不参与业务流程语义的内容。
- 使用“只读预览、确认写入”两阶段协议。两个阶段都执行相同解析和限制，确认时校验草稿修订并通过现有项目租约原子追加。
- 失败响应包含类别、原因、修复建议；可以定位时同时返回行号、列号和源码行。
- 结构化流程保留 Mermaid 文件名和图表类型作为来源信息；确认后仍由现有投影生成 `.mmd`，并由现有知识结构生成链路消费。
- 单次导入限制为 1 MiB、500 个节点和 1000 条连线，单份流程文档继续沿用最多 30 张流程图的既有限制。

## Alternatives considered

- 直接保存上传的 `.mmd`：不能稳定映射为知识生成需要的结构化流程，也会形成第二套事实源。
- 只在浏览器解析：无法防止绕过校验直接调用写入接口，且前后端错误口径容易漂移。
- 引入完整 Mermaid 运行时：覆盖范围远超当前需求，包体和攻击面更大，也不能直接得到现有流程模型所需的受控结构。

## Consequences

- 导入流程与人工编辑、保存、确认、版本记录和知识结构生成共用同一条链路。
- `subgraph` 只保留内部节点和连线，不保留分组边框；页面预览会明确提示该转换。
- 后续增加 Mermaid 语法时必须同时定义结构映射、失败诊断和安全边界，并补充解析及路由回归测试。
