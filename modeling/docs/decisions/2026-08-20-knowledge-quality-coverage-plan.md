# 知识结构生成的候选覆盖与能力拆分

## Context

知识结构生成已支持并发批次和断点续建，但首版候选规划把 Excel 来源候选当作规则、指标的唯一范围，导致产品手册中的可提取口径被统一延期。业务流程图又按一图一个 operation 生成，使多个可独立执行、复用和测试的能力被塞入单个大操作。批次校验只检查 key 与引用，空规则、空指标和没有流程步骤的 operation 要到整包体检才暴露。

## Decision

- Excel/CSV 继续唯一决定物理对象集合；文档不得扩张对象。
- 规则、指标候选同时保留表格和全文分析证据，通过候选处置判断与当前流程、对象和建模目标的相关性。
- 可提取候选的延期或排除必须给出具体边界，禁止使用“留待后续”等泛化理由。
- 多步骤确认流程生成一个总编排 operation，并为每个 action/decision 节点生成可独立测试的步骤 operation；单步骤流程保持一图一操作。
- 判断或匹配步骤必须引用 rule，计算或评估步骤必须引用 metric。
- 批次落检查点前拒绝空规则、空指标、空 operation，以及没有候选认领的规则指标。
- 继续复用现有动态分批、受控并发、自适应限流和依赖指纹检查点，不新增第二套生成路径。

## Alternatives considered

- 全部 47 个候选无条件生成：速度快但会把与当前流程无关的个人产品、竞品或旁支知识混入知识包。
- 继续只生成 Excel 同源知识：执行映射简单，但无法覆盖产品准入、匹配、异常和营销口径。
- 一张流程图只生成一个 operation：数量少，但能力不可复用、不可独立测试，且容易形成超长模糊流程。
- 每个流程节点都独立生成且不保留总编排：粒度清晰，但丢失端到端流程入口。

## Consequences

- 规则指标批次会增加，但最多 12 个候选一批并发执行，失败只重试受影响批次。
- 多步骤流程会生成更多 operation；总编排和步骤能力同时存在，后续脚本识别可以按步骤确定性能力处理。
- 严格批次门禁可能更早进入专家处理，但不会把空资源或无证据资源写入知识包。
- 候选或流程变化只使依赖指纹受影响的下游批次失效，已完成对象和无关知识批次仍可恢复。
