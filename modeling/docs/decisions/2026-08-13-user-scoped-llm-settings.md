# LLM 配置按认证用户隔离

## Context

modeling 原先把页面提交的 LLM 配置写入全局 `settings` 表。任意用户修改后，其他用户
的建模、校验、评测和优化任务都会立即使用同一配置，API Key 也没有用户所有权边界。

## Decision

- 新增 `user_llm_settings`，以认证令牌中的 `username` 为主键保存 LLM 配置。
- HTTP 请求建立异步用户上下文；请求派生的后台任务继承该上下文，LLM provider 在每次
  创建时读取当前用户配置。
- 环境变量作为所有用户的部署默认值。旧版全局 `settings.llm_*` 不向认证用户回退，避免
  将无法确定所有者的历史配置泄露给其他账号；它只保留给无认证 CLI 的兼容路径。
- 用户一旦保存个人端点、模型或 Key，任务模型也使用该用户配置，避免后台任务绕过隔离边界；
  只覆盖输出上限时仍可使用部署侧任务模型。

## Alternatives considered

- 在每个 LLM 调用函数上传递 `username`：调用点多且后台链路深，容易漏传。
- 将配置绑定项目：同一用户需要重复配置，且不符合“每个用户配置自己的 LLM”的需求。

## Consequences

- 不同用户可独立保存、清除和测试配置，API Key 仍只返回是否已配置。
- 部署环境变量继续提供零配置默认值；历史页面配置不会自动迁移，因为其真实所有者未知。
- 异步任务必须从已认证请求启动，或显式使用用户上下文；无上下文脚本只读取部署默认值。
