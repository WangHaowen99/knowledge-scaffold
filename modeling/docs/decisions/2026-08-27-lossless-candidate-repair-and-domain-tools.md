# 候选级修复、领域工具与无损校验报告

## 背景

旧修复循环把模型的一次成功写入当成修复成功，并在下一次模型调用时清空计数。
但成功写入只说明候选文件落库，不说明整包校验已经通过。多个互相依赖的详情、索引和
数据映射因此会在“写入成功、预检失败、计数清零”的循环中反复生成。

校验失败还会把全部 findings 直接放入工具结果。报告越大，后续每轮模型上下文越大，
相同错误又会随重试重复进入上下文，最终使建模时间主要消耗在历史错误的传输和解析上。

## 决策

### 修复状态属于候选，不属于一次写入

- 同一 run 的修复状态持久化在运行时 SQLite 中，服务重启和 checkpoint 恢复后继续使用。
- 一个 model call 内的并行校验失败合并为一轮。
- 成功执行 `write_file`、`delete_file` 或领域工具只记录“有修复进展”，不清零轮次。
- 修复状态绑定冻结候选 revision；切换到另一个 revision 时开启新的修复周期。
- 候选预检通过只记录 revision；只有确认结算成功，或整批候选被明确放弃，才清零修复状态。
- 相同 finding 指纹再次出现，或达到契约规定的最大轮数时，停止自动生成新候选。
- 停止后仍允许读取、删除和整体放弃；删除单个文件不会伪装成整包已经恢复。

### 校验报告采用完整事实与上下文摘要双层存储

每次可修复的核心校验失败都在同一事务中写入：

- `agent_validation_reports`：完整错误 envelope、稳定指纹、摘要和原始报告 JSON；
- `agent_validation_findings`：按原始顺序保存每条 finding JSON。

工具结果按以下规则返回：

- finding 不超过 5 项时，保留原有内联 findings，同时返回报告 ID 和指纹；
- 超过 5 项时，只返回有限的路径/规则分桶、总数、指纹和报告 ID；
- 即使不超过 5 项，只要 findings 超过 12000 字符或 reason 超过 2000 字符，也只返回摘要；
- 错误 reason 不再拼接全部 finding；
- 摘要中的路径和规则分桶各最多 20 项，单个标签最多 240 字符并带稳定哈希后缀；
- `get_validation_findings` 默认每页 20 项，最多 50 项，并返回稳定 ordinal。

这里的“压缩”只改变模型当前看到的投影，不修改、截断或合并持久化事实。指纹由完整
findings 计算，重复检测也不依赖摘要，因此不会把两个不同报告误判为相同报告。

### 结构化知识通过领域工具编译

新增四类领域写工具：

- `upsert_object`：接收对象字段、关系、查询边界、证据和可选的完整数据源绑定；
- `upsert_rule`：接收规则 key、适用对象/操作、条件、结论、例外和证据；
- `upsert_operation`：接收操作输入、输出、流程、对象/规则/指标引用和证据；
- `bind_object_source`：接收对象、资料 ID、表、完整字段绑定和主键。

核心先验证 key、引用、表和字段，再更新结构化 `PackageSpec`。详情、索引和映射统一由
`renderPackage` 生成。候选同时携带内部 `model/package-spec.json` 变更，预检和最终接受
因此读取同一份语义规格，不再出现 Markdown 已变化而规格仍停留在旧版本的情况。

派生索引、映射和内部规格进入自动 index 组，并依赖本批全部业务组；用户仍按业务规则、
操作和对象绑定审阅，而不是单独审阅机器生成的索引文本。
由于内部规格是整包单一事实源，包含领域工具产物的候选采用整批原子确认：确认卡仍展示
各业务组的影响范围，但不能只接受其中一部分。前端锁定该选择，核心也会拒绝绕过前端的
部分选择，避免依赖闭包把未勾选业务组静默带入正式版本。

## 受管写入灰度

- `mappings/object-data-mappings.json` 立即禁止直接写入，只能由 `upsert_object` 或 `bind_object_source` 生成。
- `objects/*.md`、`rules/*.md` 和 `operations/*.md` 当前返回弃用警告，Agent 提示词要求立即改用领域工具。
- 保留短期直接写兼容是为了让旧 checkpoint 能完成或被撤销；后续契约版本可把警告升级为拒绝。

## 不变量

1. 工具摘要可丢弃，完整校验事实不可丢弃。
2. 成功写入不等于校验通过。
3. 同一结构化输入必须生成相同的受管文件。
4. 模型不能直接修改内部语义规格或对象数据映射。
5. 分页读取不能改变报告指纹、顺序或内容。
6. 领域工具失败不得留下半份详情、索引或内部规格。
7. 专家没有选择的业务组不得通过派生组依赖被静默接受。

## 验证与观测

- 路由测试重建大报告的全部分页，并与持久化 finding 数量核对。
- 领域工具测试覆盖结构化调用、预检、确认、最终 spec 和渲染文件一致性。
- 运行时测试覆盖成功写入不清零、报告无内联 findings 时仍进入修复状态，以及重启恢复。
- 模型调用遥测继续记录输入字符数，可用来比较发布前后的上下文增长斜率和修复轮数。

## 回滚

领域工具写入的候选仍受现有确认与整体放弃机制保护。若新编译路径出现问题，可以退回
尚未确认的候选；正式版本不会被候选工具直接覆盖。数据库新增表是附加结构，旧代码忽略
这些表也不会改变已有知识包内容。
