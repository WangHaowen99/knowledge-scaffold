# 文档全文读取覆盖门禁

## Context

`read_document` 原先只返回正文片段和自然语言的“已到文末”提示。Agent 可以在没有连续读取全部内容时自行声称已经读完，资料分析和建模聊天也没有后端状态可以验证该声明。长文档因此可能只分析目录、前言或少量检索片段。

## Decision

- 使用共享的 `DocumentReadSession` 能力，在每次需要全文覆盖的 Agent 调用内记录文件总字符数、已读区间、连续覆盖终点和 EOF。
- `read_document` 以文件名寻址；同一调用若出现同名文档会明确失败，避免账本静默覆盖后误判为全文完成。
- 全文模式强制从 offset 0 开始，并严格使用上一页返回的 `nextOffset`；只有连续覆盖达到 `totalChars` 且观察到 EOF 才算完成。
- `runAnalyze` 的领域分析和每个未命中缓存的材料分类批次分别建立调用内账本，未完成时拒绝结构化提交；预算耗尽则让现有 analyze 节点失败，不增加任务图节点。
- `packageChatPlan` 在用户明确要求全文阅读时启用全文账本；增量修改方案则强制对本轮全部新增文本资料启用全文账本。普通聊天只使用当前知识包，不自动扫描原始资料。
- “全量提取、逐章提取、覆盖每个章节”等穷举式材料诉求与“全文阅读”采用同一门禁，避免用户要求全量提取时仍落入普通聊天模式。
- 全文模式使用按页数动态计算、上限 128 的独立回合预算。旧页原文在后续模型上下文中压缩为文件名、offset、滚动摘要和重要证据，最近一页保留原文。
- 材料分析缓存键加入全文读取协议版本和文档修订指纹，使门禁上线前的部分分析缓存自动失效。
- 分析完成后持久化由后端生成的 `documentReadCoverage`，并绑定文档 ID、修订指纹和字符数；知识对象可在 `sourceRefs[].readCoverage` 中携带匹配当前修订的覆盖快照。
- `sourceRefs[].anchors` 只表示选取的证据引用点，不表示阅读范围或正文收录清单。普通聊天不得根据锚点数量推断哪些章节未读；对象生成会重新合并分析阶段 `candidateArtifacts` 中的正文证据。

## Alternatives considered

- 只加强 Prompt：无法阻止模型误判 EOF，也无法检测跳 offset。
- 把全文阅读建成新任务或任务图节点：会改变现有工作流和用户待办，不符合调用内完成的交互口径。
- 全局提高 Agent 回合上限：会放大所有 Agent 的成本和死循环风险，且不能证明连续覆盖。
- 把全文一次性放入 Prompt：长文档会挤占上下文，并削弱后续分析和回答质量。

## Consequences

- 全文分析、增量修改方案和明确全文聊天会增加模型调用时长，但完成状态可由后端审计，不再依赖模型自述。
- 极长或多文档请求超过 128 回合时会明确失败并返回已读/未读范围，用户需要缩小范围或重试。
- 未命中缓存的材料分类批次会再次阅读本批文档，以保证分类结论本身接触过原文；已通过新协议写入的缓存仍可复用。
- 普通建模聊天的延迟和成本保持不变。
- 后续聊天可以区分“后端已验证全文覆盖”和“知识对象仅保留若干证据锚点”，不会再把两个锚点误报成只读取了两段正文。
