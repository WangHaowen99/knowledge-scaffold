# 增量资料

- 若项目由现有知识包导入，导入事件只建立“当前包是增量基线、尚未完成本项目真实评测”这一事实；不要重新跑目标和流程阶段，也不要把导入包说成已发布版本。直接等待或接收补充/替换资料。
- 导入包使用历史格式时，只修改被新资料真实影响的文件；不得以通过新格式检查为由重写整包。基线已有格式问题不属于本次增量候选。
- 先调用 `analyze_material_impact` 取得资料语义与既有来源关系。新增资料返回 `scopeResolved=false` 时，先读资料并核对相关知识，再用 `direct_resources` 提交直接影响起点；核心验证 key 后沿显式引用确定性传播。随后可用 `who_references` 对需要深挖的条目一跳一跳展开，传播到哪里停止由语义判断决定。
- 核对既有资料事实优先走档案与检索：先用 `get_material_context` 查已提取的文档摘要、业务事实和候选，再用 `search_documents` 定位锚点、按 offset 用 `read_document` 定点核对原文；档案标记 stale 的资料先重新全文精读。新上传的增量资料尚未入档，按上一条影响分析流程读取。写入知识包的数字和口径必须经原文锚点核对，不得直接引用档案摘要。
- 影响范围未确定时只呈现“正在界定范围”，不得把全包标成受影响，也不得宣称任何内容保持有效。范围确定后，主视觉先呈现“保持有效”，再呈现“需要处理”；不能让模型估算数量。
- 用 `focus(kind='impact', data=result.view)` 原样展示工具给出的状态、数量和证据链，不能改写数字。
- `scopeResolved`、`direct_resources` 等字段和工具调用步骤只供内部编排；用户可见正文只能描述“影响范围尚未界定/已界定”和实际业务影响。
- 同一批有两份以上资料时，逐份界定后必须以 `sources` 再取得一次核心确定性去重的合并视图；保持有效数、待处理数和证据链不得由模型拼接。
- 表格资料确实改变知识包内数据集时，调用 `stage_tabular_dataset` 完整同步候选；禁止分页读取后用 `write_file` 搬运整表，避免截断、漏行和超大工具参数。超出知识包上限的数据留在项目数据源，只更新对象字段与映射。
- 区分直接冲突和间接连带，提供资料段落到知识条目的证据链。
- “保留现行口径”必须写入 decisions 并标为已知不一致，不能静默忽略。
- 大面积冲突时主动给“增量修订”和“重新建模”两条路径，让专家选择。
- 候选确认前，已发布版本始终保持可用。
