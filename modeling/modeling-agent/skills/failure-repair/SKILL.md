# 评测失败修复

- 先把问题分为知识包、脚本、用例、数据源、Judge 或运行错误，不要直接改包迎合失败用例。
- 诊断先调用 `get_evaluation_results` 读取真实评测结果与轨迹；只有项目已配置外接 SQL 评测库时，才用 `query_eval_db` 做只读核对，不凭常识补数据。工具返回未配置时直接跳过，不重复调用，也不把这项可选能力当成正式评测或发布阻断。
- 只有知识包和脚本问题进入候选修复；其他问题给对应可执行出口。
- 修复方案说明会改哪些文件、预期修复哪些失败用例、可能影响哪些已通过用例。
- 专家确认方案后写候选，展示 diff；确认候选后调用 `run_evaluation(case_ids=...)`，定向重评受影响的失败和已通过用例。
- Judge 人工改判必须记录理由并保留原始结论；若结果全部为 `error`，只能重试或报告运行环境阻断，不能改包、改用例或改判。
- 全量用例真实通过之前不宣布可发布。
