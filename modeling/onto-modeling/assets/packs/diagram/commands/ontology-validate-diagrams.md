只读校验 draw.io flowcharts in ontology/diagrams/: Excel supplement alignment, structural check, then semantic check. No arguments.

对 `ontology/diagrams/` 中的所有 draw.io 流程图执行三段校验：

0. **Phase 0 — Excel 对齐校验**：检查拆分后的流程图与 Excel 补充表是否同名，drawio 中的非虚拟节点是否与 Excel「业务活动」列一致
1. **Phase A — 结构校验**：检查连线完整性、节点合规性等结构问题
2. **Phase B — 语义逻辑校验**：检查业务逻辑合理性、分支完整性等语义问题

**核心规则（必须严格遵守）：**

- 本命令是**只读校验**：只允许读取 `resource/`、`ontology/diagrams/`、`ontology/excel/`、`ontology/diagrams-summary/`
- 本命令只允许写入 `reports/`；禁止修改、生成或删除 `.drawio`、`.xlsx`、`ontology/diagrams-summary/*.md`
- 结构问题**只生成报告，绝不修改任何 .drawio 文件**
- Excel 对齐问题**只生成报告，绝不修改 .drawio 或 .xlsx 文件**
- 结构校验会读取 `resource/diagrams/图示说明定义.drawio`，图例中标记为"虚拟项"的节点类型只作为视图/注释辅助，不参与孤立节点、死路节点、无入边节点等结构问题判断；其中 `offPageConnector` 是透传虚拟项，语义上将输入和输出直接相连
- 悬空连线（浮动边）**绝对不能自动修复**（会改错）
- 语义问题只给出定位和处理建议；用户应修改 `resource/` 中的原始 drawio/xlsx 后，回复刷新选项，由代理内部执行刷新并继续引导重新校验
- 每个阶段的检查结果展示后**必须等待用户回复**，不要自动继续下一步

## 刷新模式速查

当任一阶段提示用户回 `resource/` 修改原始 drawio/xlsx 时，必须同时展示以下速查，方便用户直接选择刷新方式。用户只需回复右侧选项，不需要输入 slash 指令；代理内部执行对应刷新脚本。

| 适用场景 | 用户只需回复 |
|---|---|
| 原始 drawio/xlsx 改动较多，想完全重建派生产物 | `全量刷新` |
| 同名流程图页签和 Excel sheet 都需要刷新 | `刷新 A、B` |
| 只刷新 drawio 页签和对应摘要 | `刷新流程图 A、B` |
| 只刷新 Excel sheet | `刷新Excel A、B` |

如果原始目录里有多个 drawio/xlsx 文件，用户可以指定源文件：

- 流程图页签：`刷新流程图 resource/diagrams/总流程.drawio 中的 A、B`
- Excel sheet：`刷新Excel resource/excel/补充.xlsx 中的 A、B`

代理内部执行：

- `全量刷新` → `python3 .claude/scripts/init_flowchart_resources.py --refresh`
- `刷新 A、B` → `python3 .claude/scripts/init_flowchart_resources.py --names A B`
- `刷新流程图 A、B` → `python3 .claude/scripts/init_flowchart_resources.py --pages A B`
- `刷新Excel A、B` → `python3 .claude/scripts/init_flowchart_resources.py --sheets A B`

刷新只更新 `ontology/diagrams/`、`ontology/excel/`、`ontology/diagrams-summary/` 中的派生产物；刷新后仍需重新校验。

## Phase 0 — Excel 对齐校验

### 步骤 0.1：运行 Excel 对齐检查脚本

执行命令：

```bash
python3 .claude/scripts/check_diagram_excel_alignment.py
```

读取报告中"概览"表格里"问题"行的数量：

- Excel 缺少同名流程图：`ontology/excel/{名称}.xlsx` 没有对应 `ontology/diagrams/{名称}.drawio`
- Excel 缺少「业务活动」列
- drawio 非虚拟节点与 Excel「业务活动」列不一致

展示完毕后，向用户发送以下消息（替换 N 为实际值）：

> - 回复 **跳过** → 直接进入结构校验

**在此等待用户回复，不要自动继续。**

### 步骤 0.4：处理用户回复

**用户回复"继续"（或含义相近的表述）：**

- 读取最新的 `*-diagrams-excel.md` 报告
- 如果仍有问题，回到步骤 0.3 展示
- 如果全部通过，进入 Phase A

**用户回复"跳过"（或含义相近的表述）：**

- 告知用户将跳过剩余 Excel 对齐问题，进入结构校验

python3 .claude/scripts/check_diagrams.py

读取报告中"结构检查概览"表格里"有问题"行的数量：

## Phase B — 语义逻辑校验

> **前置条件**：Phase A 已完成（结构问题已处理，或用户选择跳过）。

### 步骤 B1：获取流程摘要

对比 `ontology/diagrams/` 中的 `.drawio` 文件与 `ontology/diagrams-summary/` 中的 `.md` 文件，确保摘要与流程图一一对应。

执行只读同步检查：

1. 找出 `ontology/diagrams/` 中有 `.drawio` 文件但 `ontology/diagrams-summary/` 中缺少对应 `.md` 的（新增图）。
2. 找出 `ontology/diagrams-summary/` 中有 `.md` 文件但 `ontology/diagrams/` 中已无对应 `.drawio` 的（孤立摘要）。
3. 找出 `ontology/diagrams-summary/{name}.md` 比 `ontology/diagrams/{name}.drawio` 更旧的（摘要过期）。

如果存在新增图、孤立摘要或摘要过期：

- 向用户列出具体文件
- 告知用户："语义校验依赖最新的流程图摘要。请先按下方刷新方式回复，例如 `刷新流程图 图名...` 或 `全量刷新`，我更新后再重新校验。"
- **停止 Phase B，不要生成、删除或修改任何摘要文件**

读取 `ontology/diagrams-summary/` 下的所有 `.md` 文件内容。每个文件对应一个流程图的摘要。

### 步骤 B2：语义分析

语义分析分两部分：先逐图检查单图内的逻辑问题，再跨图检查子流程引用的一致性。

#### 准备：收集所有流程图名称

从摘要中提取所有流程图的名称（每个 `# <名称> — 流程摘要` 标题中的名称），建立一份**流程图名称清单**，供后续跨图校验使用。

#### 第一部分：单图语义检查（对每个流程图逐一执行）

对摘要中的**每一个流程图**，依次检查以下 8 项。每一项都必须检查，不可跳过。

| # | 检查项 | 检查内容 | 问题示例 |
|---|--------|----------|----------|
| 1 | **分支完整性** | 每个判断节点是否有至少两条互斥出路；二值判断检查正反两支，分类判断允许多于两支并检查必要分类/默认分支是否覆盖，禁止把合法多分类分支误报为缺少"是/否" | 分类节点"判断订单状态"已有"待付款/已付款/已取消"三条分支时，不应报缺少"是/否"；若只保留"待付款"一支才算缺分支 |
| 2 | **分支语义一致性** | 分支标签是否与判断条件的语义匹配；二值判断用正反语义，分类判断用实际分类值 | 判断"订单状态属于哪类"的分支标签写成"成功"/"失败"，与状态分类不匹配 |
| 3 | **死路路径** | 是否存在某条分支路径无法到达结束节点 | "否"分支连接到一个没有后续出路的节点 |
| 4 | **节点标签合理性** | 节点描述是否与其类型匹配：动作节点应描述动作、判断节点应描述条件、子流程节点应引用另一个流程名 | 动作节点写了判断条件"是否有库存？"，应改为判断节点 |
| 5 | **前后逻辑连贯性** | 相邻节点的业务顺序是否自洽 | 先执行"下采购PO"再"判断是否有供应商"（顺序应反过来） |
| 6 | **异常/未覆盖路径** | 二值判断的否定路径、分类判断的未覆盖分类或默认/其他路径，是否有明确处理（提示、终止、回退等） | 分类判断覆盖"待付款/已付款"，但缺少"已取消"或"其他状态"的处理路径 |
| 7 | **说明节点内容质量** | 说明节点（注释）是否提供了有意义的补充信息（如输入/输出/业务逻辑说明），而不是简单重复节点名或内容为空 | 说明节点内容是"获取供应商"——与节点名完全重复，没有补充价值 |
| 8 | **数据流可追溯性** | 节点中引用的数据（如"Mpart编码"）是否可以追溯到上游节点的输出或流程的输入参数中 | 节点"获取Mpart编码对应的供应商"引用了"Mpart编码"，但上游没有任何节点产出这个数据 |

#### 第二部分：跨图校验（需要对比所有流程图的摘要）

遍历所有流程图中的**子流程节点**和**子流程判断节点**，执行以下 4 项检查：

| # | 检查项 | 检查内容 | 问题示例 |
|---|--------|----------|----------|
| 9 | **子流程引用存在性** | 子流程节点/子流程判断节点引用的名称，是否能在流程图名称清单中找到**完全匹配**的条目？找不到则为严重问题 | 子流程节点"判断Mpart是否有在制"在名称清单中不存在 |
| 10 | **子流程名称一致性** | 引用名与实际图名是否存在细微差异（多字、少字、空格、标点不同）？用模糊匹配检测，若能匹配到则报警告 | 引用"Epart到Mpart转换"但实际图名是"Epart到Mpart的转换"（多了"的"）；引用"判断Mpart在该机型MBOM 中是否存在"但实际图名无空格 |
| 11 | **子流程输入输出衔接** | 调用方在说明/注释中声明的输入参数，是否与被调用子流程开始节点定义的输入一致？子流程的输出是否与调用方期望的结果一致？ | 调用方传入"子ECO编号"，但子流程开始节点定义的输入是"ECO编号"（参数名不一致） |
| 12 | **子流程判断节点结果类型** | 子流程判断节点引用的子流程，其结果是否是可作为分支条件的离散判断/分类结果（不限"是/否"；检查被引用子流程的结束节点或输出说明） | 子流程判断节点引用"获取在制品数量"，但该子流程返回连续数量而非离散判断/分类结果 |

#### 评级标准

**对每个发现的问题，标注严重等级：**

- **严重**：流程逻辑断裂或引用错误——某分支无出路、通向错误结果、子流程引用不存在、输入输出根本不匹配
- **警告**：语义模糊或可能有误——标签与条件不符、子流程名称有细微差异、缺少异常路径说明、说明节点质量差
- **建议**：可读性改进——不影响流程正确性，仅优化表述、补充说明或统一命名

**对每个问题，给出具体的处理建议**（说明应在 `resource/` 原始文件中如何调整，如补充缺失分支、统一节点标签等），供用户人工修改源文件。

### 步骤 B3：生成语义分析报告

将所有分析结果写入 `reports/{YYYYMMDD}-{HHMMSS}-diagrams-semantic.md`（使用当前 `Asia/Shanghai` 时间，格式 `YYYYMMDD-HHMMSS`），严格按以下格式：

```markdown
# 流程图语义分析报告

日期：YYYY-MM-DD HH:MM:SS Asia/Shanghai
分析目录：`ontology/diagrams`

## 概览

| 状态 | 数量 |
|------|------|
| 有严重问题 | N |
| 有警告 | N |
| 仅建议 | N |
| 无问题 | N |

## 问题详情

> **处理说明**：每个问题都带全局唯一编号，编号只用于定位问题；本命令不自动修改流程图或 Excel。

### <流程图名称>

- [#1] **[严重] <问题类型>**
  <具体描述>
  处理建议：<应在 resource 原始文件中调整的内容>

- [#2] **[警告] <问题类型>**
  <具体描述>
  处理建议：<应在 resource 原始文件中调整的内容>

- [#3] **[建议] <问题类型>**
  <具体描述>
  处理建议：<应在 resource 原始文件中调整的内容>

---

## 无问题的流程图

- **<名称>**：<一句话描述该流程的用途>
```

**格式规则：**

- 所有问题统一以 `- [#编号]` 开头，编号在整份报告中全局唯一，供用户在对话中引用
- 每个问题都必须附带"处理建议"，描述应回到 `resource/` 原始文件中修改的内容

### 步骤 B4：展示语义问题并说明后续处理

1. 向用户展示所有**严重**和**警告**级别问题的摘要清单，保留每个问题的编号；如有需要，也可一并展示**建议**级别问题的编号清单

2. 根据情况向用户发送不同消息：

**有问题时：**

> 语义分析发现 **X** 个严重问题、**Y** 个警告和 **Z** 个建议，已记入语义分析报告。
>
> 请在资料区修改原始流程图或 Excel，再按上面的刷新方式回复，我更新流程图、Excel 和流程图摘要后重新校验。

**无任何语义问题时：**

> 语义分析完成，所有流程图均未发现问题。

3. **在此结束本轮校验，不要自动继续刷新或修改任何文件。**
