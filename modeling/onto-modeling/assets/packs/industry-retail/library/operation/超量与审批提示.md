# 业务描述
补货单编制完成后，按门店所属区域和商品品类累计本周补货量并与区域配额比较；超量的补货行置为待审批，并给出审批层级。

# 与operation的关联
- 被operation调用 > [[补货编制主流程]]
- 调用operation > 无
- 可单独调用 > 否

# 与object的关联
- 输入数据的对象：[[补货单]]、[[门店]]、[[商品]]
- 输出数据的对象：[[补货单]]、[[区域配额]]
- 支撑数据的对象：无

# 与object的语义关联
| 业务对象 | 语义关联关系 |
|---------|--------|
| 补货单 | 提供本次补货行，回写超量标记和单据状态 |
| 门店 | 提供区域编码 |
| 商品 | 提供品类编码，用于按品类汇总 |
| 区域配额 | 提供配额数量，回写已用数量 |

# 触发条件
[[补货编制主流程]] 生成补货单明细后调用。

# 输入
| 参数名称 | 描述 | 输入源 |
|--------|------|-------|
| 门店编码 | 本次编制的门店 | [[补货编制主流程]] 的输入 |
| 补货日期 | 本次编制的日期 | [[补货编制主流程]] 的输入 |
| 补货单明细 | 本次生成的补货行集合 | [[补货编制主流程]] 步骤 3 的产出 |

**查询边界**：补货单明细只取本次编制产生的行，不查询历史补货单；按区域编码、品类编码、配额周期查询 [[区域配额]]，每个品类至多 1 行。无匹配配额时该品类不受配额约束，在配额使用情况中注明。

# 输出
| 参数名称 | 描述 |
|--------|----|
| 待审批行清单 | 超量的补货行及审批层级 |
| 配额使用情况 | 各品类的配额数量、已用数量和本单数量 |

# 逻辑描述
1. 基于门店编码，读取 [[门店]].区域编码
2. 配额周期 = 补货日期所在的自然周，格式为「年份-W周序号」。
3. 基于补货单明细中的商品编码，读取 [[商品]].品类编码，按品类编码汇总建议补货数量，得到本单品类合计集合（字段：品类编码、本单数量）。
4. loop 遍历 本单品类合计集合，当前项记为当前品类：
   - 基于区域编码、当前品类.品类编码、配额周期，查询 [[区域配额]]，读取配额数量、已用数量、审批阈值比例。
   - if 无匹配记录 then 配额使用情况记为「无配额约束」，处理下一项
   - 超出数量 = 已用数量 + 当前品类.本单数量 − 配额数量
   - 按下表处理该品类的全部补货行（首条命中即停止）：

     | 条件 | 超量标记 | 单据状态 | 审批层级 | 已用数量 |
     |------|---------|---------|---------|---------|
     | 超出数量 <= 0 | 否 | 不变 | 无 | 加上本单数量 |
     | 超出数量 / 配额数量 <= 审批阈值比例 | 是 | 待审批 | 区域负责人 | 不变，审批通过后再计入 |
     | 其他 | 是 | 待审批 | 运营负责人 | 不变，审批通过后再计入 |

   - 将超量标记、单据状态写回 [[补货单]]，超量的行记入待审批行清单。
   end loop
5. 返回待审批行清单、配额使用情况。
