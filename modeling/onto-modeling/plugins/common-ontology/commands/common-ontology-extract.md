抽取公共本体。参数：$ARGUMENTS

- 输入知识包在 `ext/common-ontology/uploads/inputs/<上传 id>/`，**只读**（改了也不会合入）；换包、加包请用户在「公共本体」页上传。
- 这是专门抽公共本体的项目：`ontology/` 里只放实类，发布出去就是公共本体知识包。
- 门槛 N：从参数取（`min=N`、`--min N` 或单个数字都认），没给就不传，脚本沿用上次的，再没有就是 2。
- 步骤、脚本、锁、文件名不对用户说；进度只说业务话（如「对象合并好了，正在核对」）。

## 判定口径

- **公共**：至少 N 个包都有。
- **对象**：含义相同的对象，取这些包里含义和类型都一致的属性、关系的交集。交集除主键外至少一项 → **实类**（父类 = 交集，各包多出的记进映射）；否则 → **虚类**，进术语表（通用定义 + 各包叫法）。
- **规则**：逻辑相同 → 实类；只差数值或枚举 → 虚类，记成规则模板（模板 + 参数 + 各包实例与参数值），不做实例化。
- **操作**：步骤和前置条件都一致才是实类；否则没抽出。操作没有虚类。
- 指标、脚本不在抽取范围。每个输入对象、操作、规则都要进继承映射，没抽出的也列。

## Step 1：清单与决定草稿（一条命令）

```bash
python3 .claude/scripts/state_helper.py acquire common-ontology-extract start && python3 .claude/scripts/co_inventory.py --min N
```

- 说「至少要 2 个包」：告诉用户先在「公共本体」页上传，`release common-ontology-extract` 后结束。
- 说抽取决定有格式问题：按提示改好 `ext/common-ontology/result/merge.yaml` 再跑。
- 否则它写好了 `ext/common-ontology/result/merge.yaml`：已有的决定原样保留；新条目能并进已有组的已经并入（注释「新加入」）；其余按名称、别名、结构预分组，给了建议的 class。每组上方的注释是依据：对象写共有和多出的属性，操作写步骤，规则写约束原文。

## Step 2：语义合并（只改 merge.yaml）

Read 一次 `merge.yaml`，按口径改；改动多就整份 Write，少就 Edit。草稿只看名称和结构，你补语义：

- 名字不同、含义相同的条目并成一组（看依据里的属性、步骤、原文）；含义不同却分在一起的拆开，拆出来的单独成组、`class: none`，`note` 写原因（如「含义不同：这里指工位」）。脚本自己写的没抽出原因（空、「不到 N 个包」「……不一致」）下次会重新判，你写的原因会保留。
- `name` 用通用叫法，不带某个包的业务词；实类的 `name` 就是 `ontology/` 里的文件名，实类之间不能重名。
- 对象：主键以外没有共有属性 → `virtual`，写 `definition`（一句通用定义）。
- 规则：`virtual` 的 `template` 用 `{参数名}` 占位，把 `参数1` 这类名字改成有含义的（如 `上限天数`），`params` 写 `meaning`，每个成员的 `values` 写全。
- 操作：步骤或前置条件不一致的保持 `none`，`note` 写原因。
- 不删成员：每个输入条目都要留在某一组里。注释不用改，下次会重新生成。

## Step 3：写实类、生成结果、核对（一条命令）

```bash
python3 .claude/scripts/co_inventory.py --min N --apply && python3 .claude/scripts/co_check.py
```

- `--apply` 只给还没有 `ontology/` 条目的实类写草稿：对象取交集属性，各包叫法写进「属性别名」；操作、规则取代表成员的正文，链接换成公共条目名。已有条目不动。
- `co_check.py` 生成「公共本体」页读的实类清单、术语表、规则模板、继承映射，并核对：映射覆盖每个输入条目、门槛、实类和 `ontology/` 一致、公共属性在每个成员里对得上、关系每个成员都有、链接只指向实类、`ontology_checker` 的错误、产物格式。

## Step 4：润色这次新写的实类

只看 Step 3 输出里「已写进 ontology/」列的条目：对象描述、业务描述、规则描述里只适用于某一个包的说法（如「图书」「工具间」）改成通用说法。不加交集以外的属性和关系。以前就有的条目不重写，除非 `co_check.py` 报了它的问题。

## Step 5：修到通过

`co_check.py` 没通过就按问题改，再跑 `python3 .claude/scripts/co_check.py`，直到通过：

- 「没有映射」：把条目加进合适的组，或单独成组 `class: none`。
- 公共属性「对不上」：在 `ontology/` 条目的「属性别名」里写上它在那个包的叫法，或从公共条目里去掉这个属性。
- 「上次是实类、这次不是了」：删掉那个 `ontology/` 文件。
- `merge.yaml` 的分组或归类改了以后，重跑 Step 3 那条命令（会补写新实类的草稿）。
- 「不在实类清单里」只是提醒：不是本命令建的条目，转告用户，不要删。

## Step 6：收尾

`python3 .claude/scripts/state_helper.py release common-ontology-extract`。结束语一两句：实类、术语、规则模板、没抽出各多少；结果在「公共本体」页查看、下载；实类发布成知识包后，下游项目用领域包扩展继承。
