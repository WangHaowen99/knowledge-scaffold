# 访谈问答的逐题回答与回看

`AskUserQuestion` 卡片对单选、多选及文字输入使用同一提交入口。每题都有独立的文字回答框；编辑、清空一题不会改变其他题的回答。

- 单选题可选择一个选项，或填写文字回答；两种输入互相替换。
- 多选题可选择多个选项，并填写补充文字；提交时保留两者。
- 每题自带文字框；选项应写有实际含义的典型答案，不生成占位项。Other 输入入口及明确标注为占位示例的选项转为文字输入；有实际含义的“其他”“其它”选项照常保留。
- 单题、多题均通过“提交回答”统一校验和提交，选择单选项后仍可修改回答。缺答会定位到对应输入框并提示，不发出请求。Enter 换行，Ctrl/⌘+Enter 与按钮共用同一提交入口。
- 提交期间禁止重复提交；失败后保留输入并恢复编辑。
- 异常卡显示具体格式原因，提供“让助手重新提问”按钮，通过 deny 将修正要求返回给引擎；Jiuwen 边界将字符串选项转换为带 label 的对象。

接口保持 `answers: {问题文本: 回答字符串}` 契约，多选沿用逗号连接。题目文本必须非空且不重复，所有题目必须提供非空字符串答案。服务端拒绝缺答、额外答案和重复问题，并保留待处理请求，允许更正或取消。

成功答案写入 `permission_resolved.answers`，历史卡片和刷新回看显示已保存的真实答案。缺失答案只在卡片级提示一次，不渲染空的逐题答案块。取消、失效状态在卡片级展示；新超时事件保留 `behavior: deny` 并增加 `reason: timeout`，与主动取消区分。旧事件没有原因时不推断超时。

410/404 补发复用普通消息的发送锁、目标确认及忙碌状态，不读取或清空聊天草稿和附件。补发使用独立的 `POST /session/questions/{request_id}/forward` 接口，提交 `answers` 与 `conversation_id`；普通 messages 接口保持原结构。服务端验证原问题属于目标会话、答案完整且未被处理，调用原消息发送流程受理后保存 `behavior: forwarded` 和答案。“已补发”仅表示服务器受理成功，不代表模型已收到、理解或执行。失败显示具体原因，原卡保留输入供重试。

已答复卡保留原有正式选项和只读状态，当前卡片提交后的选中标记不因展示答案而消失。会话切换后展示保存的答案文本，不从逗号连接的多选答案反推勾选状态。

## 回归检查

测试数据均为人工构造的合成数据。

- 前端：`cd frontend && npm test && npm run build`。
- 后端专项：`cd backend && python -m pytest tests/test_question_answers.py tests/test_session_pool.py tests/test_studio_and_settings.py tests/test_claude_engine.py tests/test_jiuwen_engine.py`。
- 真实页面：同一卡片询问单选、多选和两道文字题，分别修改、清空文字；核对缺答时无请求、补齐后实际提交正文、助手复述、刷新回看与后端保存答案的一致性。

合成示例：环境选择“环境二”，渠道选择“渠道一”和“渠道三”，两段文字分别为“合成答案甲”和“合成答案乙”。不要使用实际业务数据或在报告中保存模型地址和凭据。
