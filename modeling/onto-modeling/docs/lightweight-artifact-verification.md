# 建模收尾轻量核验

## 1. 本轮范围

基于 `0.26.10.1` 的 `48310631fab3c816d7367bfe08a48491e4f812c6`，在独立分支
`fix/modeling-lightweight-verification` 实施。本记录仅包含本地验证；远程部署验收与分支合并另行确认。

- 空闲会话默认回收时间从 120 秒调整为 600 秒，仅做缓解。显式设置的
  `ONTO_WEB_SESSION_IDLE_TTL` 仍优先；升级时要检查实际部署配置，不能仅看默认值。
  原定时扫描周期仍为 30 秒，超过阈值后在下一次扫描回收，不是精确到第 600 秒执行。
- 合并“产物完成核验”和“确定性结构核验”：复用已有检查器，不增加模型审查轮次。
- 不修改资料用途登记、中文命令路由、子任务生命周期、会话换绑或池满驱逐逻辑。
- 不修改在线项目、原材料、业务知识包和既有测试记录。

## 2. 何时执行

流程图、对象、操作/规则/指标提取的收尾阶段运行一次；提取和覆盖子任务必须先实际结束。
应生成文件清单来自本轮计划及既有覆盖/对账结果，不能用“当前目录里有什么”代替。

在工作区根目录执行（文件名均为合成示例）：

```bash
python3 .claude/scripts/verify_artifacts.py diagrams --files "ontology/diagrams/FlowA.drawio"
python3 .claude/scripts/verify_artifacts.py objects --files "ontology/object/EntityA.md"
python3 .claude/scripts/verify_artifacts.py operations --files "ontology/operation/TaskA.md" "ontology/rule/RuleA.md" "ontology/metric/MetricA.md"
```

不带 `--files` 时核验对应类别全部已有产物；该方式不能单独证明计划中的文件没有遗漏。

| 退出码 | 含义 | 后续处理 |
| --- | --- | --- |
| 0 | 指定产物的确定性检查通过 | 保留摘要，按原确认/保存流程继续 |
| 1 | 发现确定性错误 | 只修对应产物，再核验；不更改源资料 |
| 2 | 无产物、缺文件、检查异常或核验期间内容变化 | 不宣布完成；先处理原因再重验 |

检查内容包括文件存在、有效正文/章节、对象字段与来源表一致性、关系字段方向和双端声明一致性，
以及流程图 ID、连线端点、基本连通结构。支持一端声明关联字段，不强制重复声明；
多页流程图 ID 按页隔离。无法读取的已登记数据表不能作为字段核验通过的依据。

保留既有警告/建议等级和完整语义检查；通过轻量核验不等于业务规则正确或业务覆盖完整。

## 3. 结果复用与保存提示

- 核验记录位于 `.ontology-state/artifact-reviews/`，不是知识包业务文件。
- 文件内容、交叉引用、资料用途配置、相关表格、调研报告或检查器实现变化后，旧记录失效。
- 相同输入修订及相同目标集合复用结果；失败结果也保留，不用后续成功覆盖首次失败证据。
- 缺少、损坏、版本不匹配或状态矛盾的记录均不能作为通过证据。
- 提交前 hook 复用相同核验，不再遇到检查器异常就按空问题列表放行。
  暂存版本与待核验文件不同则阻止提交，要求先完整暂存对应文件。
- 提交后 hook 只读当前记录，不重新检查；“版本已保存”与“产物核验通过”分别提示。
  增量批次通过不自动等同于整个阶段通过；完整阶段没有当前记录时明确提示仍待核验。
- 默认输出仅摘要及最多 12 条截短问题，完整问题留在核验记录；不向模型反复灌入完整报告。

核验记录不是签名证据，也不能防止恶意篡改；它面向正常工作流的修订一致性检查。
文件扫描不是事务锁，核验后再次写入必须重验。前端阶段计数与后台子任务状态机未在本轮重写。

## 4. 本地验证

验证环境为 macOS、Python 3.12.14、隔离依赖环境，使用全新合成数据，不访问模型和在线服务。

功能覆盖：默认 600 秒及显式覆盖；120/599/600/601 秒边界；空目录/仅索引；计划产物缺失；
对象与操作/规则/指标；引用与字段错误；单端/冲突关系声明；流程图缺失或重复 ID、悬空边、
多页及包装节点；无系统时区库的降级；损坏表格；核验记录复用、失效、损坏、并发变更；
路径越界；真实临时 Git 工作区的提交前拦截与提交后完成提示。

2026-10-20 最终全量执行结果：**550 通过，8 失败**；同一依赖环境、同一 PATH 的干净原基线
为 **513 通过，8 失败**。本轮新增 37 条用例全部通过，没有新增失败项。
全量套件不能描述为全部通过：两侧失败名单一致，包含 7 条 openJiuwen 依赖缺失失败，
以及 1 条 `test_studio_graph_links_and_degrees` 失败。这些均不在本轮修复范围。
另已通过 Python 语法、Shell 语法、diff 空白检查及新增内容敏感信息检查；数据均为合成数据。

复跑方式（先使用具备后端测试依赖的隔离 Python 环境，并把其 bin 目录放在 PATH 最前）：

```bash
PYTHONPATH=backend python -m pytest -q -p no:cacheprovider backend/tests
python -B backend/tests/benchmark_artifact_verification.py
```

性能脚本比较基线检查器与当前检查器；每项执行 15 次，包含 Python 启动成本。
测试数据为合成对象、简单关系、操作、规则、指标和流程图，另含 10 万行单列 CSV 场景。
其中“核验/缓存/状态读取”序列模拟三次脚本调用，不含 Git 提交、模型、网络和浏览器时间。
这些数据不能当作线上端到端建模时长或峰值容量结论。

同机复测结果（中位数，毫秒；原/新检查选取同一批对象，其他文档保留为引用上下文）：

| 合成规模 | 原对象检查 | 新核验首次 | 单次增量 | 缓存读取 | 核验/缓存/状态读取序列 |
| --- | ---: | ---: | ---: | ---: | ---: |
| 50 对象，操作/规则/指标各 10，20 图 | 52.17 | 75.86 | 23.69 | 73.03 | 193.92 |
| 500 对象，操作/规则/指标各 100，100 图 | 90.62 | 298.26 | 207.64 | 151.87 | 592.85 |
| 同上，加 10 万行单列 CSV | 94.32 | 295.57 | 201.25 | 147.46 | 590.35 |

首次核验 P95 分别为 84.44 / 336.92 / 333.11 毫秒；三次调用序列 P95 为
216.77 / 615.04 / 608.11 毫秒。序列首次调用会修改一个合成文件以强制缓存失效，
包含这次极小文件写入成本；不等同于实际提交 hook 全链路的新增时延。

流程图首次核验中位数分别为 56.88 / 82.46 / 82.05 毫秒，对应原检查为
26.05 / 28.95 / 29.28 毫秒。新增模型调用为 **0**；缓存仍需扫描内容指纹，不是零成本。
