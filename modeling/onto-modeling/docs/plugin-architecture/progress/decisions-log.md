## 2026-11-03 · F4a（连接器网关第一版：文档转换、资料的文本版、「数据接入」）

按第一性原理推导，写成 ADR-0073（目标、约束、推导、最强反对理由、待定项）。推导结论与 brief 的倾向一致，下面是 brief 没定、由推导定的点：

1. **网关用单独的镜像**（同一个 Dockerfile 的 `connector-gateway` 目标），不照搬 sandbox-gateway 的「和主服务同镜像」：解析库装进主镜像，助手在主容器里临时写脚本解析不可信文件的老路就又通了，解析库被利用时拿到的也是有工作区和密钥目录的容器。代价：离线包多一个镜像（实测 347 MB，共用基础层）。
2. **票据用 Ed25519**（内核私钥签、网关从内核 `GET /api/v1/connector/issuer-key` 取公钥），不用 HMAC：共享密钥要放进网关，等于网关存了凭据；被利用的网关也伪造不了票据。票据字段沿用 `gateway_client.Ticket`，`scope` 是原文件 sha256，另带 `converter`、`filename`；jti 在网关内存里防重放。
3. **转换器接口单独一个 `DocumentConverter`**，不做成 `kind=file` 的 `EvidenceProvider`：后者是「连接—测试—发现—采快照」的在线系统接口，套进去全是假的 conn/test 和记录拼回文档。共用的是包类别（provider，界面叫数据接入）、网关子进程运行、票据、健康检查。
4. **一个转换器 = 一个数据接入包**（清单 `converter` 段 + `converter.py`），放 `assets/packs/convert-*`；网关镜像拷进自己的只读目录加载，内核镜像里的同一份只用来展示（内核从不导入）。ID、版本、类型、许可证只写一次。
5. **文本版放 `resource/text/<分组>/<原文件名>.md`**：在资料区（对助手只读、随版本走），又不是资料分组（列表、资料地图、500 份上限都不用另加过滤）；第一行 `<!-- onto:text source=… sha256=… converter=…@… -->` 记原文件修订，状态以文件为准。没选「原文件旁边放 .md」（各处列表要过滤）、「隐藏目录」（glob 默认跳过点目录）。
6. **位置标记用 HTML 注释**（`<!-- 第 3 页 -->`、`<!-- 工作表：客户 -->`）：助手读得到，渲染时不显示（界面画成分隔条）；网关回的位置对照只用来核对，不另存（以文件里的标记为准）。Word 没有页，不加标记，用标题分节。
7. **状态记录放 `DATA_DIR/conversions/<项目>.json`**，不进工作区：转换中、等待这类状态写进 git 只会刷提交；对不上文件时按文件重判、缺文本版就排队（导入、恢复版本后自愈）。
8. **哪些算文本**：md、markdown、txt、csv 是 native；drawio 没有文本版（流程图另有工具）；HTML、图片、doc、xls 没有转换器 →「暂不支持」（HTML 在列表上也标暂不支持：资料分析只读 md 后它确实不参与）。暂不支持的也能「重新转换」（以后装了 OCR 一类转换器时用）。
9. **PDF 的预览就是文本版**（没有原样预览；资料分析读到哪的标记照旧），Word、Excel 多一个「文本」页签；列表行只标没转好或转不了的四种状态，「已转成文本」不标（RULES 口径：不加次要标签）。
10. **换默认的界面**只在同一种文件有两个以上转换器时出现在转换器详情页（现在每种只有一个，所以界面上看不到；单测和 mock 覆盖）。
11. **测试部署部署**：仓库 compose 里网关设 `pull_policy: build`、不写 `container_name`，远端 deploy.sh 不用改就会随整栈按源码构建、容器名跟着项目名（onto-plugin-connector-gateway-1）。远端脚本没改（测试部署只读）。
12. **ADR 编号用 0073**：0072 留给并行的 F3。
13. **校准**（测试部署上两份 PDF，只读、内容没出测试部署的管道）：一份 68 页有文字层、34 页带插图、21 页有表，转换 0.9 秒、约 100 MB 内存；另一份 1 页整页图片 → 判「扫描件或图片型 PDF，暂不支持」。据此定：一页少于 20 个字且图片占半页以上算图片页；有文字但图片占 10% 以上的页在说明里列出「图片里的文字没有转」。
