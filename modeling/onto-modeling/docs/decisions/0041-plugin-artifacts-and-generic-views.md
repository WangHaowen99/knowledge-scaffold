# 0041 插件产物：包登记格式、内核解析与索引，前端只认通用接口

## Context

方案 C13、详设 5.9.4、5.9.5，契约 3.17 AR-01～AR-09、MCP `artifact.list` / `artifact.get`。场景、示例数据、
流程图、脚本扫描报告、求解契约这些东西不是本体实体（对象、操作、规则、指标、动作），却要在插件页、Studio、
对话卡片里列表、看详情、编辑、标过期。P2 的验收：新登记一类产物后，不改前端就能列表、看详情。约束：
内核不跑包的代码；插件产物不建关系边、不进知识包。

## Decision

1. **包登记、内核解析**（`kernel/artifacts/registry.py`、`parsers.py`）：包在清单里登记产物类型——类型名带包前缀、
   路径（只能在 `ext/<包名>/` 下；官方包已有产物沿用原目录，见 `LEGACY_DIRS`）、格式、键、字段定义（带版本号）、
   分段、引用字段、状态映射、视图（列表列、筛选、详情布局、卡片）。格式只有内核内置的八种：`md-frontmatter`、
   `yaml`、`json`、`jsonl`、`csv`、`drawio`、`md-report`、`md-sections`；`derive`（stem、h1、表格行数、标题、
   `field:`、`match:`）与 `defaults` 补内置解析算不出的简单字段。
2. **解析不了的字段由包脚本生成标准索引**：登记 `index`（jsonl），一行一个键、带源文件哈希；内核按键并进行里，
   哈希对不上标「待刷新」。场景走查包的 `trace_index.py` 就是这样把推演结论写进 `ext/trace/index/`。
3. **按项目建索引**（`index.py`）：工作区 `.onto/run/artifacts.sqlite`（不进 git，坏了重建），文件签名没变不重新解析；
   FTS5 全文（没编译 FTS5 时退回 LIKE）。**过期**：产物某个内容版本第一次被看到时记下它引用的本体条目指纹，
   条目之后变了或没了而产物没变就标过期，产物重新生成或保存后基线重置。
4. **读写走通用接口**（`service.py`、`routers/artifacts.py`）：AR-01～AR-09；保存经写入事务（`Onto-Source: web`），
   先按字段定义校验（jsonschema），再过包声明的门禁；有专用接口的类型（求解契约、知识条目、扫描报告）登记为只读，
   返回 `artifact_readonly`。历史与趋势读主线 git。MCP 两个只读工具结果有上限（列表 50 行一页、分段 4000 字、
   表格 20 行、流程图只给节点与连线摘要）。
5. **流程图**（`flowchart.py`）：`diagram.flowchart` 的 drawio 与流程图模型互转、校验由内核做（压缩存储只读、
   明文时按 id 保留业务说明与关联条目），图示包只登记类型与视图。
6. **不是本体实体**：不解析维基链接、不建关系边、不进发布包；引用本体条目只认登记的 `refs` 字段。
7. **提交之后**：`service.after_commit(manager, project_id, paths)` 给出这次提交改到的产物（项目流 `workspace.changed`
   的 `artifacts`），并发 `artifacts.updated`（updated，以及过期状态翻转的 stale / fresh）；会话宿主每轮结束调用。

## Alternatives considered

- **包自带解析脚本由内核调用**：违反「内核不跑包的代码」；改成包脚本在 agent 侧生成标准索引，内核只读结果。
- **产物进本体（当成第六种实体）**：会进知识包、建关系边，发布口径和下游契约都要变；产物只是建模过程的工件。
- **每次请求全量解析不建索引**：场景几百个时列表、全文搜索、过期判断都要逐文件读，插件页会慢。

## Consequences

- 新的产物类型只要包登记，前端用通用列表、详情、卡片就能显示（测试用一个测试专用的包验证）。
- 过期判断依赖进程能看到的条目指纹，agent 改了条目、还没人读列表时，stale 事件要等 `after_commit` 被调用才发——
  会话宿主（B4a）合并时要在每轮结束调用它。
- 写入范围锁（`register_lock_provider`）由变更集一侧（B4b）登记，之前产物都不显示锁定。

## 合并后的衔接（2026-11-02）

见 ADR-0045。`after_commit` 登记成项目流的产物映射，挂在全部主线提交上（网页、agent、插件），不只是每轮结束；
AR-05/06/07 自己发 created / updated / deleted，提交时标出这些路径，`after_commit` 不再为它们补发 updated。
`artifacts.updated` 经 `kernel/event_port` 发到项目流。

## 审查修复（2026-11-02）

见 ADR-0045「审查修复」：流程图保存改为在原文件上只改内核认得的单元格（泳道、批注、其他页保留）；md-sections
保存只改登记了的列表项，新建文件的一级标题按登记的 `heading` 写；官方包身份只认入库来源（镜像内置），旧目录别名
只给它们；读文件前确认解析后仍在项目根目录内；保存、新建、删除的校验与写入在同一把项目锁里。
