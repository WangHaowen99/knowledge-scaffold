# 0097 会话层判定执行超时，子任务卡随一轮收尾

## Context

**目标**：一轮已经结束、被取消或者引擎不再响应时，用户不该看到一直转圈的「运行中」和子任务卡，也不用找运维，发一条消息就能接着做。

**现状（吸收 develop !568 时核对）**

- 内测引擎（Jiuwen）已经去掉框架一轮 600 秒的上限，引擎里还有一道挂起兜底：一轮里 `ONTO_WEB_JIUWEN_STALL_SECONDS`（默认 900 秒）
  没有动静就停掉 agent、按出错收尾。这道兜底在 worker 子进程里跑，worker 本身卡死时管不到。
- 稳定引擎（Claude）没有任何无响应判定；CLI 以退出码 0 退出时消息流正常结束，会话停在原状态，下一条消息才报错。
- Jiuwen SDK 把模型调用失败、执行上限都收成一条 `answer`，流照常结束。原先这条被忽略，这一轮记成成功。
- 前端子任务卡按「会话现在是否在跑」判中断：一轮结束时显示已中断，下一轮一开始，上一轮没收尾的卡又转起圈来。

**基本约束**

1. 等用户的时间不是引擎无响应：确认卡、问题有自己的超时（`ONTO_WEB_PERMISSION_TIMEOUT`）；建模命令开始前等资料转文本最多 600 秒。
2. 排队、连接引擎的时间不算这一轮。
3. 子代理「思考中」是引擎按时补发的节拍（稳定引擎每 15 秒一次），只说明还在等模型；按它算活动的话，网关挂住时永远判不出来。
4. 判定之后要和引擎异常结束走同一条收尾：执行记为中断并放续跑卡，出错卡带错误编号和重试，追加的插话退回输入框，
   排着的命令暂停，副本里已有的修改照样合入。
5. 模型调用失败重试期间同样没有事件，Jiuwen 单次调用最长 300 秒，实测连续重试可超过 25 分钟。

## Decision

- **会话层判定执行超时**（两个引擎共用）：`state=running`、没有待确认、不在等资料，连续 `ONTO_WEB_SESSION_STALL_TIMEOUT`
  （默认 1800 秒，0 或负数关闭，和 develop 一样不设上下限）没有引擎事件，就不等应答直接硬终止引擎，按 `_turn_failed` 收尾（约束 4），
  `session_error` 带 `reason: "stall_timeout"`。巡检和空闲回收共用一个后台任务。
  - 计时从交给引擎、接上引擎、确认卡答复的那一刻重新起算（约束 1、2）。
  - 子代理「思考中」节拍不刷新活动时间（约束 3）；不转发的运行时消息（状态、任务进度）由引擎产出内部事件 `_activity`，算活动。
  - 默认 30 分钟（约束 5），比 Jiuwen 引擎内兜底的 900 秒长：引擎内兜底先管模型请求挂住，会话层兜 worker 卡死和稳定引擎。
- **稳定引擎**：消息流正常结束时发 `_engine_end`（`reason: exited`）。这一轮还在跑按出错收尾；空闲时同空闲回收（ADR-0089），
  停着等下一句的执行不动，不出续跑卡。
- **内测引擎**：`answer` 里 `error` 有值（不是 aborted）按出错收尾；`result_type=error` 而没有 `error` 是步数、外层轮数用完或连续没有进展，
  照常收轮，在回复末尾提示可以发「继续」，并留档。硬终止前先 `abort()`（最多等 2 秒），否则 SDK 的 task loop 还会接着动工作区。
- **追加的消息**：和 develop 一样，出错或超时收尾时在提示里注明「本轮进行中追加的 N 条消息可能没有处理」。本分支插话有送达状态（EC-10），
  这些消息同时退回输入框（`returned`），提示按这个事实写「已放回输入框，请重新发送」。
- **子任务卡**：前端状态层在一轮收尾（`session.state` 变成 idle、error、closed，或 `session.error`、`session.interrupted`）时，
  给还没终态的子任务记下结束方式：`session.error` 的 `reason` 是 `stall_timeout` 记「执行超时」，其余记「已中断」。之后到的终态仍以终态为准。
  记在条目上，下一轮开始也不会再转圈；历史回放走同一个归约，升级前留下的卡同样恢复。

## Alternatives considered

- **只靠 Jiuwen 引擎内的兜底**：管不到稳定引擎和 worker 卡死。
- **会话层也把「思考中」算活动**：稳定引擎子代理等模型时节拍不断，网关挂住永远判不出超时，正是要解决的情形。
- **子任务卡按「卡片之后的事件」现算（develop 的 `endedByStall`）**：本分支时间线是归约后的条目，没有原始事件序列；在归约时记下结束方式更直接。

## Consequences

- 真正沉默超过 30 分钟的工作（一个不出任何输出的工具跑了半小时）会被终止；可以调大或设 0 关闭。
- `session.error` 多一个可选字段 `reason`（契约 EC-04）。
- 运维留档多两类：`stall_timeout`（会话层判定）、`round_limit`（Jiuwen 触顶，便于判断要不要调大最大迭代数）。
