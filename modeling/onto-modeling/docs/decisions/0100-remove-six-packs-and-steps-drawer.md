# 0100 去掉六个官方能力包与工作台「建模步骤」抽屉

## Context

**目标**：用户 11-17 定，下面这些对用户来说太复杂，彻底去掉（不是隐藏）：反馈演进（evo）、知识沉淀（knowledge）、迁移复用（migrate）、
系统逆向建模（rev）、联网调研（websearch）、增量构建（incremental）六个官方能力包，以及工作台顶栏的「建模步骤」抽屉。成功标准：

- 界面上不再出现这些入口，留下的页面不留空白占位；
- 已部署的环境升级后，插件中心、项目的包锁、待处理里都不留这些包的残骸，项目照常装配、照常对话；
- 留下的功能行为不变；只为这些包写的内核代码、接口、测试一起删掉。

**基本约束**

1. 已部署的包仓库里装着这些包，项目锁文件里启用着。只删镜像里的资产，老环境的插件中心还会列出它们，启用过的项目装配时找不到资产。
2. 工作区里的数据是用户的：`feedback/*.json`、`incremental/` 下的范围与核对文件、证据快照。不迁移，也不删。
3. 文档转换（ADR-0073、convert-* 包）和系统逆向建模共用连接器网关，文档转换要留。
4. 增量构建用到的两个内核机制还有别的用处：范围限定（`confine`，ADR-0085）领域包扩展在用；事件激活（`activation`，ADR-0091）
   接下来要给内核的增量更新用（新资料到了才出现、才推荐）。
5. 评测入口、完成通知、报告查看还要用，评测优化（把评测结果交给反馈演进）随反馈演进一起去掉。
6. 新资料到了以后改已有本体，原来有两种做法：内核的增量更新（`core.update`，一条命令）和增量构建包（圈定范围 → 范围内修改 → 传播核对）。
   同一件事只留一种做法，用户定留内核的增量更新。

## Decision

**推导**

- 只隐藏（不默认启用、插件中心不列）达不到目标：这些包的代码、测试、内核里的分支都还要维护，复杂度没有减少。所以删资产，
  连同只为它们服务的代码一起删。
- 老环境的残骸（约束 1）要在启动时自动清掉，否则只能手工逐个下架。规则写成通用的，不点名包：全部版本都由镜像入库、没有 owner、
  不是 core、这次镜像的 `assets/packs` 里没有它，就在通道记录上记 `retired`。下架的包目录、详情、缺省启用、跟随通道、插件运维都
  看不到，启用返回 `pack_not_found`；`runtime.normalize` 把它从项目锁文件里去掉，作为一次系统提交，项目照常装配。
- 用户数据不动（约束 2）。版本目录也不删，下架只是一条通道记录，换回旧镜像就能恢复。
- 内核机制按「还有没有别的使用者」逐个判断（约束 3、4、5），见下面「保留」一节。
- 抽屉去掉以后，进度条只展示，不能再点开。抽屉里的节点按钮由「全部命令」菜单和建议条承担（节点模型重构另记）。
  「跳过 / 恢复」可选步骤（FL-03、FL-04）暂时没有界面入口，后端接口保留；脚本节点运行（FL-05）仍可从建议条和发布页的「去运行」发起。

**删除**

| 包 / 功能 | 一起删掉的 |
|---|---|
| 系统逆向建模 rev | 证据采集（数据源、凭据、采集任务、快照、证据浏览器、ER 视图、EV-01～EV-28、EV-30～EV-34）、连接型提供方、REA 旁路容器、管理员申请审核 AD-08～AD-10、流程里的 `external` 节点和 `evidence_sources` / `evidence_snapshot` 条件 |
| 反馈演进 evo | 外部反馈收件箱、评测优化与回写（ES-07、ES-08、ES-12）、R-11/R-12、待处理的 `send_to_evolution` 动作和外部反馈条目 |
| 知识沉淀 knowledge | K-03～K-08（新增、修改、删除、冲突检查、提名）、知识信号提示规则、EP-23、知识沉淀页 |
| 联网调研 websearch | 资料分析的联网模式（`research_mode`、`web_available` 等字段与文案） |
| 迁移复用 migrate | 只有包资产 |
| 增量构建 incremental | 包资产和只测包本身的测试；借它测内核机制的测试改用合成包 |
| 建模步骤抽屉 | 顶栏按钮、抽屉、只给抽屉用的分组、节点动作、脚本运行摘要、跳过/恢复的前端封装 |

**保留**

- 文档转换：网关的转换、`convert-*` 包、健康探测。
- 资料锚点解析 EV-29：挪到 `routers/anchors.py`，只解析 `file:` 锚点。
- 知识：K-01 列表、K-02 详情（只读）；知识条目的存放、加载和行业层留在 core。
- 评测：入口、完成通知、报告查看。
- 内核增量更新：`core.update`、`/ontology-update`、增量更新页、变更清单。
- 内核机制：范围限定 `confine`（领域包扩展在用）、事件激活 `activation`（接下来给增量更新用）、一次装配只允许一个包限定范围。
- 格式迁移的 `migrate` 待处理动作（和迁移复用包无关）。

## Alternatives considered

- **只隐藏不删**：复杂度没有减少，见推导第一条。
- **只删资产、不做下架**：老环境插件中心照样列出，启用过的项目装配时缺资产（约束 1）。
- **留增量构建、删内核增量更新**：增量构建要先启用包，再走三步，用户每次都得先圈定范围；内核增量更新不用启用任何包，就能处理同一件事。
  代价是失去范围限定这层保护，见下。

## Consequences

- 用户失去的能力：联网资料分析；按外部反馈自动演进；在网页上新增、修改、提名知识条目；数据库、代码仓库、REA 采集与证据浏览；
  迁移复用；增量构建的范围限定（增量更新时，助手可以改到这一轮没打算改的条目，靠校验兜底）。
- 抽屉去掉后，「跳过 / 恢复」暂时没有界面入口。节点模型重构里，建议条会推「没做也没跳过的可选节点」，
  所以要同时给出不想做时的去处，否则推荐会一直挂着。
- 老环境升级：第一次启动时下架，并把这些包从项目锁文件去掉（一次系统提交）；工作区里这些包留下的文件不清理。
  从带证据采集的版本升级时，要手工清理的卷、密钥文件与环境变量见 README。
- 回滚：换回带这些包的镜像，入库时取消下架；已经从锁文件去掉的条目不加回来，要用的项目重新启用。
- 随之作废或部分作废的决策：ADR-0056、0082、0086（证据与连接器，文档转换部分除外）；ADR-0085（增量构建包；`confine` 机制保留）；
  ADR-0091（增量构建的触发；`activation` 机制保留）；ADR-0092（评测优化成批反馈那部分）。各自末尾已加补充。
