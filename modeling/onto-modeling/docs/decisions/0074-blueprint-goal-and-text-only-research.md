# 0074 蓝图目标只存一份、资料分析只读文本、编号不问人

## Context

用户手测中暴露了资料分析的三处问题：

1. 建项目时必填的一句话建模目标，助手根本看不到；蓝图上的「要解决的问题」是助手从资料里另写的一份。测试项目里
   目标和资料讲的是两件事，谁也没发现。
2. 资料是 PDF，资料分析临时写脚本抽文字，核验又对不上 PDF 出处，返工十几分钟；F4a（ADR-0073）已经把 PDF、
   Word、Excel 转成文本版，但资料分析还在读原件。
3. 资料里没有编号时，助手自编的 27 个业务项编号、8 个规则编号被核验脚本标成「新增ID确认，需人工确认，
   不得自行勾选」，助手只好去问用户「是否沿用这些编号」，没人答就等到超时。

用户 2026-11-03 定：蓝图「要解决的问题」参考建项目时的建模目标，「不在范围」不需要，目标和资料对不上就提问；
资料分析只读 Markdown，转换交给数据接入；编号这类内部机制的问题不再问人。

## Decision

按第一性原理推导：

- **目标**：蓝图确认的那一刻，用户只判断业务上的事——要解决什么、怎么分段、叫法统一成什么；资料分析读得快、
  出处准；用户不被内部机制打扰。
- **约束**：
  - 目标是用户写的，必须有唯一的权威来源，否则会出现两份对不上的目标；
  - 助手能改工作区文件，目标不能放在助手能改的地方；
  - 解析外来文件有风险（ADR-0073），主容器里不该再解析原件；
  - 资料可能没有编号，编号又是对象提取、ID 稳定性核对的基础；
  - 自主构建在运行开始前会代答助手的提问（F2），业务取舍不能被代答掉。
- **推导与方案**：
  1. 要解决的问题 = 项目信息里的 `goal`，蓝图不另存（旧文件的 `goal_md` 只作兼容）。BP-01、蓝图卡按项目目标显示；
     宿主在每次注入阶段提示时附上「建模目标」一行，从主线工作区的项目信息读，助手的副本里没有这份文件，改不了。
  2. 目标和资料对不上时，助手在蓝图草稿的 `questions` 里写一个目标问题（`kind: goal`，可带 `suggested_goal`），
     选项固定为「改成：…」「保持原目标」。蓝图问题不走 AskUserQuestion，所以运行前的策略代答碰不到它；没答之前
     BP-03 回 409 `blueprint_question_pending`；选了改写才改项目目标（目标仍只有一份）。
  3. 「不在范围」取消：草稿不收、写回不带、界面不显示。哪份资料读不了，资料区的文本版状态已经说明。
  4. 资料分析只读文本：`source_extract.py --sources` 列出每份资料要读的文本（md、txt、csv 读原文件，其余读
     `resource/text/<分组>/<原文件名>.md`），命令行遇到原件不解析、指向文本版；没有文本版的记为未读。出处指向
     文本版加行号；核验按文本版核对，有文本版的原件不再解析；旧报告指向原件的锚点照常核对，只提示改指文本版。
  5. 编号：资料里有编号就引用并核对来源；没有就自编 `ITEM-01`、`RULE-01`，核验在资料里查不到这个编号就算自编、
     直接通过。去掉「新增ID确认」。前后两轮不悄悄变化的检查保留（有基线时新编号要在「ID变更对照」登记）。
  6. 交互约定写明只问业务问题（含义、范围、冲突、取舍）；编号、文件名、目录、格式、读哪些资料、用什么工具、
     接下来做什么一律自己定。资料分析命令里问「还有没有别的文档」「领域名称」「已有报告怎么办」「修正还是人工确认」
     的几处都改成按参数和项目状态自己定。

## Alternatives considered

- **蓝图里保留一份目标，和项目目标同步**：两份就会漂移，同步本身也要写；不如只读一份。
- **目标问题用 AskUserQuestion 问**：自主构建运行前会被策略代答，正好丢掉最该由人定的事。
- **自编编号也必须人工确认，但改成一次性批量确认**：仍然是在问内部机制；编号错了的代价由 ID 稳定性检查兜住。
- **最强的反对理由：自编编号放开后，助手可能把「编造的资料编号」写成 ITEM-xx 蒙混过去。** 处理：ITEM-xx 只在
  资料里查不到时算自编；资料里出现过的编号必须指对出处（否则报错）；编号本身不携带业务含义，编错的后果是对象
  提取多一条或少一条，由覆盖检查和用户在 Studio 复核发现，代价可控。

## Consequences

- 契约：BP-01/BP-02/BP-03、蓝图卡、`Blueprint` 类型、错误码 `blueprint_question_pending`（`docs/api-v1.md`）。
- 详设第 9 章建议 2、建议 5 与附录 E 已改；ADR-0050 顶部加了修订说明。
- 旧报告里勾过的「新增ID确认」只是缺口清单里的已勾选条目，不再有特殊含义。
- 主服务镜像里仍能 import pdfplumber、python-docx：它们是内测引擎库（openjiuwen）的依赖，引擎自带的读文件工具
  遇到 PDF 会在进程内解析。资料分析的说明已不让助手这样读，但没有硬拦；是否在引擎的文件工具上拦截原件，另行决定。
