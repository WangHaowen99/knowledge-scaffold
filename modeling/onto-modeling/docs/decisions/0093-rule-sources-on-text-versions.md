# 0093 规则的原始资料出处在文本版里定位；条目表的最后更新时间进 ST-03

## Context

develop（!589）给规则加了「原始资料来源」节，并在工作台上点出处打开原件、定位高亮：Word 段落与表格单元格、Excel 单元格与合并区、
文本行号；PDF、图片在平台内打开，其他格式给下载。分段预览接口 `GET /source-preview` 在主服务里直接调 `source_extract` 解析 Word、
读 Excel 原件。同一批还给 Studio 表视图加了「最后更新时间」列，接口 `GET /studio/updates`，只在表视图请求。

本分支的事实：

- ADR-0076：主容器里不解析资料原件，平台和助手都只读多源连接器转出的文本版（`resource/text/<分组>/<原文件名>.md`）。
- ADR-0074：资料分析只读文本版，报告的「来源位置」「详细信息」写文本版的行号（`#L40`、`#L40-L46`），规则的「原始资料来源」照抄。
- Studio 表视图就是 ST-03 条目表；ST-03 契约里已有 `sort=updated`，但行里没有时间，后端也没实现。
- 资料区的「查看原文」（ST-06 证据卡）按 `?anchor=` 跳资料区，文本版锚点在资料列表里找不到对应项，跳过去什么都不选。

**目标**：看规则的人点出处，看到资料里被引用的那几行（高亮、带页或工作表），能回到条目；条目表能按「最后真改过」的时间排序。

**约束**

1. 不解析原件（ADR-0076），只用文本版和网关已有的转换输出。
2. 出处是资料分析写下的文本版行号，定位必须和核验（`research_checker`）、证据解析（EV-29）、选出处（R-15）同一套行号。
3. 最后更新时间要遍历版本历史，代价不能落到每次请求上；git 不可用时不能让条目表出错。
4. 外部调用路径不变；develop 的 `/studio/updates`、`/source-preview` 在本分支没有调用方。

## Decision

**推导**

- 出处写的就是文本版的行，在文本版里定位是同一精度的事：R-06 本来就能读 `resource/` 下的文本文件并按 `around` 开窗。补三处：
  `around` 认行号范围（按第一行定位）；文本版的文件头不出块；页、工作表标记不单独成块，记在后面每一块的 `location` 上。
  不另开 `/source-preview`：两者都是「锚点附近一窗带锚点的段」，R-06 已是它。
- 资料区收到 `resource/text/…` 的锚点时选中原资料，片段照旧；要转文本的资料（PDF、Word、Excel）上的行号片段在预览里按文本版定位
  （表格行合成表，紧跟分隔行的是表头；位置变化处出分隔线）。md、txt、csv 的行号照旧在原文件上定位，也认范围。
- 条目编辑器的章节是文本框，章节里写的 `resource/` 出处在文本框下面列成芯片（EV-29 给出「资料名 · 位置」），点开去资料区；
  图谱侧栏的证据卡本来就列这些出处，没有对应属性时写位置。返回靠浏览器后退（hash 路由，每次跳转入历史）。
- 最后更新时间：本分支条目表就是 ST-03，时间直接放进行里（`updated_at`），`sort=updated` 新的在前、取不到的排最后。遍历历史的
  结果按（工作区、HEAD、文档集合）缓存，每次请求只多一条 `git status`；git 出错时整列为 null。口径同 develop：提交时间，未提交的取
  文件修改时间，纯改名（`-M100%`）不算更新，Studio 草稿不算。
- 工具箱：`source_extract` 移植 develop 的稳定快照与 Office 解压上限（抽取器版本 2），`located_text` 认行号范围——报告说明里本来就让写
  `#L40-L46`，核验原先却按单个锚点找，范围一律判「无法核验」。

**最强的反对理由**：Word 表格到单元格、Excel 到单元格与合并区、PDF 原样版面，这些 develop 能做到的，文本版做不到：文本版一行是一个
段落或一整行表格；Excel 文本版去掉了空行和合并信息，回不到原单元格坐标。处理：出处本身就是行号（助手只读文本版，写不出单元格），
高亮一整行和出处精度一致；能做到原件版面要么在主容器解析（违反 ADR-0076），要么扩网关输出（转换器写原行号映射、页面坐标），
后者改动转换协议和三个转换器，记进差距，等确有需要再做。

## Alternatives considered

- **照搬 `/source-preview`，网关里解析原件、主容器只收结果**：等于给网关加一个按需抽取接口，原件预览的结构（段号、单元格）还是
  要专门的格式，而出处是文本版行号，对不上原件结构。
- **最后更新时间单开 `/studio/updates`（同 develop）**：多一次请求、前端按路径合并；本分支 ST-03 只在表格页和选范围时用，缓存后代价
  是一条 `git status`，放进行里更直接，`sort=updated` 也有了实现。
- **按 TextPane 的 Markdown 渲染定位行**：`/text` 去掉了文件头并截断到 30 万字，行号对不齐，大文件后半段定位不到。

## Consequences

- R-06 的块多一个可选字段 `location`（只在读文本版时出现），`around` 多认行号范围；ST-03 行多 `updated_at`，`sort=updated` 生效。
- 规则多一节「原始资料来源」（元模型、模板、提取说明），存量规则不自动补，重新提取后带上；`research_checker` 核对「详细信息」出处。
- 精度差距与未做的界面（报告小节定位、原件版面）记在 `progress/gaps.md`「2026-11-11 · P5b」。
