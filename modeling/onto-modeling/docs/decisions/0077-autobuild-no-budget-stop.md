# 0077 自主构建不按预算判停

## Context

ADR-0062 给自主构建设了时长、token、费用三项预算：80% 提醒，100% 停在最近的安全点，结束态 `budget_exhausted`。
2026-11-03 的运行 #1 在第 1 段就因 token 预算用完停下（100 万 token 上限，18 分钟用了 155 万，缓存读也计入），6 段只
做了 1 段，运行条一直挂在运行对话顶上。用户 2026-11-04 定：自主构建只在做完、叫停、出错时结束，预算这套设置整套拿掉；
结束后点「确认」回到陪伴建模。

约束：

- 一次运行本身有界：段数有限，每一步最多说 3 次「继续」、出错重试 2 次，修复轮数有上限；
- 花费的硬上限已有配额（ADR-0043：用户当日、项目当月 token），每一步发送都过这道检查；
- 设置项必须起作用，不起作用的上限留在界面上会让人以为还能卡住运行。

## Decision

1. **结束条件**：做完、停在安全点、转为陪伴、出错。`_ending` 只看用户的停止与转为陪伴；删除 EP-16 与 80% 提醒。
2. **用量只记不拦**：`budget.py` 只保留累加 token、费用、墙钟时长；运行条、报告照常显示用量，不再有上限与百分比。
3. **配额用完暂停**：发一步撞上配额，运行进 `paused`，`pause_reason: quota`，不记失败原因；补足后 AB-09 续跑，
   从这一步接着做。
4. **拿掉预算设置**：策略（AB-01/02/03）没有 `budget`，老请求带了忽略；SY-17 没有单次时长、token、费用上限；
   项目卡、运维总览不再有预算百分比与「因预算停止」；错误码 `budget_exceeds_quota` 删除。
5. **结束后确认**：新增 AB-19，记下 `acknowledged_at`；项目没有别的进行中运行时把构建方式改回 L2，并发 EP-20。
   运行对话里已确认的结束运行不显示运行条。
6. `budget_exhausted` 留作老运行记录的状态，之后不再产生。

## Alternatives considered

- **保留设置、到上限只提醒**：设置项不再卡住任何东西，留着只会误导；提醒也没有可采取的动作。
- **到上限暂停等确认**：运行仍会被预算打断，和「只在做完、叫停、出错时结束」的要求冲突，用户需要隔一段就回来点续跑。
- **配额用完也按结束处理**：会丢掉剩下的段；暂停后补足配额就能接着做。

## Consequences

- 管理员不能再给单次运行设花费上限，一次运行最多花到用户当日或项目当月配额为止；配额是唯一的花费闸门。
- 运行耗时只能看运行条上的已用时与预计用时，没有到点自动停。
- 老的策略文件、平台限制文件里的预算字段不再读；平台限制下次保存时清掉。
