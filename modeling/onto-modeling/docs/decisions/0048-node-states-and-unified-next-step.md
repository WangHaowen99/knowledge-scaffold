# 0048 节点状态由内核算，三个出口用同一份「下一步」

## Context

P1 的 `GET /flow` 只按完成判定（目录里有没有文件）与命令锁粗算四种状态，文件一落盘进度就打勾；下一步建议只按
主线给。详设 6.6 要求 8 种状态由内核按执行记录、变更集、产物指纹算（方案 D13），6.10 要求界面按钮、助手回复末尾
的文字、两轮之间的阶段提示用同一份「下一步」（方案 D15、D16）：`state_helper` 命令行接口不变、新增 `suggest`，
数据走文件（flow.yaml + 后端写的 flow-state.json），不调 HTTP。

## Decision

1. **节点状态（`services/flow/state.py`）**：
   - 进行中：有没结束的执行记录（运行中、等你回答）；不经网页宿主跑的命令留下的命令锁也算（主线工作区与助手副本都看）；
   - 待确认：节点的改动在没确认的变更集里（变更集记着执行过的节点）；有变更集时再按助手副本的完成判定补一遍
     （副本里满足、主线上没有的节点也算待确认，见第 3 条的共用规则）；
   - 已确认 / 过期：完成判定在主线上满足；记下的输入指纹（`stale_on` 声明的类别在主线上的树摘要）变了就是过期。
     第一次看到已满足的节点（存量项目）直接记基线；变更集确认生效后，变更集里执行过的节点按主线现状重记基线；
     主线上不再满足（回退、删了产物）时去掉记录；
   - 已跳过：可选节点被跳过（FL-03，必经节点不能跳过）；被挡住：`blocks` 指向它的关卡没确认；
   - 可开始 / 未就绪：锚点链上的上游（跳过没做的可选节点）已确认或过期就可开始。
   - 需复核：节点升级后完成判定签名变了（`upgrade`）、导入已发布的知识包带进来的（`import`）、自主构建自动合入的片
     （`autobuild`，P3 调 `mark_needs_review`）；专家接受后去掉。`display_state`：已确认 + 需复核显示 `needs_review`，
     自主构建的显示 `auto`。
   - 依据存在数据目录 `flow-state/<项目>.json`（不进 git，删除项目时一起删）。
   - 进度（x/N）只数主线上满足完成判定的节点（已确认与过期都算做过）：助手副本里的改动要确认生效才算。
   - core 与官方包补了 `stale_on`：对象 ← 资料分析；操作 ← 对象；规则与指标 ← 对象、操作；质量检查 ← 四类条目；
     示例数据 ← 对象；场景验证 ← 对象、操作；代码生成 ← 操作；流程图 ← 资料分析。
2. **下一步算法放在 core 的 `flow_state.py`**（`suggest`、`overlay_pending`，标准库）：后端经契约库按项目锁定版本
   调用（旧版本没有时用镜像版本），`state_helper.py suggest` 在工作区里直接调。优先级按详设 6.10：自主构建在跑给
   运行控制；刚被打断给「从打断处继续 / 继续 / 换个方向」；有没确认的变更集时主推「确认生效」、次选下一步与
   「撤回这一轮」（`mode=pending_confirm`）；有等你回答的问题时主推禁用「先做上面的决定」；其余按 过期刷新（2）→
   报告待处理、关卡没过（3）→ 主线第一个没做完的必经步骤（4）→ 都做完时整体视图与可选步骤（5）。1 个主推、最多 2 个次选。
3. **三个出口同一份**：
   - 后端每算一次流程（FL-01/FL-02、一轮开始前、一轮结束、项目流重算）就把节点状态、变更集、阶段写进助手副本
     的 `.onto/run/flow-state.json`（没有副本时写主线工作区）；
   - `state_helper.py suggest` 读它，叠上这份副本里自那以后还没确认的改动（`overlay_pending`：副本里满足完成判定的
     节点记待确认；文件里还在跑、命令锁已释放的节点算做完），用同一个 `suggest` 输出 JSON；
   - 宿主注入登记的提供方就是在助手工作目录里跑一次 `state_helper.py suggest`（装配目录里哈希核对过的那份），
     两个引擎（Jiuwen worker 进程也登记一份）拿到的与界面建议条一致；
   - 有没确认的变更集时，后端的下一步按助手副本的阶段与完成判定算（同一份 `overlay_pending`），所以一轮结束后
     三处结果相同（测试按此核对）。
   - `check-prereq`、`detect-stage`、`acquire`、`release` 输出不变（命令模板按旧字面量分支）。
4. **FL-03～FL-05**：跳过、恢复只对可选节点（`node_not_skippable`、`node_not_skipped`）；开始节点用节点声明的
   入口命令（没有时取第一个动作）调 S-20（同一个 `dispatch_command`），`slice_id` 作为参数带上。

## Alternatives considered

- **state_helper 调后端 HTTP 问下一步**：方案 D15 明确不调 HTTP（agent 进程拿不到登录态，也不该能调后端接口）。
- **后端和 state_helper 各写一份算法**：P1 的教训就是两套推荐各算各的。放进 core 的 `flow_state.py`，后端经契约库
  加载同一版本。
- **过期不计进度**：项目列表上的 x/N 会因为你在 Studio 里加了个对象就倒退；过期的节点是「做过、需要刷新」，在流程
  与待处理里单独提示。

## Consequences

- 助手执行命令期间主线不变，流程进度、项目列表的进度在确认生效后才前进；界面上这一步显示「待确认」。
- `stale_on` 让上游一变就提示刷新：在 Studio 里改对象后，操作提取、质量检查会显示过期（建议条第 2 优先级）。
- 每次算流程多写一个小文件；宿主注入多起一次 `state_helper` 子进程（15 秒超时，跑不起来这一条不带下一步）。
- 按切片的状态（`slices`、`slice_stages`、`per_slice` 节点）要等切片规划（建模蓝图），现在为空（见 gaps）。

## 补充（B4d）

主流程按详设 6.8 重排，建模节点按切片算状态（`slices`、`slice_stages`、`per_slice`），下一步认蓝图与这一片的下一步，
见 ADR-0050、0051。
