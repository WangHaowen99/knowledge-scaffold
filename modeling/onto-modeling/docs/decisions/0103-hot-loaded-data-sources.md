# 0103 数据源热加载：连接器插件 + 数据源资料

## Context

**目标**：建模要用业务系统里的结构和数据（表、列、外键、约束、码值）。现在只能人工导 Excel，对象间关系靠列名猜。
用户 11-19 要求：内核搭好框架，以后接一种新的数据源，只需要上传一个多源连接器插件，需要的话再加能力包，不改内核、不重建镜像、不重启。

- 给谁用：
  - 建模者：在资料页接入一个数据源，像上传资料一样；
  - 管理员：在插件中心信任连接器插件；
  - 连接器开发者：写一个插件就能接一种新系统；
  - 助手：读法和现在读 Excel 一样。
- 怎样算成功：
  1. 新增一种数据源 = 上传一个连接器插件，管理员点「信任」，下一个任务就能用；网关、主服务都不重启；
  2. 建模者接入数据库后，资料区多一份数据源资料。表登记、出处、发布时的表列绑定、版本、新资料触发增量更新都照常工作，
     外键直接给到对象抽取；
  3. 凭据不进主容器；写语句到不了业务库；样本里的个人信息默认遮蔽；
  4. 比 ADR-0101 删掉的证据采集简单：没有快照、证据浏览器、申请审核这些概念。

**基本约束**

1. 凭据泄露波及整个业务系统。助手和后端在同一个容器里，理论上能读到后端进程的东西（详设 5.8.9）。
2. 连接器代码拿着凭据、连着业务网络运行，必须被凭据的主人信任。
3. 采集打到生产库：只读、限速、限时。
4. 样本进工作区 git，助手读得到：个人信息要遮蔽。
5. 用户 11-17 嫌证据采集太复杂删掉了（ADR-0101），新做法不能把那套概念搬回来。
6. 离线部署：插件要能自带依赖，不能现装。
7. 资料流水线（文本版、表登记、锚点、版本、增量更新、发布绑定）已经跑通，是助手唯一的读法（ADR-0074、0076、0096）。

用户 11-19 定的四项：信任方式是插件中心点「信任」；采集结果当作一份资料；项目成员自助接入；第一批交付 MySQL 和 PostgreSQL。

## Decision

**推导**

1. **结果落在哪：资料区**（约束 5、7）。数据源本身是一份资料，即 `resource/excel/<名称>.datasource`，里面只有连接配置和凭据引用，没有凭据。
   它的文本版就是采集结果，格式和 Excel 文本版相同：一张表一个工作表，首行是列名，下面是遮蔽后的样本行。文本版后面
   附「库表事实」，包括列的类型和注释、主键、外键、唯一约束、检查约束、码值。这样表登记、Sheet 范围、出处锚点、发布
   绑定、版本恢复、新资料触发增量更新全部复用，不需要快照、证据浏览器和 evidence.py。重新采集就是「重新转换」。
2. **代码在哪跑：连接器网关的子进程**（约束 1、3）。沿用转换器的超时、内存上限和杀进程组。网关加接业务出口网络，
   子进程装审计钩子，只放行这个数据源登记的主机和端口。钩子是纵深防御，不是沙箱。
3. **怎样热加载**（约束 2、6）：
   - 网关有自己的插件卷。管理员信任某个版本后，内核把这个版本的包打成 tar 交给网关（票据绑定包的 sha256），
     网关校验清单和 checksums 后解压进卷，刷新自己的插件清单。下一个任务子进程按新清单导入，不用重启。
   - 随网关镜像交付的官方插件（`assets/packs/convert-*`、`db-*`）在只读目录里，始终可用。
   - 插件可以带 `vendor/` 目录（纯 Python 依赖），子进程把它放进 `sys.path` 最前面。
   - 网关卷丢了的话，内核每次刷新插件清单（30 秒缓存）发现缺了已信任的版本，就重新交付。
   - 转换器同样按这个办法加载，ADR-0073 的待定项「第三方转换器怎么安装」一起解决。
4. **连接器接口**：清单顶层的 `source` 段，和 `converter` 并列。段里声明：
   - `fields`：连接表单。界面按它生成，插件不带前端代码；`secret` 类字段只进网关的凭据库；
   - 出口：取 `host`、`port` 两类字段的值；
   - 入口函数：`test(ctx)`、`collect(ctx)`。

   插件只经 `ctx` 往外发表、事实、检查结果、进度和局限。遮蔽、限量、渲染成文本版都在网关主进程里做，插件绕不过。
5. **凭据**：
   - 网关凭据库按 `<项目>/<引用>` 存，AES-256-GCM 加密。主密钥用 `ONTO_CONNECTOR_MASTER_KEY_FILE`；没配时网关在凭据卷里自己生成。
   - 内核只存引用，没有读出明文的接口。密码只在接入、修改、测试这一次请求里经过内核。
   - 票据写明项目，网关只取这个项目下的凭据：导入别的项目、复制来的数据源资料用不了原项目的凭据，要重新填密码。
6. **能力包的位置**：库表事实的通用读法放进 core 工具箱。`table_profile --headers` 带上外键，对象抽取用它写「关联对象」的
   关联字段。能力包只管某一类数据源的特殊用法，用内核条件 `data_sources`（项目里有数据源资料）控制提示规则和节点出不出现。
7. **谁能做什么**：
   - 项目成员能接入、修改、测试、重新采集本项目的数据源；
   - 只有管理员能信任或撤销连接器插件；
   - 只读靠三层：连接器在测试连接时自检账号权限，账号能写就拒绝采集；采集只开只读会话；语句过词法白名单。

**做法**

- 网关：
  - 插件仓库：只读的内置目录加可写的卷；
  - 接口 `PUT/DELETE /v1/plugins/{名}/{版本}`、`PUT/DELETE /v1/secrets/{项目}/{引用}`、`POST /v1/sources/test`、`POST /v1/sources/collect`；
  - `/v1/providers` 多出 `sources` 和 `plugins`；
  - 连接器子进程与 SDK（`app/connector_gateway/source/`）；遮蔽 `mask-v1`；把表和事实渲染成文本版。
- 内核：
  - 插件信任 PL-22、PL-23；网关插件对账；
  - 数据源接口 DS-01～DS-04（连接器列表、接入、修改、测试）；
  - 资料转换认 `.datasource`：采集代替转换，「重新转换」就是重新采集；
  - 表格后缀加 `.datasource`；
  - 条件 `data_sources`。
- 工具箱：`table_sources` 认 `.datasource` 的文本版；`table_profile --headers` 输出 `foreign_keys`；对象抽取守则用它写关联字段。
- 插件：`db-mysql`、`db-postgres`（驱动 PyMySQL、pg8000 装进网关镜像）。
- 界面：
  - 资料页「接入数据源」：选连接器、按字段填表单、测试、保存；
  - 数据源资料有「重新采集」「修改连接」；
  - 插件中心多源连接器卡片上有「信任」「撤销信任」。
- 部署：网关加 `connector-plugins`、`connector-secrets` 两个卷和 `biz-egress` 网络。

接口与格式细节见 `docs/plugin-architecture/design/data-sources.md`。

## Alternatives considered

- **网关验签（官方由平台签，租户插件由管理员用自己的密钥离线签，验签公钥只配在网关）**：最强的一种。助手就算拿到内核的
  签名私钥，也放不进代码。用户 11-19 选了更简单的「插件中心点信任」，代价见下。
- **只热加载官方签名的插件**：最安全，但第三方扩展还是要重建镜像，达不到目标。
- **恢复独立的证据快照**（快照、证据浏览器、ER、`db:` 锚点）：功能全，但就是 ADR-0101 删掉的复杂度（约束 5）。
- **连接器每个跑一个容器（像 Airbyte）**：隔离最彻底，但网关要拿 Docker 套接字，权限比凭据还大；插件也不能再是一个 zip。
- **声明式连接器（不带代码，只写查询模板）**：安全，但新协议要新驱动，还是要改镜像。

## Consequences

- **信任方式的代价**：「信任」这一步发生在主容器里。能读到内核签名私钥的人（理论上包括被提示注入控制的助手，约束 1）
  能伪造安装票据，把代码放进拿着凭据的网关，这推翻了 ADR-0073 的约束 3。缓解措施：
  - 只有管理员能点信任；
  - 信任按版本记，网关只装 sha256 对得上的那一份；
  - 每个任务只拿到自己数据源的凭据；
  - 子进程只能连登记的主机。

  以后要收紧，就改成网关验签（上面第一个备选），插件格式不用变。
- 部署：网关多两个卷、一个网络；镜像多 PyMySQL、pg8000（纯 Python，约 1 MB）。主密钥自动生成在凭据卷里时，
  卷整个被拿走就能解密，要分开存主密钥的部署配 `ONTO_CONNECTOR_MASTER_KEY_FILE`。
- 数据源资料没有快照对比和 ER 视图；版本历史就是采集历史，表之间的关系看「库表事实」。
- 部分恢复 ADR-0086 的做法（只读三层、遮蔽 `mask-v1`、审计钩子），产出改成资料文本版。ADR-0073「第三方转换器怎么安装」
  的待定项由本决策关闭。
