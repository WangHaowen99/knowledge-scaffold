# 0010 求解契约按 Profile 模板生成：业务用户只填表单，附属文件由后端生成

## Context

求解契约目录 `ontology/solver/<solver_key>/` 下除 binding 外有五份附属文件（model.yaml、
输入/结果/事实快照三份 JSON Schema、presentation.yaml）。0009 之前，面板要求用户逐份按原文编辑，
其中 Profile 锁定的目标序、选项域、事实名等只要写错一处就会在保存或发布时被拦截。
只懂业务的建模人员既看不懂这些文件，也无从判断该怎么改；而对当前唯一的 Profile
（二选一有序路线，选项域固定为 `OPTION_0` / `OPTION_1`），五份文件里真正需要业务输入的只有
两个选项的显示名称、结果标题和（多个评估器时）评估器路径。

验证用例同样只能在 JSON 编辑器里按输入 Schema 手写；求解服务按批次号字典序排序的已知缺陷
（`B10` 排在 `B2` 之前）也只能靠用户自己避开。

## Decision

- **模板参数**：`{display_mapping: {OPTION_0, OPTION_1}, title, evaluator_path}`，后端
  `normalize_template_params` 去空白后由 `render_template` 确定性生成五份附属文件。
  - 保存与即时检查的条目可提交 `{binding, template}`（忽略 sidecars，按模板生成）或
    `{binding, sidecars}`（按原文写入）；未知参数、非文本值、超长或含控制字符的标题、
    越出包目录的评估器路径直接拒收。
  - 显示名称为空、重名、超长只作为语义问题给出（field `display_mapping`），与手动编辑同口径。
- **managed 判定不落标记**：读取时从已保存文件还原参数（`extract_template_params`），重新生成后
  与磁盘五份文件逐字节一致即 `managed: true`。视图用 `template_params` 回传参数，与提交用的
  `template` 键区分，原样回传视图不会触发重新生成。磁盘上不新增任何元数据文件，导出包不变。
- **面板**：
  - 模板契约只显示「选项显示名称 / 结果标题 / 评估器」表单，solver_key（中文 Operation 自动取
    `route_choice_N`）、Decision Model、问题族等收进默认折叠的「高级设置」，有问题时自动展开；
  - 附属文件页签只读预览即时检查返回的 `rendered`，参数未改动时直接用已保存的文件；
  - 「转为手动编辑」以当前生成结果为起点按原文编辑，「按模板重新生成」回到表单（覆盖手动修改）。
  - 视图给出 `evaluator_options`（包内可选评估器）与每条契约的 `unit_options`
    （从评估器常量字典静态解析，不执行脚本）。
- **验证用例表单**：模板契约的用例按「计划月份 / 装置 / 批次表格」填写，行序即加工顺序并
  自动重排 `item_order`；新批次号自动补零（B01、B02…），字典序与加工顺序不一致时提示。
  编辑器文本仍是唯一来源，表单改动写回文本，复杂或手动契约的用例可展开「以 JSON 编辑」。
  前端按后端 `normalize_cases` 的上限预检（条数、id、名称长度、单条与合计大小、预期候选数）。
- **中栏吸顶**：中栏页签栏与求解面板的状态/操作栏在滚动正文时固定，页签栏实际高度经
  CSS 变量 `--center-bar-height` 传给二级吸顶元素（求解状态栏、文档目录）。

## Alternatives considered

- **在 binding 或单独文件里记录 managed 标记**：需要新文件或新字段并进入导出包，手工改动附属
  文件后标记会与内容不一致；逐字节比对没有这个问题。
- **在前端生成附属文件**：前后端两套生成逻辑会漂移，与 0009「不在前端复写规则」冲突。
- **用表单编辑五份文件的全部字段**：Profile 锁定的内容本不该让业务用户改，表单只会更复杂。
- **在模型侧修正批次排序缺陷**：缺陷在求解服务一侧，不在本仓库修；这里只通过默认补零编号与提示规避。

## Consequences

- 业务用户新增契约只需选 Operation、填两个显示名称，保存即得到能通过 Profile 检查的契约。
- 新增 Profile 时须同时提供模板参数、`render_template` 与还原逻辑；当前实现只覆盖二选一有序路线。
- 后端模板输出一旦变化（格式或内容），已保存的契约读取时不再逐字节一致，会显示为「手动编辑」，
  需要用户「按模板重新生成」后保存；修改模板时应在说明中提示。
- 用例表单的字段口径跟随求解服务的输入 Schema；Schema 变化时需同步 `BATCH_FIELDS` 与提示规则。
