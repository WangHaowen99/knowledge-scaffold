# 0079 普通用户装自己的插件包（F9）

## Context

用户 2026-11-05 要求「普通用户也可以安装插件」。

现状：把目录里的包启用到项目，项目所有者已经能做。「安装插件」入口走的是上传离线包（PL-13～PL-18），只有管理员能用，发布后全平台可见。

**目标**：建模者不找管理员，也能把自己写的提示词、命令、子代理、行业知识做成包，用到自己的项目里。成功标准：上传、检查、安装、启用都能自己做完，别人的项目不受任何影响。

**基本约束**

1. 输入不可信。上传者是普通账号，包内容、清单、压缩包大小都可能是恶意构造的。
2. 执行边界。助手的 Shell 在主容器里以非 root 的 `onto-agent` 身份运行：凭据环境变量被筛掉，密钥目录读不到，但所有项目的工作区都归这个身份可写，项目之间的隔离靠 PreToolUse 守卫。装配目录就是工作区的 `.claude`：包脚本（`.claude/scripts`）由助手直接运行，守卫只看命令文本，看不到脚本里做什么；hooks 在守卫之外执行；`settings.local.json` 这样的文件放进去就生效；Claude CLI 展开命令时会执行内联 shell、读取 `@` 引用的文件。所以带可执行内容的包能绕过守卫，读写别人的工作区。
3. 波及范围。包仓库是全平台一份：`default_on` 的能力包自动进新项目，配置项、指标、告警按全部包登记，往已有包名下装版本会影响所有跟随通道的项目。
4. 现有功能不能破坏：管理员的上传审核发布流程、已有接口都不变。

## Decision

**推导**

- 由约束 2：普通用户的包，权限不能超过他在对话框里直接输入。提示词和资料满足这条，脚本、hooks、界面不满足。
- 由约束 1：黑名单挡不住没想到的路径（放进 `.claude` 的文件都可能生效），所以按白名单放行。
- 由约束 3：普通用户的包不能进全局。默认不可见，要看的地方显式取，漏改的地方也是安全的一侧。

**做法**

1. 新增 `/api/v1/me/pack-uploads`（PL-22～PL-26），登录即可。管理员接口不动。
2. 上传的包静态检查多一项白名单（`private_scope`）：
   - kind 只能是 capability、knowledge；
   - contributes 只能是命令、子代理、skill、模板、参考、规则片段、提示词、文档和行业知识数据；
   - 文件只能在这些目录下，后缀只能是 `.md .txt .yaml .yml .json .csv`；
   - 命令、子代理、skill 的开头 YAML 只能写 `name description argument-hint tools`；
   - 不能写内联 shell 和 `@` 文件引用；
   - 不能写 `required`、`split_from_core`。
3. 包名全局唯一，先到先得。公开的包名、别人的私有包名都不能用。安装时先占名再入库，入库过程中包不会公开。
4. `PackRepository.names()` 默认不含私有包。缺省能力、配置注册、指标告警、转换器这些遍历都碰不到；目录按看的人取 `private_names`；插件运维显式带 `private=True`，管理员能禁用。
5. 别人的私有包在 PL-01、PL-02、PL-03、PL-06、新建向导里按不存在处理。已经锁在项目里的照常能用，项目转给别人后不会坏。
6. 资源上限：zip ≤20 MiB，解压后 ≤64 MiB、≤2000 个文件（按实际解压字节算，压缩包头里的大小不可信），每人保留最近 20 个上传，最多 50 个版本。
7. 管理员能看到所有人的上传，可以把私有包发布出去，发布后变成公开的包。

## Alternatives considered

- **放开现有上传接口，普通用户也能发布**：一个账号能影响全平台，还能往 core 的包名下装版本。
- **普通用户上传、管理员审核后才能用**：安全，但做不到「不找管理员」，等于没解决。
- **带脚本的包在沙箱里跑**：脚本要走 sandbox-gateway，要改工作区脚本的调用方式，包里的脚本现在都假定能读写工作区。范围大得多，这次不做。
- **按用户加命名空间（改写包名）**：清单、校验和、命令前缀都要改写，工作区里的命令名也跟着变。

## Consequences

- 普通用户能自己装提示词和知识类的包，别人的项目不受影响。
- **代价**：带脚本、hooks、流程节点、页面的包普通用户装不了，还要找管理员发布。平台现有官方包大多带脚本，这类能力这次开放不了。
- 包名先到先得，普通用户能占住一个名字。公开的包名不受影响，管理员发布同名包时会收到 `pack_name_taken`，要先协调。
- 私有包不能自助删除，版本到 50 个要找管理员。
- 新增的 `kind`、`contributes`、Claude CLI 新的生效路径默认都被白名单挡在外面。CLI 升级后如果多出新的开头 YAML 键，也进不来。

**最强的反对理由**：提示词本身也能指使助手做事，白名单挡不住「请读别的项目」这种话。这条成立，但用户在对话框里也能这么说，读写仍然走守卫，包没有带来额外权限。如果要防提示词层面的越权，要在守卫和沙箱上做，和这次无关。
