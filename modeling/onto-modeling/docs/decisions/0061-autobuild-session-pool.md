# 0061 自主构建与会话池：运行中不驱逐、确认卡由策略作答、运行中别处发消息 409、同时运行数上限

## Context

方案 B13：Session 加 `run_id`，运行中不驱逐、不回收；确认卡由策略立即作答并记台账；运行中用户发消息返回 409；限制
同时运行的自主构建数。契约里有两处说法要合在一起：2.10 `autobuild_running`「有运行在跑（运行中发消息、改引擎、再启动等）」，
3.22「运行中用户发的消息按 deferred 处理，下一步开始前读取」（l4-run 页的「补充说明，不打断运行」）。

## Decision

1. **会话池**（`agent_sessions`）：`Session.run_id`；会话池按项目记正在跑的运行（`set_run`），新建的 Session 自动带上。
   带 `run_id` 的会话不算可驱逐、可回收；停机、引擎退出、出错、回收时不放续跑卡（运行器按执行记录续跑）；一轮收尾不出
   「这一轮改了什么」卡和插件产物卡。会话池给每个项目一个信号（状态变了、一轮收尾完置位）与「一轮收尾中」标记，运行器
   按条件等，不轮询固定次数。
2. **策略作答**（`decide.respond`，经 `register_policy_responder` 登记）：运行中的决策卡（AskUserQuestion）不等人：
   - 置信度从问题的 header（「置信度 0.85」）读，没写按 0.5；依据从文字里的出处锚点读；推荐项、保守项看 label 里的
     「（推荐）」「（保守）」——这些写法由注入告诉助手；
   - 达到阈值取推荐项（没有就取第一个）；低于阈值按策略取保守项并记为假设，或挂起；`must_suspend_kinds` 里写到的
     类型、没有选项可选的问题一律挂起；挂起时给助手的答案以「挂起」开头，助手跳过这一项接着做；
   - 每个决定记一条台账（问题、选择、选项、置信度、阈值、是否假设、出处、影响条目、这一段这一步），挂起记一个挂起的
     问题；分段进展块随之更新；不在对话里出决策卡（自动决定嵌在分段进展块里）。
   - 工具确认卡（权限模式不是全放行时才有）放行，对话里留一张「由策略放行」的已处理确认卡（EC-31 `by=autobuild_policy`）；
     硬性不做的事由守卫与写入路径挡。
3. **注入**（`hint`，`injection.register_autobuild_hint_provider`）：运行器每发一步前写 `autobuild/<项目>/current.json`
   （这一次运行的对话、注入文本），宿主注入时读：运行与段（第几段）、作答约定、段说明（`blueprint.py brief` 同一份）、
   最近 20 条自动决定、用户补充。放在文件里而不是内存，因为 Jiuwen 在独立 worker 里算注入；只给运行对话注入
   （Injector 带上对话 ID）。
4. **运行中的消息与操作**：
   - 运行对话里发消息（S-07）：记成用户消息（`delivery=deferred`），不交给引擎，下一步开始前作为「用户补充」注入；
   - 别的对话发消息、发命令（S-07、S-14、S-16、S-20，以及经 S-20 的 FL-05、BP-03 `next=L2`、RP-05/06）、改引擎（P-12）、
     回退版本（V-06）、删项目（P-06）、打断与重启运行对话（S-08、S-09）、删运行对话（S-04）、手动确认或撤回这一段的
     变更集（CS-04、CS-05）都回 `409 autobuild_running`（`details.run_id`）。暂停、中断的运行也算没结束：它的变更集还开着。
   - 建议条（FL-02、对话里的 EC-53）：在跑时换成运行控制（`mode=autobuild_controls`，core 的 `flow_state.suggest` 已有）；
     暂停、中断时只留「运行详情」；结束后主推「去复核」。
   - 写入范围锁：自主构建这一段的变更集没生效之前是 `autobuild_slice`（`run_id`、这一段），到这一段自动生效为止。
5. **同时运行数**：配置项 `ONTO_WEB_AUTOBUILD_MAX_RUNS`（配置注册表，默认 2，1～16；系统设置 SY-17 保存的值优先），
   只算在跑与正在去安全点的；超出的排队（AB-03 `queued`、`queue_position`，AB-04 返回 `queued`），前一个结束、暂停后按
   先来后到开始。**不允许 0**（主控 2026-11-02 定）：SY-17 收到 0（或负数）回 `422 invalid_argument`
   （`fields.max_concurrent_runs=min`、`min: 1`）；环境变量写 0 时配置注册表报配置错误（启动日志告警、SY-14 的问题清单），
   回落到下一个来源或默认值；万一读到 0 也按 1。维护模式期间不开新运行；进入维护时在跑的做完这一段就暂停（O-21
   `autobuild=pause_at_safe_point`），退出维护后排队的接着开始，暂停的等用户续跑。

## Alternatives considered

- **运行对话里的消息也 409**：l4-run 的输入框就是「补充说明」，契约 3.22、S-07 都写了 deferred；409 只给别的对话。
- **补充说明直接交给引擎（会话层原来的 deferred）**：引擎会在这一步里就看到，还会多出一轮，运行器的一步一轮就乱了；
  改为下一步开始前注入。
- **策略作答时照样出决策卡再自动回答**：对话里会多一排已回答的卡，和分段进展块里的自动决定重复。
- **改 core 的 `flow_state.suggest` 加暂停态**：要改包的脚本、升版本；暂停态的建议条在后端替换。

## Consequences

- 自主构建跑着时，这个项目的其他对话不能用；用户要先暂停后停在安全点或转为陪伴。
- 置信度、出处靠助手按注入的约定写；没写时按低于阈值处理（保守或挂起），宁可多复核。
- 运行器、会话池的「正在跑的运行」都在进程内；多进程部署要换共享存储。

## 审查修复（2026-11-02）

- **会话池统一拦发送**：`SessionManager.send` 在有运行没结束时回 `409 autobuild_running`，只放行运行器自己发的步骤
  （meta 带 `autobuild_run`）；Studio「转助手复核」、取消排队、放弃执行等内部入口不再绕过。
- **运行会话不算用户的并发会话**：运行器发步骤时不查并发会话配额，配额统计也不数带 `run_id` 的会话；同时运行数由
  SY-17 管。原来这种情况会被当成预算用完结束运行。
- **作答**：置信度只认「置信度 / confidence」后面的一个数，右边不能紧跟数字、小数点、`/`、`%`（`12%`、`1/3` 不再读成
  1.0）；百分数除以 100，0～1 之外按没写；推荐、保守只认 label 结尾的「（推荐）」「（保守）」。删除类工具确认
  （`rm`、`git rm`、`find -delete`……）与打 `release/*` 标签一律拒绝，不再放行。
- **发布标签**：守卫对 `git tag|push|update-ref` 涉及 `release/*`、`push --tags` 一律拒绝，陪伴模式同样；`settings.base.json`
  的 deny 加上对应规则。
