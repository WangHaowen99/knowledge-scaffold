# 0052 写入范围收窄到当前切片

## Context

详设 4.3：助手的修改确认之前，写入范围内的条目在所有编辑器里只读；范围是「当前执行节点声明的 `produces`，落到当前
切片包含的条目上，再加上这一轮已经改过的条目，以及等用户决定的决策卡在改动预览里列出的条目」；节点不按切片执行时，
范围是 `produces` 声明的整类条目；助手写不出这个范围（守卫拦）。B4b（ADR-0047）在切片规划之前按整类条目锁，助手执行
对象提取时所有对象都只读（主控定为过渡，decisions-log「主控定：B4b 留下的三个问题」）。

## Decision

1. **用户一侧（ScopeLock，`kernel/changesets/service.scope_lock`）**：按切片的节点（建模）在按片模式下不再用节点声明的
   整类模式，而是这几片包含的条目路径（`blueprint.member_paths`，操作含旧目录，转义成字面量）与条目（`entries`）：
   - 助手在跑：执行记录的切片；
   - 这一轮结束、修改待确认：变更集 `slice_steps` 里做过的那几片；
   - 加上这一轮改过的路径与条目、决策卡预览列出的条目（不变）；
   - `slice` 给 `{id, name}`，`reason_text`「助手正在改「X」这一片，确认生效或撤回之前这些内容只读」；
   - 全量模式（没有蓝图、只有一片）或不知道在哪一片时仍按节点声明的整类条目（宁宽勿漏）。蓝图取界面上看到的那份
     （没确认的变更集改过就取副本里的）。
2. **助手一侧（守卫）**：`state_helper acquire` 在按片模式下（宿主写的 `.onto/run/exec.json` 有切片、命令属于按切片的节点）
   给 `.onto/run/active.json` 的这条命令另记 `slice` 与 `protect`：节点范围目录里已经有了、不属于这一片、这一轮也没改过的
   条目。内核守卫 `scope` 把 `protect` 里的路径当越界拒绝，提示「别的片已有的条目只读，只能链接引用」；新建条目照常。
3. 别的片已有的条目需要改时，命令文档要求助手在回复里列出来由用户决定（`SLICE_MODE.md`），不要绕过。

## Alternatives considered

- **守卫只放行这一片的条目**：抽取时会发现规划里没有的新条目，全拦住就建不出来；新条目在主线上不存在，用户也改不到它。
- **只收窄用户一侧、守卫仍按整类**：用户改片外条目时助手也可能改到，合入时才以冲突出现，违背「人和助手不会改到同一个条目」。
- **protect 由守卫每次现算**：守卫要读蓝图、跑 git，拖慢每一次工具调用；acquire 时算一次就够（这一轮新建的不在里面）。

## Consequences

- 建模时只有这一片的条目只读，别的片照常在 Studio 里改；确认生效后解锁。
- 操作提取想给别的片的对象补关联会被拦下，只能在回复里提出；决策卡预览扩出片外时，守卫这一侧还不放行（引擎侧的决策卡
  还不带改动预览，gaps B4b 第 11 条），见 gaps B4d。
- 片外的指标（`writes` 里的 `ontology/metric/*`）已有的也在 protect 里；新建照常。
