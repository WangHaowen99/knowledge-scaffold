# 0081 插件开发 Skill：按分类下载，后端现打包

## Context

**目标**：开发者在插件中心下载一个按分类的 skill zip，放进编码助手（Claude Code、Codex 等），一句需求做出合协议的插件 zip。
成功标准：助手只读 skill，不读这个仓库；zip 第一次上传就过静态检查，能安装，能启用到项目。

**基本约束**

1. 助手手里只有这个 zip，协议、样例和检查手段都要在里面。
2. 协议常量和静态检查随平台版本变。skill 和后端不同源，就会说一套、查一套。
3. 开发者的机器只能假定有 Python 3 和 PyYAML，也可能连不上平台；skill 里的代码在别人机器上跑，结果不可信。
4. 私有包只归本人可见（ADR-0079），别人的私有包名不能发出去。
5. 普通用户上传已有明确的检查和上限（ADR-0080）：`checks.run(tenant=True)` 加 `private_name`，zip ≤20 MiB，解压后 ≤64 MiB，≤2000 个文件。
6. 转换器打进连接器网关镜像才运行（ADR-0073），数据接入包导入后不生效。

## Decision

**推导**

- 约束 2 排除手写的协议文档：协议和平台快照下载时由后端现生成，检查器用后端的同一份代码。
- 约束 1、3 要求离线也能查：检查器文件原样进 zip，相对导入靠保持包层级；只有两个懒加载的模块（`flow.state`、`onto_mcp.definitions`）拖着半个后端，
  而离线只用其中的常量，所以下载时生成只含常量的文件。服务器上的检查代码一行不改。
- 约束 3 决定离线结果只能帮开发者少走弯路，准入还是服务器复查。
- 约束 4 决定快照只取 `repository.names()`（公开包）。于是「包名有没有被别人的私有包占用」「这个版本装过没有」「依赖的是不是自己的私有包」离线判不了，
  列成「上传时检查」，不算通过。
- 不同分类要读的东西差很多，助手上下文有限，所以按分类下载。同一个分类里节点包是能力包的特例，放在能力包的 skill 里。
- 约束 6 决定数据接入包的 `SKILL.md` 要求助手最后如实告诉开发者这一点。

**做法**

1. `GET /api/v1/packs/dev-skills/{category}`（PL-27）：`services/packs/dev_skill.py` 在内存里打包，登录即可，可用 `?token=`（下载链接带不了头）。
2. zip 内容：`SKILL.md`、`references/protocol.md`（后端生成）、`references/<分类>.md`、`references/examples/`（合成样例）、`platform.json`（平台快照）、
   `scripts/pack_tool.py`、`scripts/checker/`。
3. `pack_tool.py`：`init` 从样例改名建骨架，`check` 写校验和并检查，`build` 检查通过后打 zip，zip 根就是包。
4. 静态部分放 `assets/pack-dev-skill/`：随 `COPY assets` 进镜像，不在 `assets/packs/` 下，不会被当成包导入。
5. 插件中心只在 `capability`、`industry`、`system`、`provider` 四个分类视图的页头放一个按钮。放页头是因为系统知识包现在一个包都没有，分类的段落不显示。

## Alternatives considered

- **仓库里放一份静态 skill**：最简单，但协议常量、平台已有的包名都会过期，开发者要到上传才发现，违反约束 2。
- **所有分类一个 skill**：只有一个下载入口，但助手每次要读完四类说明，分类规则也更容易串。
- **skill 调平台的在线检查接口，不带检查器**：不用发代码，也不会有离线差异。但助手要拿令牌，开发环境要能连平台，违反约束 3，开发者的令牌也不该交给助手。
- **`pip` 发一个开发工具包**：要多维护一个发布渠道和版本对应关系，平台内网部署时还装不上。

## Consequences

- 开发者不用读仓库就能做包；静态检查的问题在本地修完，不用反复上传。
- **代价（最强的反对理由）**：所有登录用户都能拿到检查器源码，照着规则就能写出刚好绕过检查的包。这个取舍成立，是因为静态检查本来就不是安全边界：
  服务器照样复查，规则不靠保密，而 ADR-0080 已经接受用户脚本在守卫之外运行。检查器发出去没有让攻击面变大，但也不能指望它挡住恶意的包。
- 检查器的几个文件不能新增对后端其他模块的依赖，否则离线会失败；`test_dev_skill.py` 有覆盖。
- 离线和服务器的结论有已知差异：上面三项上传时检查，以及 Python 版本不同时的语法结果。这些差异由测试逐项列出。
- 每次下载都读一遍公开包的清单。实测 12 个公开包时 40～120 毫秒，第一次下载要导入基础建模能力，约 700 毫秒。公开包到 500 个上限时要读的清单多得多，这个量级没有实测；下载不频繁，打包放在线程里不挡事件循环，先不做缓存。
- 数据接入包能做能装但不运行，开发者要找平台管理员打进网关镜像才算完。
