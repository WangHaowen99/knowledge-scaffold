# 0049 待处理汇总不另存状态，变更点清单从副本里的影响分析收进来

## Context

详设 4.7 把等用户处理的事项集中到「待处理」：工作台图标的角标就是它的计数，「处理完一项，对应的来源随之改变，
计数自动减少」；契约 3.13 定了 13 类事项、筛选、处理动作与等价接口，B4c 给左栏插件页角标留了
`registry.register_badge_provider`。增量更新的变更点清单（契约 3.14）要能找到所在对话（F3 补充），
`/ontology-update {change_list_id, fix_scenarios}` 要有清单可读（gaps B4c 第 5 条）。

## Decision

1. **待处理按来源现算（`services/flow/inbox.py`）**，不另存事项：决策（在线会话里没回答的决策卡）、续跑（中断、
   能续跑的执行记录）、修改待确认 / 合入冲突（当前变更集）、过期 / 需复核（节点状态）、报告待处理（`reports/` 里
   还有 `- [ ]` 的报告，一份一项）、格式待迁移（插件产物的 `format_version` 比登记的旧）、外部反馈（`feedback/`
   下的批次）、变更清单（没执行的清单）。证据冲突、挂起随证据源与自主构建（P3）。事项 ID 是 `<kind>:<来源 ID>`，
   与契约里决策卡的 `inbox_item_id`（`decision:<question_id>`）、合入冲突（`changeset_conflict:<cs>`）同一套。
2. **只自存两样**：忽略记录与当天处理过的记录，放主线工作区 `.onto/run/`（不进 git）。忽略后不计数；「今天的进度」
   = 今天处理过的 + 还剩的。
3. **处理一项转给等价接口**（IN-03）：决策 → S-11，续跑 / 放弃 → S-16 / S-17，确认生效 / 撤回 → CS-04 / CS-05，
   合入冲突 → CS-07，刷新与重做 → FL-05，需复核的接受 → 去掉标记，报告 → 以校验命令调 S-20，外部反馈 → 以反馈演进
   命令调 S-20（没启用反馈演进包时 `pack_not_enabled`），变更清单 → INC-03 / INC-02 / INC-04。格式迁移要包提供
   迁移命令，现在的包都没有，回 `pack_not_enabled`。批量（IN-04）：刷新过期一次只跑最上游的那一个（同一项目同一时刻
   一条命令），其余列在 `skipped`；接受高置信自动决定在 P3。
4. **推送与角标**：每次重算流程（`project_events.refresh_flow`，变更集、执行、工作区变化之后都会调；决策卡出现、
   回答之后也调）顺带重算待处理，和上次比有增减、内容变了才发 `inbox.updated`（`added`、`removed`、`changed`）。
   插件页角标 = 待处理里归这个包的事项数（过期 / 需复核的节点属于提供它的包，格式迁移属于登记产物的包，外部反馈
   属于反馈演进包）。
5. **变更点清单（`services/flow/change_lists.py`）**：`/ontology-update` 第 2 步把影响分析写进副本的
   `.ontology-state/update-plan.json`；一轮结束时宿主把它收成一份清单，存数据目录 `change-lists/<项目>/`，记下所在
   对话与变更集，「这一轮改了什么」卡带上 `change_list_id`。变更点的把握按改动类型给（修改高、新建中、删除低）。
   清单在执行前可以编辑（不受写入范围锁约束，决定 #40）；执行（INC-04）把清单写进副本的
   `.onto/run/change-lists/<清单>.json`，往对话发 `/ontology-update change_list_id=<清单>`，命令文档补了按清单执行
   （跳过影响分析与确认）与 `fix_scenarios=[…]`（只修这些场景的回归失败）两种入口。影响面（INC-05）按变更点指到的
   条目给；回归场景要等场景走查包的索引（见 gaps）。

## Alternatives considered

- **待处理存一张表、各来源往里写**：每个来源的状态变化都要同步这张表，漏一处计数就错；现算只多几次读文件。
- **变更清单由助手调后端接口登记**：助手拿不到登录态，也不该能调后端；文件交换与 `state_helper suggest` 同一个做法。
- **清单进 git**：清单是建模过程的中间物（确认后落到条目上），进 git 会让版本列表多出与本体无关的提交。

## Consequences

- 待处理每次请求都现算（含一次流程计算、扫描 `reports/` 与 `feedback/`），大项目会慢一些；项目流只在变化时推。
- 决策卡只在会话在线时出现：服务重启后没回答的决策卡按 B4a 的规则失效，待处理里也随之消失。
- 变更点清单的「条件 / 取值 / 出处锚点」按助手现有的影响分析格式映射（条件取理由、取值取变更说明，锚点为空）；
  按契约的变更点格式产出要改 `/ontology-update` 的影响分析代理（见 gaps）。

## 补充（B5c 合并，2026-11-02）

- 决策多一个来源：人工节点（ADR-0066）没回答的决策卡，回答后消失。
- 所属包版本被熔断（O-29）的节点不列过期与需复核：流程里它算跳过、开始不了，IN-04 也就不会选中它。
