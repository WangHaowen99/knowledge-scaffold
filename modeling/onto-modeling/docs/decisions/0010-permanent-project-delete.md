# 0010 项目删除改为永久删除

> 后续变更：旧版数据评测与远端 Modeling 项目关联已删除，删除项目不再取消评测轮次，也不再级联删除远端项目；下文相关步骤仅作历史参考。

## Context

删除原为软删除：工作区整体移入 `DATA_DIR/trash/`，保留 git 历史，可在运维中心回收站恢复。
需求是删除建模任务立即生效、不论任务当前状态，删除后数据不再保留。原实现与此有三处不符：

- **删不掉**：会话运行或排队、数据评测进行中时接口返回 409（`PROJECT_BUSY`），要用户先等
  任务结束；关闭会话要先排会话池的锁、再等 CLI 优雅断开，CLI 悬死时删除请求跟着等。
- **删不净**：回收站里留着完整工作区、版本历史和对话记录；工作区之外的项目数据——事件
  历史与续接点、数据源配置（含连接凭据）、Studio 写锁与草稿、Jiuwen 引擎工件区——删除时不处理。
- **删得慢**：大工作区的移动在请求内同步执行；Windows 上刚被杀的进程要片刻才释放目录句柄，
  此时移动会失败。

## Decision

删除改为永久删除：不进回收站，不看项目状态，二次确认由前端弹窗完成。

1. **响应前只做快的步骤**（`DELETE /api/projects/{id}`）：
   - 会话 `SessionManager.discard()`：立即硬杀引擎、退出排队、拒绝待确认的权限卡、清除事件
     历史与续接点；不排锁、不等 CLI 应答。连接中的会话由 `_connect` 在引擎连上后发现已被摘除，
     当场硬杀，不留游离子进程。
   - 评测 `modeling_eval.abort_for_delete()`：置协作取消标记，返回待取消的远端轮次坐标，不发网络请求。
   - 工作区 `stage_delete()`：同盘 `os.replace` 原子移入 `DATA_DIR/.purging/`，项目立即从列表和所有
     接口消失；目录被占用时短暂重试，仍失败就把 `.onto-web.json` 换成 `.onto-web.purging`
     标记、原地清除。
   - 清除数据源配置（含连接凭据）与 Studio 写锁、草稿。
2. **响应之后并发收尾**（`_finish_delete`）：递归删除暂存目录与 Jiuwen 工件区、取消远端评测
   轮次、级联删除 modeling 侧项目（失败进入已有的持久化重试队列）。各项互不阻塞，未完成的
   记入运维错误日志。评测编排可能晚于删除才收尾，工作区不在时不再落状态、不重建目录。
3. **启动清扫**（`purge_leftovers`）：清除 `.purging/` 下的残留和带清除标记的原地目录。
4. 递归删除只删链接本身、不跟进：工作区里的 `.claude` 等指向所有项目共用的资产目录。
5. 回收站页面与恢复接口保留，只服务旧版软删除留下的存量条目。

## Alternatives considered

- **保留软删除，回收站定期清理**：保留期内凭据与对话仍在盘上，还要新增定时任务；不满足
  "删除即清除"。
- **保留忙碌守卫，让用户先停任务**：会话悬死或排队时用户无从下手，表现为"删不掉"；需求
  明确要求不论状态直接删除。
- **请求内同步递归删除**：大工作区耗时长，Windows 上句柄未释放会直接失败；先原子移出、
  响应后再删，对用户即时生效，删不净的还能由启动清扫兜底。

## Consequences

- 删除不可恢复，系统内没有找回入口；前端确认文案明确提示进行中的会话、排队消息和数据评测
  会被强制终止。
- 删除接口在磁盘清理完成前就返回成功；收尾失败不回报给用户，记入运维错误日志，工作区目录
  的残留由下次启动清扫兜底。
- 删除接口不再返回 `PROJECT_BUSY`；409 只剩目录被占用、暂时无法删除（`project_busy`）。
- 数据目录下新增 `.purging/` 暂存区和 `.onto-web.purging` 标记文件，均由平台维护。
- 存量回收站条目清空后，回收站页面与恢复接口可另行移除。
