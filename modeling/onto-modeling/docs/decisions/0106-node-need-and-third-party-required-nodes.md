# 0106 节点模型：用 need 一个字段表达何时要做，第三方包可以声明必需节点

## Context

节点模型重构（2026-11-17 定，批次 1～3）之前，节点「什么时候要做」分散在 placement、section、optional、progress、
visible_if、activation、preempt 七个字段里。建模按段拆成 per_slice 步骤，ADR-0078 取消分段后遗留字段还在。ADR-0065
规定节点包的挂法只能是 step / branch / gate / on_demand，主流程位置 spine 只能随 core 发布。

重构已在代码里落地（`backend/app/services/flow/need.py`、`backend/app/services/packs/checks.py`），没有对应 ADR，
ADR-0065 的挂法限制和代码不一致。

- **目标**：包作者、平台、助手对「这个节点要不要做、什么时候做」只有一种说法；进度、推荐、导航栏、自主构建资格由同一份声明算出。
- **约束**：
  - 第三方包（不是镜像内置入库、也不是 core）的内容不可信，自主构建无人值守。
  - 锁定旧 core 的项目、助手副本里的旧脚本还在读旧字段，不能一次删掉。
  - 进度分母和推荐顺序在后端和助手副本两处计算，必须一致。

## Decision

1. 节点只用 `need` 表达何时要做：
   - `required`：上导航栏，计入进度，没做时推荐，自主构建会做；
   - `optional`：挂在前面最近的必需节点下面，可以跳过，不计入进度，必需节点都做完后才推荐；
   - `{when: <内核条件>}`：条件成立时出现，处理完就隐藏。

   旧字段在装配时按 `need.py` 的折算表折成 need，同时写了以 need 为准；旧字段不删，按 need 补齐。
2. 第三方包可以声明 `required` 节点，取代 ADR-0065 中「主线节点只能随 core 发布」这一条。spine、step、gate 都折算成
   required，「主流程位置」和「串入的一步」不再区分。安全边界改由自主构建承担：第三方包的节点没写 `autobuild` 时装配成
   `autobuild: false`；写了 `autobuild: true` 的，在上传审核页列出给审核的人看。
3. 建模拆成「提取对象」`core.object` 和「提取操作」`core.operation` 两个节点，分段遗留整个去掉，`core.model` 作为
   `core.operation` 的别名保留。「规则」一步删掉，规则和指标同由「提取规则与指标」`core.metric`（optional）完成。
4. 增量构建包删掉，内核的「增量更新」`core.update` 声明为 `need: {when: materials_added}`，沿用 ADR-0091 的触发机制。
5. 节点名就是主命令名。导航栏、全部命令菜单、建议条、对话气泡、排队条、执行记录用同一个名字，节点编号不改。
6. 推荐按五级从上往下判，命中就停，后端和助手副本共用 `flow_state.suggest`，取代 ADR-0048 的优先级。可补做的必需节点
   排第 4 级（ADR-0065 写的是第 5 级），「可补做」的判断改成「后面已完成的节点用了它的产出」。`done` 为空的节点永远不推荐。

## Alternatives considered

- **保持 ADR-0065，只有 core 能占主流程位置**：不选。step 串入的节点本来就计入进度，和 spine 的差别只剩「位置由谁定」，
  对包作者是多余的概念。这条限制真正要防的是无人值守时执行不可信内容，autobuild 默认关闭直接防住了这一点。
- **第三方包只能声明 optional 或 when**：不选。包作者想要一步发布前必做的检查时，只能降成可选，用户可以跳过。
- **保留多字段，只补文档**：不选。七个字段能写出互相矛盾的组合，装配时只能按优先级猜意图，包作者和审核的人都要记这套优先级。

## Consequences

- 一处声明算出进度、推荐、导航栏和自主构建资格，`packs/checks.py` 对所有包统一检查 need 写法。
- **最强的反对理由**：装一个第三方包，项目就多一个必经节点。包的完成判定写得不好时，进度永远到不了 100%，推荐一直指向它。
  缓解：`done` 为空的节点不推荐；用户可以停用这个包，停用后产物保留、节点显示「已停用」（ADR-0065）。
- **代价**：旧字段要和 need 并存到锁定旧 core 的项目都升级之后；need 折算表在内核（`need.py`）和助手副本
  （`flow_state.need_of`）各有一份，靠测试对齐。
- **迁移风险**：老项目的确认记录迁移出错时，会被推「提取对象过期」，进度倒退；自主构建从按段改成按节点后，暂停中的老运行要能续跑。
