# 0072 去掉「确认生效」：每一轮结束自动合入成版本，检查只提示

## Context

ADR-0046 按详设 v1.1 的 8.2 做了陪伴建模的「确认生效」：助手一轮的修改留在副本里，检查通过后用户点确认生效才合入主线；
确认蓝图（BP-03）要先确认生效资料分析那一轮。用户在测试部署上手测（自主构建项目、内测引擎）时卡死了：

- 资料分析那一轮的报告、建模蓝图、6 个对象都在同一个变更集里；合入检查报了 6 处「链接失效」——都是指向还没建的操作、
  别的段的对象，在分段建模里是正常的——确认生效回 `422 gate_failed`；
- 确认蓝图要先合入这个变更集，同样 422；能走的只剩「撤回这一轮」，会把报告和蓝图一起扔掉；
- 同一个变更集跨了两轮，对话里出了两张一样的卡，待处理里还有一条详情是空的「修改待确认」。

用户 2026-11-03 决定：确认生效去掉，陪伴和自主一样，助手每轮的修改直接进项目、每轮存一个版本，对话里每轮一张卡，
只留「撤回这一轮」；检查在建模过程中只提示不拦截，发布时才拦。这回到 10-31 定的「变更集保留为内核机制，单人自动合入」，
推翻详设 v1.1 8.2 的「检查通过后用户点确认生效」。

## Decision

1. **每一轮结束自动合入**（`kernel/changesets/service.settle`）：会话宿主在一轮出 result 时（成功、被打断）、引擎出错
   或被硬杀时，把副本里这一轮的修改合入成一个版本。引擎里还排着下一条消息时不合（并到下一轮），避免和正在写的那一轮
   抢副本。合入沿用 ADR-0046 的步骤（合成树、按实体检测冲突、受保护路径取主线、ChangeTx squash 提交），只是：
   - 不再查「助手在不在跑」（调用方知道这一轮已经结束，`turn_over=True`）；其他入口（Studio 转复核、执行清单经
     `copy_for_turn` 走到这里）在助手还在跑时不合，免得把半轮合进去；
   - 实体冲突照旧记 `conflict` 进待处理（CS-07 选好再合）——这是用户唯一会看到变更集的情况。
2. **补合遗留的**：下一轮开始前（`_deliver`）、服务启动时（`startup_repair`，先 `observe` 把副本里已提交没记下的
   改动记进变更集）把没走到收尾的合入；自主构建没结束的运行留给运行器。**升级迁移**就是这一条：部署前留下的
   `pending_confirm` 变更集，启动时没冲突的自动合入并把对话里的卡更新成已生效，有冲突的进待处理。
3. **一轮一张卡**：一个变更集（一轮）只放一张「这一轮改了什么」卡，之后原地更新；卡片只说改了什么、存成的版本和检查
   提示，按钮只有「查看改动」「撤回这一轮」，冲突时「去处理」。前端遇到升级前同一变更集的两张卡只画最新那张。
4. **撤回这一轮 = 回到上一个版本**（CS-05，`revert_round`）：合入过的在主线上写反向提交，另存一个版本；之后别处的
   修改保留；这一轮之后又改到同一条时 409 `merge_conflict`，说明是哪几条、不硬撤。按段建模的一轮会把新条目记进蓝图
   的这一段：撤回时只去掉这一轮记进去的（同自主构建按段撤回），建出蓝图的那一轮（资料分析）整份撤回；这一轮记过的
   段、步骤作废，按主线现状重算。冲突中还没合入的照旧撤回副本。
5. **检查只提示**：合入时的规则检查与包声明的提交门禁（`ChangeTx(hint_gates=True)`）只记进变更集的 `checks`。按段
   建模时，链接失效的目标在合成树的蓝图里已规划（某段的对象、操作、规则）就记「待建」（`pending_links`，带第几段），
   不算问题；没有蓝图或全量模式照常算。卡片提示按「3 处指向第 2 段待建的内容」「1 处链接找不到对象」「2 处结构缺失」
   说，不说「检查有 N 个新错误」。Studio 保存只拦解析不了的结构（缺必需章节、表头缺列），链接、主键只提示；MCP 写入
   的引用问题只进 `warnings`。发布门禁链（PB-01）不变。自主构建合入前有新错误先让助手修（策略里的轮数），还有就照样
   合入、标需复核；不再因为检查挂起一段。
6. **去掉的**：卡片和建议条上的「确认生效」、建议条的 `pending_confirm` 模式（合入冲突时主推「处理冲突」）、待处理的
   `pending_changeset`、BP-03 对合入的依赖（升级前遗留的先 `settle`，冲突时 409 指向待处理）、陪伴建模合入时的门禁
   拦截。CS-04 保留给遗留的待确认变更集，界面不再调。写入范围锁的 `pending_confirm` 只表示合入冲突（界面叫「有冲突」）。

## Alternatives considered

- **只放宽门禁、保留确认生效**：用户明确要去掉；确认生效每轮多一次点击，且检查本来就要在发布时再拦一次。
- **一轮结束只合入已提交的内容，没提交的留在副本**：副本合入后要重置到主线，留下的改动得另做 rebase；卡片按副本快照
  （含没提交的）说「改了什么」，合入范围和卡片说的不一致。仍按快照合入，和 ADR-0046 的确认生效同一口径。
- **检查不过时自动撤回这一轮**：会把资料分析报告和蓝图一起扔掉，正是这次卡死的原因。

## Consequences

- 用户看不到变更集；版本页上每一轮一个版本，撤回也是一个版本。
- 检查发现的问题会带进主线：靠卡片提示、待建计数、发布门禁和「撤回这一轮」兜底。
- 跨多轮的命令（中间用文字问用户）每一轮都会存一个版本；段、步骤的确认按执行记录收尾时的主线状态记。
- 插件声明的提交门禁在助手合入里只提示；网页、产物编辑器经写入事务的保存仍按包声明拦（未在本次范围内改）。
