# 0007 发布数据绑定门禁：可修复、可降级

## Context

发布知识包（以及非导入模式的数据评测）前，后端按对象「# 数据来源」声明与项目数据表
（schema 表格资料、评测数据源保存的上传表）做绑定；声明的表不存在或一列都对不上时整包拒绝导出。
实际使用中暴露三个问题：

- 项目里还没有任何数据表时，所有声明都"不存在"，整包无法发布——但此时声明根本无从核对；
- 建模阶段 agent 会从调研报告、数据字典或对象英文名臆造表名，规则检查只给警告，问题拖到发布时才暴露；
- 阻断只有一行错误文本，没有修复入口，也没有"先发出去"的出路。

## Decision

- **门禁范围收窄**：只有"有数据表可核对、声明却对不上"才阻断（`issues[].blocking`）；
  没有任何数据表时声明记为 `declared_unverifiable`，只提示，对象不绑定（来源Sheet 写 `—`）。
- **结构化问题与修复入口**：`resolve_object_tables` 在 `problems` 文本之外产出 `issues`
  （对象、类型、候选表）；`GET /package/check` 返回体检结论（条目有上限，附文档版本号）；
  `POST /objects/{key}/data-source` 把声明改成现有表或「无」，走 Web 保存同款乐观并发与版本点。
  前端发布前先体检，有问题项时弹出修复面板：选候选表、标记不落库、把已上传的表格标为 schema
  或补传一份、打开文档、交给助手修复。
- **降级发布**：用户确认后带 `allow_unbound=true` 导出，对不上的对象按未绑定处理、不进 mapping；
  `last_package_publish`（时间、操作人、是否降级、未绑定对象）写入项目元数据。脚本契约等
  其他导出错误不受影响，仍然阻断。
- **评测同口径**：非导入模式发起评测前同样体检，返回 `code=binding_problems` 与阻断项；
  用户确认后带 `allow_unbound` 继续，执行详情展示未查库对象。导入模式沿用本轮工作簿的宽松绑定。
- **前移到建模阶段**：工具箱规则检查与发布门禁同口径——有数据表时声明不存在或一列都对不上
  判 `错误`（提交前检查拦截）；没有数据表却声明了表判 `警告`；抽取提示词与对象模板要求
  无数据表时填「无」，不臆造表名。

## Alternatives considered

- 保持硬阻断、只改错误文案：用户仍然无路可走，且无数据表时的误拦截不解决。
- 无数据表时静默放行、不提示：臆造的表名会一路留到后续补 schema 时才集中爆发。
- 降级发布仅限管理员：数据绑定问题是建模质量问题而非权限问题，限制只会把问题推给管理员；
  改为人人可用、留发布记录可追溯。

## Consequences

- 无数据表的项目可以直接发布，包内对象全部未绑定（与引入发布门禁之前的行为一致）。
- 降级发布的包里，对不上的对象在数据问答里查不到数据；执行详情与发布记录会标明这些对象。
- 已有项目中声明了不存在表名的对象，下次由 agent 提交相关文档时会被规则检查拦下，需要先修正声明。
