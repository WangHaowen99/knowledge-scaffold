# 0060 自主构建运行器：按蓝图逐片执行，每片新开上下文、自动生效，生效之后是安全点

## Context

详设 1.6 #2、8.5 定下第二种构建方式「自主构建」：在用户设定的范围和预算内按建模蓝图一路建完，不停下来问；拿不准的
按策略决定并记账或挂起；每片一个变更集，检查通过自动合入，产出标「需复核」；每片合入之后是安全点；结束出运行报告。
方案 B12 给了运行器的步骤（新开上下文 → 注入片说明和台账摘要 → 带 owner 发送 → 等 result → 查执行记录，没做完也没
挂起就说「继续」→ 检查 → 合入 → 到安全点检查暂停、转陪伴）。B4b 留了变更集接口（`open_changeset`、`merge(source=
"autobuild", needs_review=True)`、`revert_merged`），B4d 留了蓝图接口（`run_slices`、`register_autobuild_preview`、片的
命令带 `slice=`），B4a 留了执行记录与启动恢复注册表。

## Decision

1. **代码与数据**：`services/autobuild/`（`policy`、`limits`、`plan`、`store`、`budget`、`decide`、`hint`、`runner`、
   `review`、`views`），接口 `routers/autobuild.py`。运行记录在数据目录 `autobuild/<项目>/runs/<run_id>.json`（状态、
   进度、预算、台账、挂起的问题，不进 git：复核状态常改，每次都成为一个版本不合适），策略在同目录 `policy.json`。
   运行结束时台账与运行报告经写入事务写进工作区 `reports/autobuild/<运行号>/ledger.json`、`report.json`（来源
   autobuild，一次提交）。
2. **范围**（`plan.build`）：按蓝图建议顺序、没排除的片；`all_pending` 取没做完的（`refresh_stale_first` 时过期的也算），
   `selected` 取选中的。每片要跑的步骤取建模节点的 `steps`（对象、操作、规则，启用场景走查再加「场景」），已确认的不做，
   规则没规划时不做（`include_optional` 时也做），`generate_scenarios=false` 不做场景。切片之后主线上的几步（校验、
   全量回归、全局一致性）各算一个单元，做到 `until_node`（含）为止；发布、增量更新、人工节点、旁支不做。需要已确认的蓝图
   （`409 blueprint_not_confirmed`）。
3. **一片怎么跑**（`runner._run_unit`）：
   1. 新开上下文：关掉运行对话的模型上下文（清续接点、回收引擎），历史里记一个 `context_reset`（不投影成对话流事件），
      Jiuwen 的历史回放只取它之后的；
   2. 先占变更集（`source=autobuild`、`build_mode=L4`、`run_id`、`slice_id`）；
   3. 每一步：写注入（ADR-0061）后以项目所有者的身份发 `/<命令> slice=<片>`（这条用户消息标 `hidden`，不进对话流），
      按条件等这一轮结束（会话池的信号 + 「一轮收尾中」标记，不按固定次数空转）；查执行记录：完成就下一步；命令锁还在
      （等待）说「继续」，最多 3 次；执行记为中断（引擎出错、会话被回收）按执行记录续跑（`turns.resume_text`，带
      `resume_exec`），连续出错 3 次运行失败；这一步挂起了问题、或「继续」用完了，这一步记部分完成，执行记为放弃、
      副本里的命令锁清掉，接着下一步；
   4. 自动合入：`merge(source="autobuild", needs_review=True)`，提交说明 `autobuild: 自主构建运行 #n「片名」（cs-x）`；
      门禁不过（新增错误）把错误发给助手修，最多策略里的 `max_fix_rounds` 轮；还不过就撤回这一片的修改（`discard`）、
      挂起一个问题「「片名」检查没通过」，接着做下一片；合入冲突、门禁跑不起来时运行失败（冲突进待处理）；这一片
      没改出东西时先占的变更集关掉、版本不变；
   5. 安全点：发 EP-15，查标志——预算用完、停在安全点、转为陪伴就结束；暂停（含维护模式的「在安全点暂停」）就暂停；
      否则下一片。
4. **控制**（AB-06～AB-09）：暂停在一步做完之后生效（`pausing` → `paused`，这一片的变更集留着、写入范围仍锁这一片）；
   停在安全点、转为陪伴在这一片生效之后生效（`stopping` / `converting`）；已经停在安全点（这一片还没开始）或还在排队时
   直接结束；暂停、中断的运行续跑接着做这一片剩下的步骤（不新开上下文）；从暂停直接停在安全点、转为陪伴会先把这一片做完。
   转为陪伴不改项目的默认构建方式，运行对话之后照常能聊。
5. **结束**：报告先进 git、对话里的切片进展块、运行报告卡、一行提示（「运行 #n 已完成」等，不出现「合入」「L4」）、
   建议条（主推「去复核」）都放好，最后才把状态记成结束——看到运行结束时，报告已经在版本里、对话里了；之后发 EP-14、
   EP-17、用户流通知（通知中心 A-13 还没有，只推实时）、可观测，排到结束后的改判发出去，再看排队的运行。
6. **重启**（AB-09、详设 8.3）：启动恢复登记「自主构建」一步（order 105，在执行记录改判之后）：停机时在跑的运行改判
   `interrupted` 并标自动续跑（`pausing` 的直接算暂停，`stopping` / `converting` 续跑后接着停）；时长按最后一次记账的时刻
   止算，停机时间不算。lifespan 在启动恢复之后自动续跑（`recovered_from_checkpoint` 加一），每一步按执行记录接着做
   ——执行编号没来得及记下时按运行对话里这一步的执行记录找回。执行记录带 `run_id`：重启时不放续跑卡，待处理不列。
7. **卡片**（契约 4.7）：`autobuild_start`（范围、预算、拿不准时；生产库不出，证据源只留接口）；每片一个
   `slice_progress`（步骤、用时；自动决定与挂起按时间嵌在 `timeline` 里，F2 补充第 9 条）；`run_report`（AutobuildReport
   加 `review_count`）。运行中不出「这一轮改了什么」卡和插件产物卡。

## Alternatives considered

- **一片的多个步骤并成一条命令**：工具箱没有「做完这一片」的命令，按片的命令本来就分步骤；分开发也让执行记录、续跑、
  「继续」的判断落在一步上。
- **台账只存 git**：复核（接受、改判）要改条目状态，每次都是一个版本；数据目录存工作副本，结束时把那一刻的样子写进 git。
- **每片生效时顺带写台账进 git**：撤回一片用反向提交，台账文件后面的片也会改，就撤不动了。
- **门禁不过时把这一片留给用户确认**：同一项目同一时刻只有一个没关闭的变更集，后面的片就开不了；撤回并挂起，用户在
  待处理里回答后补做。

## Consequences

- 自主构建产出的每一片都是主线上的一个版本（来源 autobuild），版本列表、撤回、发布门禁照常；运行报告多一个版本。
- 运行器在进程内（每个项目一个任务），停机时取消、重启后续跑；多进程部署要换成共享调度（与命令限频、票据同样的限制）。
- 场景推演通过数没有数据来源，运行与报告里给 0（gaps B5b）。
