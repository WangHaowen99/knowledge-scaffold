# 0035 命令执行记录归会话宿主，续跑卡与页面命令任务都以它为准

## Context

详设 8.4、方案 B5～B7：命令执行断点原来靠 `state_helper` 的锁文件（`.ontology-state/lock-<命令>.json`），
后端不读。Claude 引擎下 CLI 子进程一回收、服务一重启，锁就被判过期清掉，用户看不到「续执」；
能不能释放全靠模型自觉。界面需要的执行记录（契约 ExecRecord、S-15～S-17、EP-09）、续跑卡（4.7 resume）、
页面命令的进度条（S-19、S-20、EP-10 CommandTask）都没有数据来源。

## Decision

1. **每条命令一份记录，宿主维护**（`session_host/exec_records.py`，存 `DATA_DIR/exec/<项目>/<执行 ID>.json`）：
   - 消息开头是流程登记的斜杠命令（flow.yaml 的 `commands`）就开一份；普通消息接着这条对话里等待中的那份；
     运行中收下的消息要等前一轮出 result 才开始（引擎接着跑它时再开）；
   - 节点、节点版本取自组装后的流程；阶段取自工具箱命令锁的 `phase`（state_helper 的命令行接口不变）；
   - 一轮结束：命令锁还在（或在等你回答）记**等待**——陪伴建模一个命令常跨几轮问答，不能一律记中断；
     命令锁已释放记**完成**；
   - 打断、引擎异常结束、会话回收、停机、启动时还开着：记**在某阶段中断**，并在对话里放续跑卡
     （你自己打断的不放卡，建议条主推「从打断处继续」）；
   - 中断时记下输入指纹（资料区与上游节点完成判定看的目录在主线上的提交树）：续跑前输入被别人改过、
     或者节点版本变了，返回 `exec_not_resumable`（`inputs_changed` / `node_upgraded`）；
   - 续跑（S-16）往对话发一条带原命令的续跑指令，接着原来那份记录；放弃（S-17）不回退已保存的版本，
     续跑卡整卡替换成已放弃，对话里放一行系统提示。
2. **会话身份进 agent 的环境**：引擎实例 ID、项目、对话（`ONTO_RUN_*`，ADR-0034）；当前执行写进
   `.onto/run/exec.json`，agent 的提交据此带 `Onto-Node`（ADR-0037）。
3. **页面命令任务**（`session_host/command_tasks.py`，存在同一目录的 `tasks.json`）：S-20 解析按钮或命令、
   发到对话（用户消息带来源页面），返回任务对象；任务状态跟着执行记录（running / waiting_user / done /
   interrupted / cancelled），不是流程命令的跟着这一轮。状态变化在项目流发持久的 `command.progress`，
   只是阶段文字变了发瞬时的。包页面按钮 → 命令的解析由扩展项注册表登记（`register_action_resolver`，B4c）。

## Alternatives considered

- **state_helper 改为调本机接口读写执行记录**（方案 B5 原文）：要动工具箱脚本（包拆分归 B4c 并行在改），
  且 Jiuwen 进程内共用环境；先由宿主观察命令锁，state_helper 的兼容层留给 B4b（D15，数据走文件）。
- **一轮结束一律记完成或中断**：陪伴建模里命令跨轮问答是常态，会把正常的等待当成中断，满屏续跑卡。
- **开始时记输入指纹**：命令自己在执行中改上游目录（补字段）会被误判成「输入变了」；改为中断时记。

## Consequences

- 节点状态（D13）的「进行中」可以直接读开着的执行记录；B4b 计算节点与切片状态时以它为准。
- 记录按项目最多留 200 条（开着的不删）；项目删除时连同任务一起删。
- 阶段的「第几步 / 共几步」只能按出现过的阶段数给，命令锁不带总步数；以后由节点声明补。
