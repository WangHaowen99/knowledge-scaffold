# 0074 界面上不出工作区路径：业务名由后端算

## Context

- 用户 2026-11-03 定：工作区的文件目录不让用户看见，用户尽量通过 Studio 看内容。用户面对的是对象、规则、资料，不是文件夹。
- 现状：变更卡、查看改动、版本页、待处理、出处悬浮、发布清单、对话气泡等十几处直接显示 `ontology/…`、`resource/…`、
  `research/…` 路径或带扩展名的文件名；前端各页各写一套「路径 → 说法」的猜法，口径不一。
- 助手和开发侧的工作区目录结构不变，接口里的路径字段也要留着（助手、插件、测试都靠它定位）。

## Decision

1. **后端一处算业务名。** 新模块 `app/services/workspace_labels.py`：路径 → `{group, target}`，`target.label` 是给人看的名字。
   - 条目按元模型（对象「门店」）；插件产物按登记的 `title`（流程图「订单流程」）；
   - 认得的文件按固定叫法：建模蓝图、资料分析报告、检查报告、资料用途；资料按资料名（原文件名去扩展名，文本版映射回原资料）；
   - 认不出的返回空，由调用方合成「另有 N 处改动」，不出文件名。
2. **接口加字段，不删路径。** `EntryRef` / `ArtifactRef` 加 `label`；`Material` 加 `title`、`type_label`；
   `AnchorResolution` 加 `material`，`source_label` 改为资料名，`location_label` 按位置标记（第 3 页、工作表 客户）或小节标题算，
   不显示行号。
3. **给人看的文字在下发前换掉路径。** `humanize()` 把一段话里的工作区路径换成业务名，用于命令气泡、版本说明、报告位置；
   发给助手的原文不动（S-20 新增 `display_text`，对话只显示命令和说明，不带参数）。
4. **前端只显示 label。** 卡片、查看改动、版本改动表直接用 `target.label`；资料页不再按工作区子目录分组。

## Alternatives considered

- **前端统一一个路径猜法。** 改动小，但产物登记、元模型只在后端，前端猜不全（插件产物、改过元模型的项目），且和 AGENTS 的
  「前端不自己猜路径」相反。
- **接口去掉路径字段。** 助手、插件、测试、对比与下载都要定位文件，去掉会大面积破坏兼容。

## Consequences

- 新增的用户可见文字都要过 `workspace_labels`；新的产物类型只要在登记里写好 `title` 就有业务名。
- 认不出的文件在界面上只计数：版本文件抽屉不列它们（zip 里照有），变更卡、查看改动合成一行。
- 出处行号不再显示；没有位置标记、也没有小节标题的资料只显示资料名。
