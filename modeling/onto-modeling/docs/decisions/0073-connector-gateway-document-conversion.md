# 0073 连接器网关第一版：文档转换

## Context

### 目标

- **要解决的问题：** 用户上传的 PDF、Word、Excel，助手读不准。平台的抽取脚本不认 PDF，助手每次临时写脚本抽，核验对不上出处，
  一个项目返工十几分钟（用户 2026-11-03 定的整改起因）。
- **给谁用：**
  - 建模用户：上传后能看到这份资料「转好了没有」，能看转出来的文本；
  - 助手：按「只读 Markdown」就能拿到每份资料的文本，文本里带页码、工作表，出处能写「第 3 页」「工作表 客户」；
  - 管理员：同一种文件有多个转换器时指定默认；
  - 运维：看得到转换服务是否可用。
- **怎样算成功：**
  - 上传文字版 PDF、Word、Excel 后，几秒内资料区里有对应的文本版，界面能看；
  - 扫描件和图片明确标「暂不支持」，不参与分析；
  - 转换服务停了不丢活，恢复后自动补上；
  - 后端进程从不解析这些文件；
  - 换转换器不用改内核。

### 基本约束（不能违背的事实和要求）

1. **输入不可信。** 文件来自用户上传，单个最大 20 MiB。PDF、OOXML 的解析库出过卡死、内存炸开、zip 炸弹一类的问题；坏文件、
   恶意文件都可能让解析卡住或吃满内存。
2. **主容器里有能执行任意命令的助手。** 后端以 root 运行，工作区、密钥目录都在这个容器里；内测引擎直接跑在后端进程里；
   助手能访问主容器所在网络上的任何 HTTP 接口。
3. **连接器网关以后要存数据库凭据、连业务网络（详设 5.8）。** 它的信任边界现在就得按那时的要求定：主容器（也就是助手）
   不能往网关里放代码，不能不经内核授权就让网关干活。
4. **写工作区只走写入路径。** 版本、事件、资料区对助手只读，都靠写入路径保证。
5. **要能替换。** 同一种文件可以有多个转换器，管理员指定默认；新任务用新版本；换了默认不自动重转旧资料。
6. **许可证。** 只用 MIT、BSD、Apache 一类；不用 AGPL（PyMuPDF）。
7. **界面不露工作区路径**（用户 2026-11-03 定）。
8. **已有的「资料变化 → 资料分析需要更新」**靠两样：资料分析回执记下读过的文件修订（`research_review.file_revisions`），
   和项目元数据的 `resource_updated_at`。

## Decision

### 推导

1. **在哪解析。**
   - 不能在后端进程里：解析卡死或吃满内存会拖垮整个接口和所有事件流（约束 1）；内测引擎也在这个进程里（约束 2）。
   - 也不该在主容器里另起子进程：子进程能隔离资源，隔离不了权限。解析库一旦被利用，拿到的是有工作区和密钥目录的容器；
     而且解析库装进主镜像，助手临时写的抽取脚本就又能在主容器里解析不可信文件，正是这次要去掉的做法。
   - 所以放进单独的容器（连接器网关）。容器里每个任务再起一个子进程，设超时、内存上限、输出上限；子进程崩了不影响网关
     本身（约束 1）。
2. **镜像。** 网关用单独的镜像（同一个 Dockerfile 的 `connector-gateway` 目标），只装转换库和网关代码，不带 git、助手 CLI
   和后端代码。理由同第 1 条：解析能力不进主容器，网关里可被利用的东西尽量少。脚本验证网关和主服务同镜像，是因为它
   本身不解析任何东西，只转发给 jiuwenbox。
3. **数据通路。** 内核把文件内容发给网关，网关回 Markdown 和位置对照，内核走写入路径落盘（约束 4）。网关不挂任何数据卷，
   被利用了也碰不到别的项目。
4. **网络。** 网关只接一个 `internal: true` 的内部网络，和主服务互通，没有出口（第一版不接业务网络）。
5. **鉴权：一次性票据，内核用私钥签、网关用公钥验。**
   - 不鉴权不行：助手能直接调网关（约束 2），现在只能白耗网关资源，接上数据库以后就是越权采集（约束 3）。
   - 票据沿用 `gateway_client.Ticket` 的字段：jti、任务、操作、范围哈希（这里是原文件的 sha256）、预算、10 分钟过期、
     用过作废。转换的票据另外写明用哪个转换器、文件名。
   - 用 Ed25519 签名的 JWT：私钥在后端的密钥目录（0700，助手读不到文件），网关启动后从内核取公钥。网关手里没有任何
     能签票据的东西；网关被利用了也伪造不了给别处用的票据。共享密钥（HMAC）就得把同一把密钥也放进网关，等于网关
     存了凭据。
   - 网关按 jti 记已用过的票据（内存里，过期就清）；按收到的内容重算 sha256 和票据核对。
6. **转换器的接口：单独一个 `DocumentConverter`，不套 `EvidenceProvider`。**
   - `EvidenceProvider` 的形状是「连接、测试、发现、采快照、补采样」，产出标准记录进证据快照，前提是有一个带凭据的
     在线系统。文档转换是「字节 → 文档」的纯函数，没有连接、凭据、范围。套进去要造假的 `conn`、`test`，再把记录拼回
     Markdown，多出来的全是没用的面。
   - 共用的部分：都是「数据接入」插件（包的 `kind: provider`，H2，平台级安装、不按项目启用），都跑在网关的子进程里，
     都用同一套票据、健康检查、描述字段（ID、版本、许可证、运行方式）。
7. **转换器放在哪：一个转换器 = 一个数据接入包**（清单 + `converter.py`），放在 `assets/packs/convert-*/`。
   - 网关镜像把这些目录拷进自己的只读目录（`/opt/connector/converters`），启动时加载清单，任务子进程按清单的入口导入。
   - 内核镜像里也有同一份包，只用来在插件中心展示（内核从不导入 `converter.py`）。ID、版本、文件类型、许可证只在清单
     里写一次，两边不会对不上。
   - 不做主容器可写的共享插件目录（约束 3）。第三方转换器怎么装是待定项（见下）。
8. **输出格式：Markdown + 行内位置标记。**
   - PDF 每页前一行 `<!-- 第 3 页 -->`，Excel 每个工作表前一行 `<!-- 工作表：客户 -->` 加一个二级标题；Word 没有页的概念，
     不加位置标记，用标题分节。
   - 助手读的就是这个文件，标记让它不用再查别处就能写「第 3 页」；界面渲染时把标记画成分隔条。
   - 网关另回位置对照（行号 → 位置），内核用它核对标记和文本对得上；对照本身不另存，以文件里的标记为准，免得两份对不上。
9. **文本版放在哪：`resource/text/<分组>/<原文件名>.md`**（如 `resource/text/others/合同.pdf.md`）。
   - 要在工作区里：助手用文件工具读，不可能每读一次都调内核接口；
   - 要在 `resource/` 下：资料区对助手只读，文本版同样不能让助手改；
   - 要跟着版本走：恢复旧版本时原文和它的文本版一起回去；
   - 不能出现在资料列表里：资料列表只列 `diagrams`、`excel`、`others` 三个分组，`text` 不是分组，不用另加过滤；
   - 和原文件一一对应：分组加完整文件名再加 `.md`，`合同.pdf`、`合同.docx` 不会撞；
   - 文件第一行是 `<!-- onto:text source="合同.pdf" sha256="…" converter="convert-pdf@1.0.0" -->`，记原文件修订和转换器版本。
10. **状态。** 每份资料的转换状态有：转换中、已转成文本、暂不支持、转换失败、等待转换（网关不可用）；md、txt、csv 本身就是
    文本，不经网关。
    - 中间状态存在内核数据目录（`DATA_DIR/conversions/<项目>.json`），不进工作区：转换中、等待这类状态写进 git 只会刷提交，
      工作区助手也能改。
    - 「已转成文本」以工作区里的文件为准：文本版存在且第一行记的修订等于原文件当前修订就算。导入、恢复版本之后状态记录
      对不上时，按文件重新判断，缺的再排队转。
11. **执行。** 上传立即返回；内核在后台排队（两个转换线程，同一份资料不并发），结果经写入路径提交（来源 `plugin`），中间状态经项目
    事件流推给前端（`materials.text.updated`）。网关不可用时记「等待转换」，后台每 30 秒看一次网关，恢复后自动补转。
    升级后后台把还没有文本版的资料补转一次。重启时把「转换中」的重新排队。
12. **资料变化。** 替换原文件时，同一个提交里删掉旧的文本版（不让助手读到过期文本）；重新转换后文本变了就是 `resource/`
    下一次普通的提交，资料分析回执记的文件修订对不上就退回待核验，`resource_updated_at` 也跟着更新（约束 8）。
13. **选哪个转换器。** 管理员按文件类型指定默认（存内核设置），只能在已有的转换器之间选；没指定时用唯一的那个，有多个时
    优先官方的。选择是策略，归内核；执行是机制，归网关。换了默认不重转旧资料，资料上有「重新转换」。

### 结论

1. 新服务 `connector-gateway`：独立镜像，非 root、根文件系统只读、`cap_drop: ALL`、`no-new-privileges`、限内存和进程数，
   只接内部网络，不挂数据卷，不读 `.env`。接口：`GET /health`、`GET /v1/providers`、`POST /v1/convert`。
2. 协议在 `app/evidence/convert.py`（转换器接口、结果、位置标记）与 `app/evidence/tickets.py`（票据签发与核验）；网关在
   `app/connector_gateway/`；三个官方转换器是 `assets/packs/convert-pdf`（pdfplumber）、`convert-docx`（python-docx）、
   `convert-xlsx`（openpyxl）。
3. 内核侧在 `services/material_conversion/`：状态记录、后台队列、网关客户端、迁移与补转。

## Alternatives considered

- **主容器里起子进程转换（rlimit + 超时）：** 资源隔离够，权限隔离不够（第 1 条）；解析库进了主镜像，助手又能自己解析。
- **网关和主服务同一个镜像（照搬 sandbox-gateway）：** 少一个镜像，但解析库会进主容器，理由同上。
- **把转换器做成 `kind=file` 的 `EvidenceProvider`：** 见第 6 条，多出没用的接口面，还要把记录拼回文档。
- **文本版放在原文件旁边（`合同.pdf.md`）：** 资料列表、资料地图、核验清单、500 份上限各处都要加过滤，漏一处就多一份「资料」。
- **文本版放在隐藏目录（`resource/.text/`）：** 很多文件工具和 glob 默认跳过点目录，助手按「只读 .md」找不到。
- **文本版放在内核数据目录：** 助手读不到，也不跟版本走。
- **票据用共享密钥（HMAC）：** 网关得持有同一把密钥（第 5 条）。
- **转换和上传同步做：** 上传接口要等不可信文件解析完（最长几十秒），网关不可用时上传也失败。

## 最强的反对理由

1. **「为了转三种文件，多一个容器、一个镜像、一套签名票据，太重；主容器里起个限资源的子进程就够了。」**
   - 子进程只隔离资源，不隔离权限；解析库进主镜像后，助手临时脚本解析不可信文件的老路又通了。
   - 网关本来就是要给数据库采集用的地方（详设 5.8），骨架按那时的约束搭，接数据库时不用推倒。
   - 代价：离线包多一个镜像（实测 347 MB，和主服务共用 python:3.11-slim 基础层），部署多一个服务，内核要管一对签名密钥。认这个代价。
2. **「签名密钥在后端进程里（详设 5.8.9 的缺口），票据防不住能读后端内存的助手，等于没用。」**
   - 对能读后端进程内存或以 root 读密钥目录的助手确实防不住，这个缺口照详设 5.8.9 记录，要等「按项目隔离 agent」解决。
   - 但它挡住了最直接的路径（助手直接调网关），每张票只能转一个指定内容（sha256 绑定）、用一次；接数据库时沿用同一套。
3. **「每次上传多出一个版本（上传一次、转换一次），版本历史变吵。」** 认这个代价：转换结果必须经写入路径；同步转换的代价更大
   （见 Alternatives）。
4. **「状态记录不在工作区，会和文件对不上。」** 以文件为准（第 10 条），记录只是中间状态的缓存，对不上就按文件重判。

## 和已定原则的核对

- 详设 5.8.3 原写「文件资料在内核 worker 里运行」，与「转换器不放内核」的决定矛盾，本 ADR 起改为网关里的转换器（详设
  5.8.2、5.8.3、5.8.9 同步修订）。
- ADR-0056「证据源本期只留接口」：数据库采集、快照、证据浏览器仍不出现；插件中心的「数据接入」分类有了转换器才出现。
  PL-04（申请平台安装）、PL-19（平台安装）仍回 501。
- 详设 1.4「包不带前端代码」：转换器包只有清单和网关里跑的 Python，没有前端代码。

## 待定项

- **第三方转换器怎么安装**（用户正在定）。约束：不能有「主容器把代码放进网关」的通道（约束 3），倾向由网关自己验包的签名，
  信任的公钥不放在主容器里。定之前只有随网关镜像交付的官方转换器。
- **扫描件与图片（OCR）**：先标「暂不支持」。以后接 OCR 时依赖很重，应作为单独的转换器镜像或旁路容器。

## Consequences

- 契约：R-01 的 `Material` 加 `text`；新增 R-13（查看文本）、R-14（重新转换）、PL-20（转换器与默认）、PL-21（设默认）、
  事件 EP-25 `materials.text.updated`；术语加「界面叫法：数据接入」（`_plan/contract-changes.md` F4a 节）。
- 部署：compose、离线包、`deploy.sh`、`redeploy-app.sh` 多一个 `connector-gateway` 服务和镜像；主服务多一个内部网络。
- 运维：健康检查的「连接器网关」从占位改为真实探测；启动报告随之体现。
- 测试镜像要装 `backend/connector-requirements.txt`（转换器测试在缺库时跳过，Linux 全量要用带库的镜像）。
