# 稳定复用知识包语义检查结果

## 背景

知识包“检查内容”同时包含确定性检查和大模型语义检查。确定性检查对同一输入结果稳定，
但语义检查每次从头审阅整个知识包，可能把同一问题依次判断为提示、警告、错误或不报告。
版本号、发布状态等元数据变化也会产生新的知识包修订，导致用户在业务内容未变化时看到新的错误。

## 决策

- 格式、引用、数据映射等确定性检查每次点击都重新执行。
- 语义检查根据当前检查规则和完整业务规格计算 SHA-256 哈希；即使超长脚本发送给模型时只传首尾，缓存键仍覆盖完整脚本。
- 版本号、知识包状态不进入语义检查正文，因此不会改变语义哈希。
- 同一修订已有可用语义结果时，将该结果作为稳定基线并写入缓存。
- 后续修订的语义哈希相同时复用缓存，不重新调用模型。
- 语义检查执行失败或返回损坏结构时不写入缓存，下次允许重试。
- 保留显式 `forceSemantic` 参数用于校验规则升级或人工排障；普通页面操作不启用该参数。

## 备选方案

- 将模型温度设为零：部分模型仍不保证完全确定，且无法解决版本元数据触发重复检查的问题。
- 连续运行两次并取交集：成本和等待时间翻倍，仍可能产生严重级别漂移。
- 完全取消语义检查：会丢失跨对象、操作、规则和脚本的业务一致性检查能力。

## 影响

- 重复点击“检查内容”不会再凭空改变语义错误数量。
- 业务知识发生变化时仍会生成新的语义检查结果。
- 校验提示或模型升级后若需要重新审阅旧内容，必须显式执行强制语义复查。
- 新增语义检查缓存表；现有数据库启动时自动创建，无需人工迁移。
