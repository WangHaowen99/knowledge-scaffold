# Neo4j Excel 导入采用保守列类型推断

## Context

Excel 解析会生成列类型提示，但通用数据字典将数据行保存为字符串矩阵，Neo4j 图导入因此把所有业务属性都写成字符串。数值、布尔值和日期无法使用 Neo4j 原生比较、聚合与时间函数。

## Decision

仅在 modeling 的 Neo4j Excel 图导入链路中保留可选的单元格类型元数据，并按 `Sheet + 来源列` 扫描全部非空值，统一推断以下类型：

- `string`
- `integer`
- `float`
- `boolean`
- `date`
- `local_datetime`

整数与浮点数混合时统一为 `float`，日期与本地日期时间混合时统一为 `local_datetime`，其他不兼容组合按 `string` 导入。前导零编码、超出 Neo4j 64 位整数范围的整数和超过保守浮点精度的文本数值均保留为字符串。

Excel 日期时间不携带时区。图导入直接从 Excel 日期序列提取年月日时分秒，保持表格中的本地时间，不经过 UTC 转换；时间精度统一到秒并写为 Neo4j `LocalDateTime`，纯日期写为 `Date`。

空值不参与类型推断。只要该行的实体投影不是全空，所有映射属性都保留；空单元格写为空字符串 `''`。关系采用字段匹配时仍使用原始规范化字符串，不受属性存储类型影响；同行匹配直接使用数据行索引。

## Alternatives considered

- 仅依据第一行或少量样本推断：后续出现不兼容值时会产生混合类型或写入失败。
- 直接复用通用数据字典的 `number` 类型：无法区分 Neo4j `INTEGER` 与 `FLOAT`，也无法保留日期时间和 Excel 显示格式编码。
- 将空值写为 `null`：Neo4j 会移除对应属性，不满足保留空属性的要求。
- 任一空值都将整列降级为字符串：会让大多数可用数值列失去原生查询能力。

## Consequences

- 非空属性使用 Neo4j 原生驱动类型写入，可以直接进行数值、布尔和时间查询。
- 同一来源列被多个实体重叠使用时共享同一推断结果。
- 空值节点上的属性值为字符串 `''`，非空节点上的同名属性为推断类型；数值或时间查询需要排除空字符串。
- 混合列和精度风险会在导入校验阶段产生降级告警，不会中断整批导入。
