# Neo4j Excel 导入使用行实例身份

## Context

同一个 Excel Sheet 可以投影为多个实体，各实体使用的字段可以不同或重叠。业务主键在这种表结构中不一定唯一，按业务主键合并节点会丢失行实例，属性不同的重复键还会中止整个导入。

## Decision

仅在 modeling 的 Neo4j Excel 图数据导入链路中采用行实例身份：

- 每个实体对每个非全空的 Sheet 数据行生成一个独立节点。
- 内部 `_d2o_record_key` 使用 `node:<objectKey>:<8 位数据行序号>`，并与 Workspace、Ontology、Label 一起定位节点。
- 业务主键保留为知识包元数据和普通节点属性，不参与图导入去重或实例身份生成。
- 关系显式区分两种匹配方式：`field_match` 按用户配置的源、目标关联属性匹配，重复关联值生成全部 `M × N` 节点组合；`same_row` 仅允许来源 Sheet 相同的实体，按 Excel 数据行索引连接该行生成的两个节点。
- `same_row` 不保存源、目标关联属性；任一实体在该行投影全空、没有生成节点时，该行不生成关系。
- 缺少匹配方式的历史关系映射按 `field_match` 处理，保持既有导入语义。

## Alternatives considered

- 继续按业务主键去重：无法表达重复业务键对应的多个行实例。
- 自动拼接更多业务字段：仍不能保证完全相同行唯一，且身份会随业务字段变化。
- 所有同 Sheet 关系强制按同行连接：会改变既有的关联字段匹配语义，也无法表达仍需按业务字段展开匹配的场景。

## Consequences

- 重复业务键和属性完全相同的行都能正常导入。
- 全空实体投影不会产生空节点。
- 覆盖导入同一份、同一顺序的 Excel 时行实例键稳定；调整行顺序后内部键会变化。
- 新建的同 Sheet 关系默认使用同行匹配，用户可切换为字段匹配；跨 Sheet 关系固定使用字段匹配。缺少匹配方式的历史映射仍按字段匹配处理。
- 字段匹配模式下，大量重复关联值可能产生较多关系，预览统计会展示实际展开后的关系数量。
