# 独立知识包 Hub 边界

## Context

Onto 发布原先生成临时 ZIP，版本号依赖有上限的工作区历史列表。正式版本和原始资料需要独立保存，同时保留原发布检查、评测和消费导入格式。

## Decision

新增 `knowledge-hub/` FastAPI 服务，沿用文件、JSON、Git 存储。Hub 是正式发布版本权威；Onto 负责项目权限、稳定打包输入和原格式转换。版本由 Hub 持久分配，发布采用预留、上传、提交，故障重试复用请求和原 ZIP。

资料只保存项目最新集合，独立同步、不进 Git、不与知识包发布组成联合事务。评测包作为内部快照交接给既有执行流程。旧 Modeling Agent 入口不变；MCP 草稿不冒充正式发布。

## Alternatives considered

保留临时 ZIP 无法提供不可变版本下载；共享工作区写目录破坏服务边界；引入数据库或对象存储不符合本期存储一致性目标。把所有评测强行改为读取正式发布包会破坏按数据源生成映射的现有能力。

## Consequences

Hub 不可用时新发布和需打包的新评测失败关闭。Onto/Hub 需分别备份并对账，恢复必须重放删除记录。采用单实例本地卷，跨进程锁支持进程恢复，但不承诺多副本网络文件系统。原始资料不能用于复原某次历史建模输入。
