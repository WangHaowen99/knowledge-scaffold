# 图查询过滤值按物理属性类型规范化

## Context

图查询 Agent 通过 JSON 生成工具参数。JSON 中的数字、布尔值和字符串只是传输类型，未必与图数据库中的物理属性类型一致。旧过滤解析器还会从字符串词法推断标量类型，因此数字形态的字符串可能被当作整数，而超出紧凑 schema 字段上限的属性又没有类型信息可供转换。

该问题不限于整数和字符串。布尔、浮点、Decimal、日期时间、Duration、Point、List、Vector、Map、Bytes，以及同名属性存在多种物理类型时，都需要明确的安全边界。节点、关系、路径过滤和最短路径端点也应遵循同一规则。

## Decision

在图工具执行器与后端之间增加请求级物理类型解析和过滤值规范化层。

类型来源和优先级如下：

1. Provider 在请求开始时从当前 workspace/scope 的图数据库预取 schema，并压缩为 `schema_context`。目标字段存在、该目标的字段集合完整且 Provider 声明这些类型可作为物理类型依据时，直接使用它，避免重复查库。Neo4j 的预取 `valueType` 满足该条件；HugeGraph 当前预取由有界 snapshot 推断，不走该快速路径。
2. 目标字段缺失，或 compact schema 明确标记字段截断/底层采样不完整时，通过后端 `get_property_types` 仅查询本次实际过滤字段。Neo4j 使用作用域约束后的 `valueType`；HugeGraph 优先读取 schema 元数据，无法取得时才检查有界 snapshot。
3. 回查按字段判定权威性。完整查询返回的类型可覆盖 compact schema；HugeGraph schema 元数据直接确认的字段即使同批 snapshot 被截断也仍然有效。仅由达到上限的不完整采样推断的字段、回查失败、未知类型或无非空值字段不做猜测，保留原输入和旧查询行为。
4. 同一字段出现不同类型族时视为歧义并拒绝强制转换；同族别名（例如不同整数宽度）合并为同一类型，并保留可表示范围。

仅规范化比较操作数，不转换 label、关系类型、变量名、返回字段名或排序字段。规范化覆盖：

- `property_filter`
- `count_search`
- `aggregate_search`
- `sorted_search`
- `pattern_search` 的节点和关系过滤字段
- `shortest_path` 的起止节点属性

`hop_search` 没有属性过滤参数，不进入该层。

同一边界同时用于 Provider 内部 Agent 工具、MCP 搜索执行器、独立工具适配器和确定性执行 Provider Broker，避免直接调用后端的旁路产生不同类型语义。

外部工具参数和聚合结果仍保留调用方传入的原始 filter；转换后的值只在数据库调用边界内部使用，避免影响审计摘要和 Agent 后续推理。

schema 压缩继续保留每个类型最多 30 个字段、最多 80 个类型以及有限关系三元组，以控制 Prompt 体积。压缩结果分别标记类型名称截断、字段截断和底层数据截断；字段类型解析只把后两者视为需要回查的信号。Markdown 业务上下文不作为物理类型权威来源。

定向类型回查只证明所请求字段的物理类型，不证明节点/关系类型名称全集或该类型的字段全集完整；focused preload 同样不代表全库名称全集。pattern schema 校验因此只在来源显式声明名称或字段清单完整时做否定校验。

## Alternatives considered

- 只修改测试 Prompt 或要求 LLM 输出正确 JSON 类型：不能覆盖前导零字符串、超过 JavaScript 安全整数范围的整数，也不能保证所有模型调用稳定遵守。
- 只在 `_build_part_condition` 中把数字字符串转为整数：只能处理一种语法和一种类型，会遗漏结构化操作符、列表、路径及其他工具。
- 每次过滤都查询数据库类型：结果最直接，但会给所有请求增加额外数据库往返；完整 compact schema 已来自同一 Provider，无需重复查询。
- 只依赖 compact schema：字段上限和底层 snapshot 上限会导致被截断字段继续缺少类型。
- 根据字段名或值形态猜类型：对编码、UUID、日期文本和混合类型字段存在不可接受的误转换风险。

## Consequences

- 过滤值与数据库物理类型一致，数字形态字符串和大整数不再经过不精确浮点转换。
- 可作为物理类型依据的 schema 完整时没有新增数据库调用；HugeGraph snapshot 预取会对实际过滤字段做请求内去重的定向回查。
- HugeGraph 有界 snapshot 达到上限时不会把样本类型当成全量事实；可用 schema 元数据时优先采用元数据。
- HugeGraph 仅在 schema 未提供任何节点/关系类型清单时采用全局 PropertyKey；若清单存在但目标 class 不在其中，不借用其他 class 的同名字段类型。
- HugeGraph `BLOB` 的 REST 文本编码不在该边界猜测 hex/base64/UTF-8；文本操作数保持原样，避免静默改值。
- 无法安全确定类型时保持兼容，不会因兜底机制改变旧查询语义。
- 歧义类型和非法值会在工具执行阶段返回可重试的输入错误，而不是静默转换后返回错误结果。
- 新增类型解析、后端回查、pattern 协议兼容和各查询入口的专项回归测试；真实数据库和 UI 端到端验证仍需在具备对应本地服务与测试用例的环境中执行。
