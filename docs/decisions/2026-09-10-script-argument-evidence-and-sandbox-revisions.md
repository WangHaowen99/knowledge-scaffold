# 脚本参数证据与已验证知识包副本的执行边界

## Context

普通 Agent 的脚本参数校验需要区分已有实体标识与新建结果标识，并允许后续操作使用当前请求内真实工具输出的记录。单纯按字段后缀拒绝标识会阻止合法创建；放宽所有标识又会允许无依据的参数和跨记录拼接。

版本预检会生成工作区外的不可变暂存副本。沙箱原有工作区路径限制无法执行该副本，而直接放开暂存目录会扩大文件可见范围。恢复会话历史时，还必须保留当前用户消息边界，避免上一轮结果被当作本轮证据或缓存结果。

## Decision

- 由实际绑定的脚本描述显式声明 `generated_identifiers` 字段路径和 `uuid4` 格式。校验在绑定及版本验证完成后、脚本启动前执行。
- 仅使用当前用户消息之后的可信结构化工具输出。脚本证据关联实际调用 ID 和知识包，保留记录内字段关系，排除失败输出及跨轮结果。
- 将参数拒绝映射为固定分类和字段路径；重复失败按操作、分类和路径识别，公开终态不包含错误参数值。
- 通过内部 `ContextVar` 作用域传递已完成版本验证的暂存包。作用域绑定工作区、知识包、运行和精确路径，不能由工具参数创建；每次执行使用独立附属沙箱，仅挂载该副本与标准运行文件，并拒绝额外挂载。
- 在 `finally` 中先释放附属沙箱，再由外层预检清理副本；退出时恢复上下文。已有工作区执行路径继续使用原有沙箱检查。

## Alternatives considered

- 全面允许 UUID 或结果类字段：无法限制具体操作的生成权限，也不能阻止已有实体标识被伪造。
- 将全部历史工具输出作为证据：旧请求、失败输出和不同记录之间可能形成错误关联。
- 把暂存目录整体加入沙箱白名单：同级运行副本可能暴露给当前脚本。
- 将已验证路径加入公开工具参数：模型能够影响执行边界，且公开接口承担了内部版本交接职责。

## Consequences

创建操作需要显式声明可生成字段；已有实体仍需请求或当前轮可信证据。错误参数可在首次拒绝后修正，重复相同原因的失败会以 `AGENT_LOOP_STALLED` 结束。

暂存副本每次执行会增加附属沙箱的创建和释放成本，换取版本一致性与最小文件可见范围。新增的作用域、失败清理、证据关联和历史边界均有合成回归覆盖；真实模型、Run API、SSE 与 JiuwenBox 的完整验证见 [端到端记录](../issue-295-e2e-verification.md)。
