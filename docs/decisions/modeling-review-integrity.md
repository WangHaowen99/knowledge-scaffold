# 建模输入、评测结果与来源核验的真实性边界

## Context

场景 Markdown 经 Agent 临时正则转换时可静默丢失带尾注的字段；评测服务的轮次
`done` 不一定有有效回答；将 Office 压缩文件当 UTF-8 文本读取也不能证明源 ID 不存在。
旧来源核验接受任意非空新增依据及已有 ID 基线，会使未核实的 ID 进入后续基线。
此外覆盖率分母混用，产品决定先隐藏展示而不移除缺项检查。

## Decision

1. 单项、批量、交互保存后转单项的 trace 共用 `trace_inputs.py`。确认稿到交接 JSON
   绑定 SHA-256，逐场景保留字段、类型、值和尾注。解析失败、重复字段或修订不符即停止。
   推演结果回传场景 ID、初始输入和来源摘要，报告前机械对账。不会根据预期路径补值。
   这证明交接/回执一致，不代替模型实际推理的语义审查。
2. 隐藏新报告与页面的覆盖率统计；旧 Markdown 原件不改，仅渲染时隐藏已知指标。
   具体缺失分支、对象/规则待补项、推演通过率、数据评测分数仍保留。内部检查不撤销。
3. 保留现有终态 API：完整有效轮 `done`，存在技术异常或无结果 `failed`。
   summary 增加 `valid` 与 `result_status=complete|partial|unavailable`。
   pass/partial/fail 必须有非空回答；无效结果及缺少的用例计 error，不参与业务分数分母。
   无有效判分时 score=null，不是 0；混合结果明确为有效子集得分。报告、详情与列表一致。
   已收取的异常轮不会被重跑入口再次续接，正常重新发起评测。优化推荐阈值策略不变。
4. `source_extract.py` 统一严格 UTF-8 文本、DOCX 正文/表格、XLSX 单元格抽取。
   返回原始摘要、提取器版本和可核验锚点；分页/长段落续读有界。超限、损坏、未支持格式
   返回无法核验，不返回空串假装未找到。research 回执版本升至 3，来源摘要和当前文件
   必须一致；大文件流式哈希，等长修改也失效。历史报告和 ID 基线不删除，但不再免检。
   来源路径不明、重名或锚点错误不放行；报告不能自证。新增编号只有可读原始依据仍不够，
   需经人工确认；已有源 ID 使用沿用，不伪装新造。确认入口沿用「缺口与待决」勾选机制，
   这不是新增身份鉴权系统，Agent 不得代替人工勾选。

## Alternatives considered

- 继续使用临时正则或手工重抄场景：无法稳定保留字段和类型，也无法对照实际输入，未采用。
- 以空文本表示抽取失败，或信任旧基线/任意新增依据：会混淆未找到与无法核验，未采用。
- 删除覆盖检查或重写历史报告：超出只隐藏指标的范围，保留缺项检查与原件。
- 将技术异常记为零分或全量完成：会混淆运行可用性与业务质量，采用有效子集和显式异常状态。

## Consequences

新增确定性检查会拦截原先静默放行的输入和来源问题，需按错误定位修正，不能绕过检查。
人工新增 ID 确认仍受既有工作区权限与人工流程约束；本轮不引入新的审批身份系统。

### Compatibility and verification

- 旧工作区没有新工具时不能声称已验证输入完整性，需要先更新工具箱；不改旧确认稿。
- 旧来源回执保留并转待核验。已经提取对象的项目仍保留既有阶段进度，只提示来源待核验，
  不重置整个业务流程。新报告进入对象提取前必须通过来源验收。
- 库函数只做结构与来源定位，不能证明业务规则正确、语义覆盖充分或在线模型可用。
- 合成回归覆盖尾注/零/false/空值、漏字段/类型/修订变化、Office 中文及锚点、损坏/超限、
  新增声明绕过、基线免检、全部异常/混合结果/真实零分/缺结果与重新评测。
- 不涉及模型配置、账号授权、执行时间展示、命令内部性能策略或评测后交互设计。
  本地测试与构建不等于 Windows、线上部署或真实模型前向演练验收。
