# eval1 独立评测服务

## Context

Hub2 通用包以统一账号身份访问，已提供 evaluation mapping_update 契约。旧评测依赖 Onto 项目、Core 存储及建模 Agent 工作流；原 TypeScript Judge 默认加载 Core 模型配置，不能直接搬运运行入口。

## Decision

- 新增 `eval-service/`，使用仓库已有 FastAPI/Python、React/Vite 和独立 SQLite。优先直接复用 Python mapping 确定性规则，避免跨语言重写绑定；判分协议和既有容差移植到独立客户端，不加载建模 Agent。
- 运行期仅调用账号、Hub 和 consumer。用户身份按 issuer/subject 隔离，不存建模项目或成员表。用户令牌只保留内存，配置凭据和输入数据用外部提供的 Fernet 密钥保护。
  - 展示用建模项目名称（修订）：Hub 不记录建模项目，“知识包 → 建模项目”只在建模服务按用户保存。任务中心需要显示项目名称，因此评测以当前用户登录调用建模只读接口，按包查询本人可访问且本人关联的项目名称（每次最多 20 个包、每包 5 个名称）。名称不落盘、不参与评测执行与权限；建模不可用时只隐藏名称，评测不依赖建模启动或可用。
- 以固定 Hub 版本生成 mapping 派生副本；只改 mapping 和 manifest version，由 Hub 再次校验白名单。快照和正式发布独立幂等。
- consumer 新增受限 evaluation 空间预置接口，同时验证用户和独立服务凭据；空间归属取当前用户，不接受 owner。已有安装、激活、运行与取消接口继续使用用户权限。
- 单进程持有文件锁，SQLite 保存请求和运行状态；最多两个执行线程、队列最多 16 项、每用户一个活动任务。重启后等待授权对账，不盲目重跑。提交未知时复用 consumer 已实现的 session fingerprint 与 Idempotency-Key。
- 同源独立路径复用现有浏览器登录态，两个前端使用相同 Web Locks 刷新锁，账号切换后拒收旧结果；评测认证直接连接账号服务。
- 评测入口直连（修订）：原先只能经同源独立网关访问，部署须额外维护网关；改为默认由浏览器打开与建模页面同主机的 8090 端口，评测端口默认开放所有网卡。评测在其他主机、端口或经 HTTPS 时由建模部署变量 `ONTO_WEB_EVAL_PUBLIC_URL` 指定；不接受相对路径或与建模页面同源的地址，登录统一通过跨源窗口消息交接。
  - 跨源时建模页面打开评测窗口，评测页面就绪后用 `postMessage` 交接登录：建模侧只向入口地址的来源发送，评测侧只接受 opener 发来、来源在 `EVAL_TRUSTED_ORIGINS`（未配置时同主机名，本机回环名视为同一主机）中的消息。
  - 该地址决定登录交给哪个站点，因此只由部署配置决定、不提供页面修改入口，并限定为不含账号和查询参数的 http(s) 地址。
- 独立部署参数 `--eval-only`，同时纳入默认全栈部署与完整离线包；不加入 `--onto-modeling-only`。使用独立 Compose（`eval-service/deploy/docker-compose.eval-service.yml`）与运行卷。
- 运行配置开箱即用（修订）：原先要求外部 `EVAL_ENV_FILE`，整栈部署因此无法直接完成；改为与 Hub 部署相同的做法，由评测部署脚本维护 `eval-service/deploy/.env`（权限 600，不入库）。
  - 首次部署生成 Fernet 密钥。`.env` 只保存凭据和显式配置的值；非敏感的整栈默认地址写在 Compose 中，运行配置以 `--env-file` 参与插值，同名值优先。
  - Hub 与 consumer 的部署脚本各自生成评测服务凭据，评测部署时沿用。
  - 与 Hub 一样必须加入 consumer 网络（`CONSUMER_NETWORK` 必填，网络声明写在主 Compose 文件中）。
  - 已有数据卷而缺少密钥时拒绝生成新密钥。
  - `EVAL_ENV_FILE` 保留为可选的外部配置，脚本不改写。Judge 部署配置缺失只告警。
- 临时模型策略 MODEL-CONFIG-01：consumer 管问答模型，Judge 由部署参数提供默认值；可选 NL2SQL 暂复用 Judge 客户端配置。eval2 决定最终统一方案。
  - 问答模型可选（修订）：发起评测时可从 consumer 全局模型池已启用的模型中选择一个，留空仍用 consumer 默认模型；执行时校验所选模型仍在全局池中，不使用工作空间私有模型。
- 数据源工作空间绑定（修订）：consumer 图查询在未显式给出范围值时按当前工作空间 ID 过滤，NL2SQL 场景也绑定在评测工作空间上，因此与原建模评测一致：Neo4j 数据源的轮次在“Workspace 对应值”、NL2SQL 连接的轮次在“评测工作空间 ID”指定的 consumer 工作空间中执行，新建空间的名称与 ID 一致。为不改动 consumer，评测以当前用户权限调用其通用工作空间接口：不存在则创建，存在则只复用本人所有且未共享的空间，该空间跨轮次复用、删除轮次时保留。无数据源和上传数据集仍使用受限预置接口创建的每轮私有空间。
- 每轮用例并发（修订）：原先逐条提问；改为发起时设置并发数（1 到 8，默认 4），每条用例只持久化自己的结果，避免并发覆盖。
  - 页面配置 Judge（修订）：原先只能部署时配置，更换判分模型须改运行配置并重新部署；改为管理员可在评测页面保存 Judge 配置，整体替换部署配置。该配置对所有用户生效且会收到评测内容，因此按账号服务返回的 role 仅允许管理员修改；Key 用现有 Fernet 密钥加密存入数据卷、从不返回，更换网关须重填 Key。
  - 配置版本自动生成并记入轮次；值变化后，已创建的轮次在预检和逐条判分时拒绝新配置，不混用判分模型。
  - 个人判分模型（修订）：每个用户可保存个人 Judge 配置覆盖默认配置，也可删除以回到默认；生效顺序为个人配置 > 管理员页面配置 > 部署配置。个人配置只用于本人轮次，发送的也只是本人评测内容，因此无需管理员权限；Key 加密存储，留空时不借用默认配置的 Key，避免用户以共享 Key 调用自选模型。轮次按所有者解析配置版本，个人配置变化只影响本人轮次。NL2SQL 由 consumer 以场景凭据调用、无法确定用户，仍使用默认配置。
- 可选 SQL adapter 使用 PyPI 的 `sqlglot`（MIT）解析并限制只读 SQL，避免仅靠正则判断跨库查询和写入。其余新增依赖来自仓库已有技术体系；不引入专有代码或数据。

## Alternatives considered

- 整体搬运 TypeScript 引擎：会保留 Core 仓储、配置和工作流依赖。
- Onto 代理发布和鉴权：重新引入项目归属耦合，建模停机影响评测。
- 复制工作区或建立虚拟项目：违反包来源与独立身份边界。
- 跨域 URL 传 token：不采用，令牌会进入浏览器历史、代理与服务端日志及 Referer；窗口消息交接只在浏览器内存传递。
- 只保留同源网关：简单部署也要多维护一个网关容器，因此移除同源接入方案。
- 继续强制外部 `EVAL_ENV_FILE`：密钥与依赖地址完全由部署方管控，但整栈部署无法直接完成，部署方还要手工对齐 Hub 和 consumer 的评测凭据，因此不再作为默认，只保留为可选覆盖。

## Consequences

Python mapping 规则从原实现提取，后续修改应保持绑定行为测试一致。服务只支持单实例，不承诺多副本或绝对恰好一次。完整工具轨迹仍由 consumer 管理，本地保存运行引用并明确标记未采集。外部 SQL 连接只读，上传数据用隔离 dataset 库；图导入必须用户明确选择并使用本轮 scope。真实模型效果、数据库兼容性和现场网关路由须部署联调确认。直连时评测页面持有独立的登录副本，建模页面退出不会同步清除；评测端口默认对所有网卡开放，除健康检查、客户端配置和登录转发外的接口均需用户登录或专用凭据，不需要远程访问时可改为只绑定本机。

默认部署下，加密密钥与数据卷位于同一台主机，但密钥不在卷内；备份须分开保管，丢失 `deploy/.env` 即无法解密已有数据。在本次修订前部署的整栈，Hub 与 consumer 尚无评测凭据，须完整执行一次整栈部署。
