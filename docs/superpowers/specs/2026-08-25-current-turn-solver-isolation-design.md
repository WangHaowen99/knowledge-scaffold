# 当前轮求解器隔离与结果归因设计

## 状态

已确认。用于修复同一会话中“上一轮执行求解、当前轮仅做统计校验”时，模型错误暗示当前轮仍由求解器参与的问题。

## 问题

求解路由守卫可以避免统计校验请求被强制绑定到求解器，但当前 Agent 仍会：

1. 将所选知识包的 Solver ToolCard 暴露给当前轮模型；
2. 将上一轮求解请求、原始工具调用、工具结果和最终回答整体加入当前轮活动上下文；
3. 缺少“工具执行声明必须属于当前轮”的明确约束。

因此，即使当前轮只调用普通脚本，模型仍可能生成“求解器已返回结果”之类的错误过渡语。

## 目标

- 明确的统计、汇总、校验、负荷或容量检查请求，不暴露任何 Solver ToolCard。
- 当前轮不会继承任何已完成求解轮次的任务、工具调用、工具结果或最终回答。
- 模型只能依据当前轮实际工具事件描述当前轮执行情况。
- 显式求解请求、未分配方案的隐式求解请求及非求解工具保持原行为。

## 非目标

- 不删除持久化会话历史；隔离只作用于当前轮发送给模型的上下文投影。
- 不删除未调用求解工具的普通历史轮次。
- 不修改知识包求解契约、Connector 或独立求解服务。
- 不通过关键词事后删除最终回答中的句子。

## 方案

### 1. 当前轮路由状态

路由守卫在每轮开始时产生三态工具可见性：

- `required`：当前轮已绑定具体 Solver Operation，只暴露该求解 ToolCard 和交互工具；
- `hidden`：当前轮是非求解统计或校验，只暴露普通本体工具；
- `available`：没有足够证据限制求解工具，保留现有通用工具集合。

显式求解意图优先于统计词，避免“求解并统计候选方案”被错误隐藏。结构化参数匹配到求解契约时也始终进入 `required`。

### 2. 工具注册隔离

工具注册 API 增加默认开启的 `include_solver` 参数。当前轮为 `hidden` 时，动态 Solver ToolCard 不进入 OpenAI schema 或九问 ToolInfo；静态工具不受影响。

### 3. 历史消息隔离

当前轮为 `hidden` 时，先按用户消息切分历史轮次。只要某个历史轮次实际调用过平台生成的 Solver ToolCard，就从当前模型上下文中移除该完整轮次，包括用户请求、工具调用、工具结果和最终回答；其他普通轮次保持不变。持久化历史不做删除。

过滤依据平台生成的 Solver ToolCard 命名契约，不依赖具体业务操作名称。对缺少完整轮次边界的旧历史，仍保留逐条移除原始求解工具消息的兼容处理。

### 4. 当前轮事实归因

在当前轮模型输入中注入通用的当前请求边界：只有最新用户消息定义活动任务；不得推断、延续或报告已省略的历史任务；不得在回答中解释未暴露或已省略的工具；只能使用当前轮实际暴露的工具。

该约束只在 `hidden` 状态启用，避免影响真实求解流程。

## 数据流

1. Orchestrator 根据最新用户请求解析求解要求和工具可见性。
2. 可见性写入本轮 `user_context`，不会作为会话长期状态复用。
3. Agent 构建工具列表时根据可见性跳过 Solver ToolCard。
4. Agent 构建历史上下文时过滤实际调用过求解工具的完整历史轮次。
5. 当前轮查询附带执行事实归因约束。
6. 普通脚本执行并形成当前轮结果；求解服务不收到请求。

## 验证

- 单元测试：统计校验请求得到 `hidden`，显式及隐式求解请求保持 `required`。
- 工具测试：`hidden` 状态下 OpenAI schema 与九问 ToolInfo 均无 Solver ToolCard。
- 历史测试：上一轮完整求解轮次被移除，后续普通历史轮次保留。
- 同会话回归：第一轮执行合成求解，第二轮执行合成负荷/容量校验；第二轮仅调用普通脚本，事件中没有权威求解结果，输出不暗示当前轮使用求解器。
- 既有求解器、MCP 和普通本体工具测试全部通过。
