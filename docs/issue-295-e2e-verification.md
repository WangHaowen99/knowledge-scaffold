# Issue #295 实际端到端验证记录

验证日期：2026-09-10。代码基线为 `origin/develop` 的 `b49d63b6`，测试包含当前工作区修复。

## 环境与验证方式

使用独立 Backend、认证服务和 JiuwenBox 容器加载当前源码。后端 37 项声明依赖全部满足，openJiuwen 为 `0.1.17`。知识包、账户及业务记录均为合成数据。

完整链路为：注册与登录 → 创建会话 → `POST /agentic/runs` → 真实 DeepSeek 模型工具调用 → 参数校验 → JiuwenBox 执行绑定脚本 → 实时 SSE → Run 状态查询与事件回放。

模型使用环境配置的 `deepseek-v4-flash`。凭据仅在内存中传递，本地转发层负责认证和转发，不生成或替换模型响应。沙箱配置为 `SANDBOX_ENABLED=true`、`SANDBOX_FALLBACK_LOCAL=false`。

每个成功脚本均断言：执行器为 `/usr/bin/python3`，沙箱运行契约文件存在，Backend 测试目录不可见；断言通过才输出 `sandbox_verified: true`。成功判定同时核对真实工具输出和最终 Run 状态。

## 最终结果

9 个 API 场景全部达到预期，共 25 次真实模型调用、10 次沙箱脚本执行、9 次参数校验拒绝。

| 场景 | 验证结果 |
| --- | --- |
| 声明生成 UUID4 后执行，再由后续脚本引用 | 两次沙箱执行成功，结果 ID 和记录保持一致 |
| 连续使用两个不同的非法生成 ID | 两次均未执行脚本，终态为 `AGENT_LOOP_STALLED` |
| 非法生成 ID 后改为合法 UUID4 | 首次拒绝，修正后执行成功，后续引用成功 |
| 查询脚本结果作为后续参数证据 | 查询与后续执行成功，使用同一条记录 |
| 同一会话下一轮复用旧记录 | 返回 `ungrounded_identity`，未执行脚本；Agent 正常报告拒绝原因 |
| 混用查询结果中不同记录的字段，再修正 | 返回 `evidence_record_mismatch`，修正为完整记录后执行成功 |
| 把新 UUID4 用作未声明的实体 ID，并更换值重试 | 两次拒绝，终态为 `AGENT_LOOP_STALLED` |
| 同步模型模式下生成并引用结果 | 两次沙箱执行成功 |
| 同步模型模式下更换非法 ID 重试 | 终态为 `AGENT_LOOP_STALLED`，保留结构化原因 |

前 7 项采用流式模型模式并开启 `DETERMINISTIC_EXECUTION_ENABLED`；后 2 项采用同步模型模式并关闭该开关。绑定操作均走普通 Agent 路径。

所有场景均核对实时 SSE 与回放事件完整一致、序号连续、只有一个 `turn.finished`，以及 Run 查询状态与终态一致。重复失败的公开诊断保留字段路径、分类和 `correctable: true`，运行本身的 `retriable` 为 `false`，诊断不包含错误参数值。

## 联调发现并补修的问题

1. **锁定副本与沙箱路径边界不一致。** 预检副本位于运行时暂存目录，原沙箱执行器只接受工作区内路径。新增内部验证作用域，将已验证副本交给独立附属沙箱；仅只读挂载本次副本，拒绝额外挂载、其他运行或知识包的路径，执行结束后释放沙箱，再删除副本。
2. **恢复历史后的当前轮边界不完整。** 工具状态缺少本轮用户消息，且重复执行保护扫描整个历史，导致旧成功结果在新请求校验前被复用。现在补入当前消息边界，复用范围限定本轮，显式失败结果不计为成功；ContextEngine 的历史输入仍排除重复的当前查询。
