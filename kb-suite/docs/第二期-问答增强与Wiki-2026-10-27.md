# 第二期：问答增强、LLM Wiki 与知识库设置（2026-10-27）

## 背景

第一期的 kb-service 只有混合检索（向量 + BM25、RRF、重排）和文档摘要。用户要求补上 WeKnora 的问答增强、LLM Wiki，以及 WeKnora 知识库设置页的可配置项。行为尽量照 WeKnora 实现（调研时核对过源码），只在 kb-service 的架构差异处调整。

## 范围

| 项 | 做法 | WeKnora 对应 |
|---|---|---|
| AI 问题生成 | 每个文本或表格分块调一次模型，带前后分块作上下文；问题存 `chunk_questions`，单独建向量和 BM25 索引，命中归到父分块；重排和 MMR 的文本带上问题 | `generate_questions.yaml`、`GeneratedQuestions`、`EnrichedPassage` |
| 重排阈值 | 低于阈值丢弃；全不过且阈值大于 0.3 时降到 `max(阈值×0.7, 0.3)` 再试；仍为空保留最高分（≥0.15） | `reranking/rerank.go` |
| 复合打分 | `0.6×重排分 + 0.3×召回分 + 0.1` | 同上 |
| MMR | `λ×相关性 − (1−λ)×最大 Jaccard`，λ 默认 0.7；Jaccard 用中文双字和英文词（不引入 jieba） | `reranking/mmr.go` |
| 相邻合并、补上下文 | 同一文档里相连或重叠的命中合成一条；短于 350 字的补到约 850 字，前后各一半，一侧到头就让给另一侧；补完重叠的再合并一次 | `merge.go`、`merge_expand.go` |
| 父子分块 | 检索时用 L1 的标题结构取命中所在章节，不超过父块大小；不另建索引 | `enable_parent_child` |
| 跨文档去重 | 包含关系或词重合率 ≥0.85 的只留一条；在截取前 k 条之前做，重复内容不占名额 | `removePartialOverlaps` |
| 查询扩展 | 召回不足时，去疑问词、按标点拆句，再做几次关键词检索 | `query_expansion.go` |
| LLM Wiki | 见下节 | `wiki_ingest_batch.go`、`prompts_wiki.go` |
| 知识库描述 | 汇总文档标题和摘要生成；输入没变就不调模型 | `profile_config` |
| 上传选项 | 上传时覆盖分块、解析引擎、摘要、问题、Wiki 开关 | `KnowledgeProcessOverrides` |

检索参数在 WeKnora 里放在智能体和租户上。kb-service 没有智能体，所以放在知识库上，检索请求可以用 `options` 临时覆盖。多个知识库一起检索时，阈值按各命中所属的知识库算，数量取最大，开关只要有一个开就开。

## 配置

`knowledge_bases.config` 改成分节结构：`chunking`、`parsing`、`indexing`、`summary`、`questions`、`wiki`、`profile`、`retrieval`，外加 `language`。见 `kb_service/kb_config.py`。

- 读取时补齐默认值，兼容第一期的扁平写法（`chunk_size`、`chunk_overlap`）。
- 显式的 0 和 false 会保留。第一期用 `or` 取值，0 会被当成没填。
- 某一节存的值不合法时只回退这一节。

## LLM Wiki

数据：

- `wiki_pages`：`slug`、`page_type`（summary / entity / concept / index）、`summary`、`content`、`aliases`、`source_doc_ids`、`chunk_refs`、`out_links`、`in_links`、`version`，以及向量和 BM25 索引。
- `wiki_page_revisions`：每次覆盖前存一份快照，最多保留 50 版。

每篇文档的摘要完成后，排一个 `wiki_ingest` 任务：

1. 抽候选实体和概念。粒度分 focused、standard、exhaustive 三档；重新处理时沿用这篇文档上次的 slug。
2. 识别同一事物。标题或别名完全一致的直接复用已有页面；否则用 pg_trgm 找相似页面，交给模型判断是不是同一个。
3. 生成文档摘要页 `summary/<doc_id>`，链接到这次抽出的页面。
4. 把分块按 `c000` 编号，每批约 1.2 万字交给模型，标出每个分块支撑哪些页面。
5. 用被引用分块的原文创建或合并页面。写入带版本号，冲突时重试；同类型页面的标题唯一，写入时加锁检查。
6. 这篇文档已经不支撑的页面，撤回它的那部分内容；没有来源的页面删除。

文档删除时排 `wiki_retract` 任务。每个知识库还有一个合并执行的 `wiki_finalize` 任务，负责：

- 清理失效链接；
- 把正文里第一次出现的其他页面标题自动加上链接；
- 重算反向链接；
- 重写索引页。

同一知识库的 Wiki 任务用 advisory lock 串行执行，锁被占用时任务延后，不消耗重试次数。原因是并行写会让查重看不到别的任务刚建的页面。实测并行时有 41 页，其中有同名重复；串行后 33 页，没有重复。代价是变慢：7 篇文档从约 4 分钟变成约 9 分钟。

WeKnora 里 Wiki 页面不进向量索引，WikiBoost 实际不生效。kb-service 把页面建了索引，检索时可以带上 Wiki 页面：

- 加权系数默认 1.3；
- 每次最多返回 2 页，避免挤掉原文片段，因为 agent 引用出处要靠原文。

没有做的：目录树（folders）、问题标记（issues）、agent 写页面的工具。提示词改写自 WeKnora，去掉了图片相关的规则。

## 接口变化

- 管理接口：
  - `GET /v1/config/meta`；
  - `PATCH /v1/kbs/{id}` 支持传 `config`；
  - `POST /v1/kbs/{id}/reprocess`；
  - `POST /v1/kbs/{id}/profile/{generate,apply}`；
  - `PUT /v1/chunks/{id}/questions`；
  - `POST /v1/documents/{id}/questions/regenerate`；
  - `/v1/kbs/{id}/wiki/{status,pages,page,graph,rebuild,finalize}`；
  - `POST /v1/search` 增加 `options`、`min_score`、`include_wiki`、`trace`。
- 检索结果新增字段：
  - `relevance`：0–1；
  - `scores`：向量、关键词、重排、召回分；
  - `matched_question`；
  - `merged_chunk_ids`；
  - `core`：命中分块在扩展后正文里的位置；
  - Wiki 命中的 `wiki_slug`、`wiki_type`、`wiki_sources`。
- MCP：新增 `search_wiki`、`read_wiki_page`。
- DA 工具：
  - `kb_search` 支持 Wiki 页面类型和 `linkedFrom`；
  - `minScore` 改为和 `relevance` 比较。原来比的是 RRF 分，和 DA 的接口约定不符。
  - `wiki_browse` 支持 `wiki:` 开头的 pageId。
- 数据库迁移 `002_enhance.sql` 只做加法，第一期的代码可以直接跑在新 schema 上。

## WeKnora 设置项对照

| 分组 | 已做 | 不适用或没做 |
|---|---|---|
| 基本信息与模型 | 名称、说明、AI 生成描述（生成、用作说明）、摘要模型、Wiki 模型、问题生成模型；向量和重排模型只读展示 | 向量存储、存储引擎（kb-service 只有一套 ParadeDB 和本地卷） |
| 解析与分块 | 分块策略（按标题、按分隔符）、分块大小、重叠、分隔符、父子分块（检索时实现）、按文件类型选解析引擎、表格元数据要求 | token 上限、语言提示、xlsx 首行作表头 |
| 索引开关 | RAG 开关（关了就是只做 Wiki 的库）、摘要、问题生成（数量、要求）、Wiki、知识库描述 | 多模态、图片向量、ASR（没接 VLM 和 ASR）、知识图谱（没接 Neo4j）、自动打标签 |
| Wiki | 提取粒度、提取重点、内容要求、每篇最多页数，以及 kb-service 自己加的「参与检索」三项 | — |
| 检索参数 | 向量和关键词的开关、召回数、阈值，RRF 的 k 和权重，问题匹配，查询扩展，重排开关、候选数、阈值，复合打分，MMR，合并，补上下文 | FAQ 优先、表格数据分析 |
| 上传时覆盖 | 分块、解析引擎、摘要、问题、Wiki | 扫描件、多模态、ASR、标签 |
| 智能体、对话、租户、系统 | — | 属于 Swarm 一侧（模型、提示词、联网搜索、记忆、MCP 等），kb-service 不重复做 |

## 验证

- kb-service 单测 43 个，覆盖配置、检索后处理、Wiki 链接、问题解析和分块策略。数据库相关的 SQL 在临时库上跑过。
- 端到端在 5199 实测：
  - 新建测试库「压缩机运行资料（增强测试）」，7 个文档共生成 66 个问题和 34 个 Wiki 页面（含索引页）；
  - 检索命中生成的问题和 Wiki 页面；
  - MCP 和 DA 工具都返回 Wiki；
  - DA 冒烟测试中会读 Wiki 并回到原文引用出处。
